## 这个实验要验证什么

一句话：**验证"同一个插件，靠 `cordis.yml` 的 `config` 块，在不同场景下用不同参数"——且配置错了插件根本不启动。**

前面几讲，插件的 `apply` 都硬编码行为。05 讲让插件**可配置**：给插件传参数，`apply` 里就能读到。

官方原话：

> **出处**：`docs/cordis-tutorial/05-config.zh.md`——*"`cordis.yml` 中的每个 Cordis 配置项都可以携带 `config` 块，插件则声明一个 schema，在运行 `apply` 前验证该块。错误配置会导致加载失败，并给出准确的错误：插件绝不会在配置不完整时启动。"*

用你的 Go 经验类比：像**服务启动时读配置 + 校验，错了直接 fail-fast**（而不是跑起来了、某个请求才炸）。

---

## 先讲理论（动手前必读）

### 概念① `Config` 是"三合一"：接口 + schema + 校验器

本讲最核心的新写法：

```ts
export interface Config {          // ① TS 接口：给类型检查
  greeting: string
  targets: string[]
}

export const Config: Schema<Config> = Schema.object({   // ② 运行时 schema：给 Cordis 校验
  greeting: Schema.string().default('Hello'),
  targets: Schema.array(String).default(['world']),
})

export function apply(ctx: Context, config: Config) {    // ③ apply 第 2 参 = 已验证的完整配置
  ...
}
```

> **出处**：`docs/cordis-tutorial/05-config.zh.md`——*"导出的 `Config` 既是 TypeScript 接口，也是同名的运行时 schema：消费方获得类型，Cordis 获得验证器。"*

**Go 类比**：像把 struct 的**类型定义**和它的**校验逻辑**绑在一起——`interface Config` 是类型（编译期），`Schema.object(...)` 是运行时的"校验器 + 默认值填充器"。

> [!note] TS 小知识：接口与 `const` 为何能同名
> `interface Config` 和 `const Config` 同名却互不冲突——因为 TS 里有**两个独立的"声明空间"**：类型空间（interface）和值空间（const）。它们同名共存是合法的、也是惯用法。第一次见会愣一下，习惯就好。

### 概念② `apply` 的第二个参数 = 已验证的配置

对比前几讲：

| 讲 | `apply` 签名 |
|---|---|
| 01–04 | `apply(ctx: Context)` |
| **05** | `apply(ctx: Context, config: Config)` ← 多了 `config` |

**关键保证**：`config` 进来时**一定完整且合法**——缺的字段被 schema 默认值补齐，类型错的**根本进不到 `apply`**（加载前就被拦下）。

> **出处**：`docs/cordis-tutorial/05-config.zh.md`——*"未提供 `greeting`，因此 schema 默认值会将其补齐：`apply` 始终会收到完整且经过验证的配置。"*

Go 类比：比常见的 `yaml.Unmarshal` 更进一步——非法配置**不是**让你在业务代码里 `if err != nil` 处理，而是**插件直接加载失败、压根不启动**。

### 概念③ "绝不带病启动" + 精准报错

传错配置会得到带**精确路径**的报错：

```
ValidationError: invalid config:
  - $.targets expected array but got not-an-array (at targets)
```

> **出处**：`docs/cordis-tutorial/05-config.zh.md`「明确报错」节——*"插件的 fiber 进入 FAILED 状态，本教程的启动器打印错误后以状态码 1 退出。"*

Go 类比：**启动时 fail-fast**——配置错了服务直接起不来（而不是跑起来后某个请求才炸）。`$.targets`、`(at targets)` 精确定位到出错字段。

### 概念④ `!!js` 标签——加载时计算的值

```yaml
config:
  greeting: !!js process.env.DEMO_GREETING ?? 'Hello'
```

`!!js` 让你在 yml 里写**加载时求值的表达式**（如读环境变量）。

> **出处**：`docs/cordis-tutorial/05-config.zh.md`「计算得到的配置值」节——*"`!!js` 仅在 `config` 与条目 `disabled` 字段内有效。……其余元数据（`name`、`id`、`inject` 等）保持静态，其中的表达式是普通真值数据。"*

**注意限制**：`!!js` **只在两个地方有效**——`config` 块 和 `disabled` 字段。

Go 类比：像 yml 里嵌入 `os.Getenv()` 求值（如 Helm 模板、`os.ExpandEnv`）。

### 概念⑤ Schemastery 与 "Standard Schema"（一个坑）

> **出处**：`docs/cordis-tutorial/05-config.zh.md`——*"本仓库使用 Schemastery 定义 schema；Cordis 本身接受任意 Standard Schema 验证器，因此将普通对象导出为 `Config` 无法工作。"*

即：`Config` **不能是普通对象**，必须是 schema 校验器。官方用 `@deepseek-ai/schemastery`（写法像 Zod）。

## 第 2 步：写可配置插件

### `config-demo.ts`（逻辑与官方一致，注释为本人添加）

**请自己敲**：

```ts
import type { Context } from '@deepseek-ai/cordis'
import Schema from '@deepseek-ai/schemastery'

export const name = 'config-demo'

export interface Config {
  greeting: string
  targets: string[]
}

export const Config: Schema<Config> = Schema.object({
  greeting: Schema.string().default('Hello'),
  targets: Schema.array(String).default(['world']),
})

export function apply(ctx: Context, config: Config) {
  for (const target of config.targets) {
    console.log(`${config.greeting}, ${target}!`)
  }
}
```

> **出处**：`docs/cordis-tutorial/05-config.zh.md`（代码逐字一致）

## 第 3 步：跑四个场景（验证配置系统的行为）

### 场景① 传部分配置 → 默认值补齐

```yaml
- name: './config-demo.ts'
  config:
    targets: ['alpha', 'beta']
```

```sh
npm start
```

输出：

```
Hello, alpha!
Hello, beta!
```

**注意**：yml 里**没传 `greeting`**，但输出是 `Hello, ...`——schema 的 `default('Hello')` 把它补上了。

> **出处**：实测（2026-09-16）；与官方一致

### 场景② 完全不传 config → 全用默认值

```yaml
- name: './config-demo.ts'
```

```sh
npm start
```

输出：

```
Hello, world!
```

两个字段都走默认值（`greeting='Hello'`、`targets=['world']`）。

> **出处**：实测（2026-09-16）

### 场景③ 传非法配置 → ValidationError + 退出码 1️⃣（重点）

```yaml
- name: './config-demo.ts'
  config:
    targets: 'not-an-array'
```

```sh
npm start
```

**核心报错**：

```
ValidationError: invalid config:
  - $.targets expected array but got not-an-array (at targets)
```

退出码为 **1**：

```sh
npm start >/dev/null 2>&1; echo "exit = $?"
# exit = 1
```

> **出处**：实测（2026-09-16）——与官方报错文案一致，退出码 1 与官方"状态码 1 退出"一致

> [!tip] 实测发现：报错被 loader 包了一层
> 你实际看到的是**外层 loader 错误**套**内层 ValidationError**：
> ```
> Error: failed to apply loader entry ... (./config-demo.ts): invalid config:
>   - $.targets expected array but got not-an-array (at targets)
>   [cause]: ValidationError: invalid config: ...
> ```
> 最里面那层 `ValidationError` 才是 schema 的原始错误，外层是 loader 在"应用配置项失败"时的包装。看报错时**认准最内层的 `ValidationError` 与字段路径**（`$.targets`）。

### 场景④ `!!js` 读环境变量

```yaml
- name: './config-demo.ts'
  config:
    greeting: !!js process.env.DEMO_GREETING ?? 'Hello'
    targets: ['env-test']
```

```sh
npm start                          # 未设环境变量 → 走 ?? 右侧
DEMO_GREETING=NiHao npm start      # 设了环境变量 → 用它
```

输出：

```
Hello, env-test!      # 未设时
NiHao, env-test!      # 设了时
```

> **出处**：实测（2026-09-16）

## 第 4 步：与前面几讲的呼应（把"契约"串成一条线）

01–05 讲其实在反复讲**同一件事**：**插件与框架之间的契约**——你在文件里 `export` 的东西，都是喂给框架的接口。

| 讲 | 主题 | 导出的"契约" | 谁读它 |
|---|---|---|---|
| 03 | 服务 | `super(ctx, 'name')` 服务名 | 消费方 `inject` / `ctx.xxx` |
| 03 | 服务 | `export const name` 插件名 | 框架（loader / 注册表） |
| 04 | 事件 | `interface Events` 事件签名 | `ctx.emit` / `ctx.on` 的类型 |
| **05** | **配置** | **`interface Config` + `Schema`** | **Cordis 加载前校验** |

这正好呼应 03 讲"**两个 name**"那个洞察——**你写的东西不一定是给自己用的，往往是给框架读的**。

## 一页纸总结

| 概念 | 一句话 | Go 类比 | 出处 |
|---|---|---|---|
| `Config` 三合一 | 接口 + schema + 校验器，同名共存 | struct 类型 + 校验逻辑绑定 | 官方 05 讲 |
| `apply(ctx, config)` | 第 2 参是**已验证的完整配置** | 启动读配置 + 校验 | 官方 05 讲 |
| 默认值补齐 | 缺的字段由 schema `.default()` 填 | 配置默认值 | 官方 05 讲 + 实测 |
| 绝不带病启动 | 配置错 → fiber FAILED，exit 1 | fail-fast | 官方 05 讲 + 实测 |
| `!!js` | 加载时求值，仅 `config`/`disabled` 可用 | `os.ExpandEnv` / Helm 模板 | 官方 05 讲 + 实测 |
| Schemastery | schema 库，普通对象**不能**当 Config | 要有校验器不能裸 struct | 官方 05 讲 |

## 踩坑记录

- **`Config` 不能是普通对象**：必须是 Standard Schema 校验器（官方用 `@deepseek-ai/schemastery`）；导出普通对象不工作。（出处：官方 05 讲）
- **本讲多一个依赖**：`lesson-05-config` 需额外 `npm install @deepseek-ai/schemastery@3.18.2`，否则 `import Schema` 报模块找不到。（出处：实测）
- **报错被 loader 包了一层**：实际看到的最外层是 `failed to apply loader entry ...`，真正的 `ValidationError` 在其中 `[cause]` 里；排查时认准最内层的字段路径（如 `$.targets`）。（出处：实测）
- **`!!js` 作用域有限**：只在 `config` 块和 `disabled` 字段有效；`name`/`id`/`inject` 等元数据是静态真值，写表达式不生效。（出处：官方 05 讲）
- **退出码陷阱**：`npm start 2>&1 | tail` 会让 `$?` 拿到 `tail` 的退出码（0），要看真实退出码得直接跑 `npm start >/dev/null; echo $?`。（出处：实测）
