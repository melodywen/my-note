## 这一篇在讲什么

05 篇讲"插件的生命周期"，06 篇讲**插件之间怎么协作**——通过**服务**。

> **出处**：`docs/user/develop/framework/service.zh.md`——*"服务是一个插件向其他插件公开的能力。inject 声明插件需要哪些服务。"*

**本篇的关键转向**：实验03 你学的是**消费**服务（`inject: ['tools']`，用别人提供的能力）；01–05 篇的插件也一直在**消费** `tools`。06 篇的重点是**反过来——让插件「对外提供」能力**。

**用 Go 类比**：实验03 学的是"**用**一个 interface"；06 篇学的是"**实现并注册**一个 interface 的实现"。

## 先讲理论（完整版）

### 概念① 什么是服务 —— 挂在 `ctx` 上的命名能力

> **出处**：官方 service.zh.md——*"在 Harness 中，`tools`、`llm`、`agents` 都是服务。服务是挂载在 `ctx` 上的命名能力："*

```ts
ctx.tools    // ToolRuntime service
ctx.llm      // LLM service
ctx.agents   // Agent service
```

> **出处**：官方 service.zh.md（逐字）

**关键**：`ctx.tools` 不是"某个变量"，而是**一个服务实例**挂在了 `ctx` 上。任何插件都能提供服务。

> **出处**：官方——*"任何插件都可以提供服务，供其他插件使用。"*

### 概念② 消费服务：`inject`（实验03 学过）

> **出处**：官方 service.zh.md——*"声明 `inject` 来使用已有服务："*

```ts
export const inject = ['tools']
export function apply(ctx: Context) {
  // ctx.tools 在此外就绪
  ctx.tools.register(/* ... */)
}
```

> **出处**：官方——*"框架保证：在 `apply` 执行时，`inject` 声明的服务已经全部就绪。如果服务还没准备好，你的插件会等着，不会执行。"*

**关联**：这正是**实验03（inject 声明依赖 + PENDING）** 的官方重述。

### 概念③ ⭐ 提供服务：`Service` 基类（本篇核心新知）

**这是 06 篇最重要的内容**——实验03 你可能只是在最小工程里写过一次，这里是**真实 dsh 插件的完整写法**。

```ts
import { Service, type Context } from '@deepseek-ai/cordis'

export default class MetricsService extends Service {
  static inject = ['llm']  // 服务本身也可以依赖其他服务

  constructor(ctx: Context) {
    super(ctx, 'metrics')  // 'metrics' 是服务名
  }

  // 公开的服务方法
  record(event: string, value: number) {
    // ...
  }
}
```

> **出处**：官方 service.zh.md（代码逐字）

**三个关键点**（逐条对照源码）：

1. **`extends Service` + `super(ctx, 'metrics')`** —— 以名字 `metrics` 注册。这就是**实验03 概念①** 讲的"源码 `service.ts:57` 调 `ctx.reflect.provide`"。
2. **`static inject = ['llm']`** —— **服务自己也能依赖其他服务**（服务是插件，插件能 inject）。
3. **`record()` 是公开方法** —— 消费方通过 `ctx.metrics.record(...)` 调用。

**注意**：这里 `export default class`——用的是**类形态插件**（01 篇概念⑤ 的第三种形态）。**需要对外提供服务时，就用类形态。**

**消费方如何用它**：

```ts
export const inject = ['metrics']
export function apply(ctx: Context) {
  ctx.metrics.record('tool_call', 1)
}
```

> **出处**：官方 service.zh.md（逐字）

**Go 类比**：`MetricsService` ≈ 一个实现了某 interface 的 struct；`super(ctx, 'metrics')` ≈ 把它注册到 DI 容器；消费方 `inject: ['metrics']` ≈ 声明"我要这个 interface"。

### 概念④ 类型声明：`declare module` 让 `ctx.metrics` 有类型（实验03 学过）

```ts
import { Service, type Context } from '@deepseek-ai/cordis'

declare module '@deepseek-ai/cordis' {
  interface Context {
    metrics: MetricsService
  }
}

export default class MetricsService extends Service {
  constructor(ctx: Context) {
    super(ctx, 'metrics')
  }
  record(event: string, value: number) { /* ... */ }
}
```

> **出处**：官方 service.zh.md（逐字）

**关联**：这是**实验03 概念②**（运行时 vs 编译时两条线）的完整重讲——`declare module` 是**编译时**（让 `ctx.metrics` 通过类型检查），`super(ctx, 'metrics')` 是**运行时**（真注册）。

### 概念⑤ 必需依赖 vs 可选依赖（实验03 学过）

> **出处**：官方 service.zh.md——*"必需依赖：服务缺失时插件不加载 / 可选依赖：省略 inject，在使用处用 `ctx.get()` 查询"*

```ts
// 必需：服务不在时插件不加载
export const inject = ['tools']

// 可选：省略 inject，在使用处用 ctx.get() 查询
export function apply(ctx: Context) {
  const metrics = ctx.get('metrics')
  metrics?.record('plugin_loaded', 1)
}
```

> **出处**：官方 service.zh.md（逐字）

⚠️ **踩坑提醒**（实验03 的原创发现）：`ctx.get()` 默认 `strict=true`，在 `apply` 里**同步**调用时，异步挂载的 provider 可能还没 ACTIVE → 返回 `undefined`。**可选依赖要在"使用处"探测**，不是初始化时。（详见实验03）

### 概念⑥ 服务消失时的行为（实验03 学过）

> **出处**：官方 service.zh.md——*"如果应用运行期间某项必需服务消失（例如其提供方卸载）：1. 依赖它的插件会自动 dispose；2. 当服务重新出现时，插件自动重新加载。"*

**关联**：这是**实验03 概念④（依赖持续跟踪）** 的重述，也是**05 篇 Fiber 状态机**的应用（依赖消失 → 卸载 → 恢复 → 重载）。

### 概念⑦ ⭐ 服务隔离（`isolate`）—— 新知

> **出处**：官方 service.zh.md——*"`cordis.yml` 支持服务隔离——同一个服务可以有多个实例，不同插件组看到不同实例："*

```yaml
- id: group-a
  name: '@deepseek-ai/cordis-plugin-group'
  group: true
  isolate:
    shell: true
  config:
    - name: '@deepseek-ai/dsh-bash-local'
      config:
        timeoutMs: 5000
    - name: './src/plugin-a.ts'

- id: group-b
  name: '@deepseek-ai/cordis-plugin-group'
  group: true
  isolate:
    shell: true
  config:
    - name: '@deepseek-ai/dsh-bash-local'
      config:
        timeoutMs: 60000
    - name: './src/plugin-b.ts'
```

> **出处**：官方 service.zh.md（逐字）

> **出处**：官方——*"`plugin-a` 和 `plugin-b` 各自看到自己组内的 Bash 实例，互不影响。"*

**解读**：
- **组（group）**：把一批插件打包成一个单元
- **`isolate: { shell: true }`**：该组内 `shell` 服务**用独立实例**——group-a 的 Bash 超时 5s，group-b 的 60s，**互不干扰**

**Go 类比**：像**多租户/多实例**——同一个 interface 名（`shell`），不同组有**各自的实现实例**，配置独立。

> **出处**：官方指向前置知识——`cordis-primer` 与 [服务隔离示例](../develop/framework/service.zh.md#service-isolation)；完整细节也可看 [入门](../...)

### 概念⑧ Harness 内置服务（了解）

> **出处**：官方 service.zh.md——*"服务名、公开方法和源码位置由仓库自动生成到各服务的[子系统页面](../../../subsystems/core.zh.md)。开发插件时应以这些生成区块和服务的 TypeScript 接口为准，不要维护另一份静态清单。"*

**要点**：dsh 的内置服务（`tools`/`llm`/`agents`/`shell`…）的**权威定义**在**子系统页面的自动生成区块**里——不要凭记忆写。开发时以 TypeScript 接口为准。

## 动手案例：提供 `metrics` 服务 + 消费它

> **规则（AGENTS.md）**：动手环节"你动手"。本文代码已写出并**已实测**。

**目标**：写**两个**插件——一个**提供** `metrics` 服务，一个**消费**它——验证"对外提供服务 → 别的插件通过 `ctx.metrics` 调用"。

案例在 `dsh-learn/plugins/metrics-demo/`，含：
- `metrics.ts` — **provider**：`MetricsService extends Service`，注册 `metrics`，提供 `record()` / `dump()`
- `consumer.ts` — **consumer**：`inject: ['metrics']`，调用 `ctx.metrics.record(...)`

### 提供方 `metrics.ts`

```ts
import { Service, type Context } from '@deepseek-ai/cordis'

declare module '@deepseek-ai/cordis' {
  interface Context {
    metrics: MetricsService
  }
}

export default class MetricsService extends Service {
  private counts = new Map<string, number>()

  constructor(ctx: Context) {
    super(ctx, 'metrics') // 以名字 'metrics' 注册本服务
    console.log('[metrics] 服务已注册')
  }

  record(event: string) {
    const next = (this.counts.get(event) ?? 0) + 1
    this.counts.set(event, next)
    console.log(`[metrics] record(${event}) -> ${next}`)
    return next
  }

  dump() {
    return Object.fromEntries(this.counts)
  }
}
```

### 消费方 `consumer.ts`

```ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'metrics-consumer'
export const inject = ['metrics']

export function apply(ctx: Context) {
  console.log('[consumer] metrics 服务就绪，开始消费')

  ctx.metrics.record('plugin_loaded')
  ctx.metrics.record('tool_call')
  ctx.metrics.record('tool_call')

  console.log('[consumer] 计数结果 =', JSON.stringify(ctx.metrics.dump()))
}
```

### 挂载层（provider 在前，consumer 在后）

```yaml
- insert:
    - id: metrics
      name: '/Users/melodycchen/ai-work/dsh/dsh-learn/plugins/metrics-demo/metrics.ts'
    - id: metrics-consumer
      name: '/Users/melodycchen/ai-work/dsh/dsh-learn/plugins/metrics-demo/consumer.ts'
```

### ✅ 实测输出（2026-09-16）

```
[metrics] 服务已注册
[consumer] metrics 服务就绪，开始消费
[metrics] record(plugin_loaded) -> 1
[metrics] record(tool_call) -> 1
[metrics] record(tool_call) -> 2
[consumer] 计数结果 = {"plugin_loaded":1,"tool_call":2}
```

> **出处**：本人实测（2026-09-16，`dsh 0.1.5-rc.1`）

**逐行解读**：

| 输出 | 证实的概念 |
|---|---|
| `[metrics] 服务已注册` | 概念③ provider 用 `super(ctx,'metrics')` **对外提供服务** |
| `[consumer] metrics 服务就绪` | 概念② consumer 靠 `inject` **等到服务就绪**（PENDING → ACTIVE） |
| `[metrics] record(...)` | 概念③ 消费方通过 `ctx.metrics.record()` **调用 provider 方法** |
| `[consumer] 计数结果 = {...}` | 服务的**返回值**能正常拿到（不只"能访问"，还能传数据） |

### 补充验证：服务缺失时 consumer 的行为（概念⑥）

只挂 `consumer`、**不挂 provider**，重新启动 → **无 `[consumer]` 输出**（`inject: ['metrics']` 缺依赖 → consumer PENDING → `apply` 不执行）。

> **出处**：本人实测（2026-09-16）——无 provider 时 consumer 静默 PENDING，印证概念⑥

## 一页纸总结

| 概念 | 一句话 | Go 类比 | 出处 |
|---|---|---|---|
| 服务 | 挂在 `ctx` 上的命名能力 | 注册到 DI 容器的 interface | 官方 service.zh.md |
| 消费：`inject` | 声明依赖，框架保证就绪 | 声明我要某 interface | 官方 + 实验03 |
| **提供：`Service` 基类** | `extends Service` + `super(ctx, name)` | 实现并注册一个 interface | 官方 service.zh.md |
| 服务可依赖服务 | `static inject = ['llm']` | 实现类自己也 inject | 官方 service.zh.md |
| 类形态插件 | `export default class ... extends Service` | —— | 官方 + 01 篇 |
| `declare module` | 让 `ctx.metrics` 有类型 | 编译期接口签名 | 官方 + 实验03 |
| 可选依赖 | `ctx.get()` 在使用处探测 | 可选注入 | 官方 + 实验03 |
| 服务消失行为 | 自动 dispose → 恢复重载 | 依赖变化触发生命周期 | 官方 + 实验03 |
| **服务隔离** | `isolate` 让同服务名有独立实例 | 多租户/多实例 | 官方 service.zh.md |
| 内置服务 | 权威定义在子系统页生成区块 | —— | 官方 service.zh.md |

## 踩坑记录

- **`ctx.get()` 同步 undefined**：可选依赖写法在 `apply` 里同步 `ctx.get()` 可能拿到 `undefined`（provider 异步挂载未 ACTIVE）；要在**使用处**探测。（出处：实验03 + `reflect.ts:12-18`）
- **`Service` 子类用类形态**：对外提供服务用 `export default class extends Service`，不是函数形态。（出处：官方 service.zh.md）
- **服务隔离只在组内生效**：`isolate` 配在 `cordis-plugin-group` 的组上，作用是让该组内的服务实例独立，不是全局。（出处：官方 service.zh.md）
