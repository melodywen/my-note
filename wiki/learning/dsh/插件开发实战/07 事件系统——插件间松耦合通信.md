## 先讲理论（完整版）

### 概念① 基本用法：`ctx.on` / `ctx.emit`（实验04 学过）

> **出处**：官方 events.zh.md——监听与触发：

```ts
// 监听
ctx.on('event-name', (payload) => { /* 处理 */ })

// 触发
ctx.emit('event-name', payload)
```

> **出处**：官方 events.zh.md（逐字）

**关联**：实验04 你已用过（`ctx.on('stats/report', ...)` / `ctx.emit(...)`）。

### 概念② 四种分发模式（实验04 亲手验证过）

> **出处**：官方 events.zh.md「事件模式」节

| 模式 | 调用 | 语义 |
|---|---|---|
| **emit** — 广播 | `ctx.emit(name, ...)` | 所有监听器**同步**执行，**返回值被忽略** |
| **bail** — 短路 | `ctx.bail(name, ...)` | 按顺序运行，**第一个非 `null`/`false`/`undefined` 的返回值成为结果** |
| **serial** — 顺序 | `await ctx.serial(name, ...)` | 按注册顺序执行并**等待异步**；首个非空返回终止后续 |
| **waterfall** — 流水线 | `await ctx.waterfall(name, ..., next)` | 每个监听器**包装下游返回值**，**必须调用 `next()`** |

> **出处**：官方 events.zh.md（逐字）

**代码示例**（官方给的）：

```ts
// bail
const result = ctx.bail('some-check', input)
ctx.on('some-check', (input) => {
  if (shouldBlock(input)) return 'blocked'
  // 返回 null / false / undefined 继续下一个
})

// serial
await ctx.serial('setup-phase', context)

// waterfall
const output = await ctx.waterfall('my-plugin/transform', input, async () => input)
ctx.on('my-plugin/transform', async (_input, next) => {
  const downstream = await next()
  return downstream.trim()
})
```

> **出处**：官方 events.zh.md（逐字）

> [!warning] waterfall 的纪律（实验04 重点）
> > **出处**：官方 events.zh.md——*"waterfall 监听器**必须调用 `next()`**。不调用 `next` 会短路整个流水线，这是故意为之的设计——用于实现拦截/网关逻辑。"*
>
> **关联**：实验04 你实测过——忘了 `next()` 会**静默吞掉下游**。

> [!note] 为什么官方表格只有 4 种，实验04 却讲 5 种？
> 实验04 讲的第五种是 **`parallel`**（并发跑所有监听器）。framework/events.zh.md 这页**只列了 emit/bail/serial/waterfall**——但阶段一我们发现 Cordis 实际有 **5 种**（含 `parallel`）。**官方这页是简化版**，完整 API 见 `cordis-api` 参考。

### 概念③ 类型安全的事件：`interface Events`（实验04 学过）

> **出处**：官方 events.zh.md——*"Harness 使用 TypeScript 声明合并来为事件提供类型安全："*

```ts
import '@deepseek-ai/cordis'

declare module '@deepseek-ai/cordis' {
  interface Events {
    'my-plugin/ready': (payload: { id: string }) => void
    'my-plugin/check': (input: string) => boolean | undefined
    'my-plugin/transform': (input: string, next: () => Promise<string>) => Promise<string>
  }
}
```

> **出处**：官方 events.zh.md（逐字）

**关联**：实验04 概念①——`interface Events` 让 `ctx.emit`/`ctx.on` 有完整类型。

### 概念④ ⭐ Cordis 事件 vs 持久化会话事件（本篇核心新知）

**这是 07 篇最值得记的区分**——**dsh 里有"两套事件体系"**：

> **出处**：官方 events.zh.md——*"Harness 的 Cordis 事件遵循 `namespace/action` 命名，例如 `agent/pre-step`、`agent/request`、`agent/request-error`、`tools/result` 和 `session/event`。完整签名与触发模式见子系统页面上生成的 `cordis-surface` 区块。"*

> **出处**：官方——*"**`turn/*`、`step/*`、`tool/call`、`tool/result` 和 `compaction/*` 是持久化的会话事件类型，不是同名 Cordis 事件。**需要观察它们时，监听 `session/event` 并检查 `event.type`。"*

**两套体系对照**：

| | **Cordis 事件** | **持久化会话事件** |
|---|---|---|
| 本质 | 内存中的**事件总线**（插件通信） | **落盘的会话记录**（trajectory） |
| 命名 | `namespace/action`（如 `tools/result`） | `turn/*`、`step/*`、`tool/call` 等 |
| 怎么监听 | `ctx.on('tools/result', ...)` | **监听 `session/event`**，检查 `event.type` |
| 出处 | 官方 events.zh.md | 官方 events.zh.md |

⚠️ **最容易踩的坑**：你以为 `tool/result` 是个 Cordis 事件，想 `ctx.on('tool/result', ...)` ——**错！** `tool/result` 是**持久化会话事件类型**；要观察它，得监听 **`session/event`** 然后判 `event.type === 'tool/result'`。

> [!warning] 注意 `tools/result` vs `tool/result`（差一个 s！）
> - `tools/result`（复数）= **Cordis 事件**（`ctx.on('tools/result', ...)`）——实验04/07 用的
> - `tool/result`（单数）= **持久化会话事件类型**（在 `session/event` 里）
>
> 官方特意提醒这个区分——**一字之差，体系不同**。

**Go 类比**：Cordis 事件 ≈ 进程内的事件总线（`chan`/pubsub）；持久化会话事件 ≈ **审计日志 / WAL**——它们会被落盘、可回放。**观察"发生了什么"要读日志（`session/event`），不是监听内存总线。**

### 概念⑤ 事件监听器也是 effect（实验04 学过）

> **出处**：官方 events.zh.md——*"通过 `ctx.on()` 注册的监听器会在插件卸载时自动移除："*

```ts
export function apply(ctx: Context) {
  ctx.on('tools/result', handler)   // 插件 dispose 时自动移除
}
```

> **出处**：官方 events.zh.md（逐字）

**关联**：实验04 概念④ + 05 篇（`ctx.on` 是自动清理清单之一）。**删除监听器也是"注册即 effect"的体现。**

### 概念⑥ 官方示例：日志插件（实验07 类似）

> **出处**：官方 events.zh.md「示例：日志插件」节

```ts
import type { Context } from '@deepseek-ai/cordis'
import '@deepseek-ai/dsh-tools'

export const name = 'tool-logger'

export function apply(ctx: Context) {
  ctx.on('tools/result', (exec, result) => {
    console.log(`[tool] ${exec.name}(${JSON.stringify(exec.arguments)})`)
    const text = result.content
      .map(block => block.type === 'text' ? block.text : '')
      .join('')
    console.log(`[tool result] ${text.slice(0, 100)}`)
  })
}
```

> **出处**：官方 events.zh.md（逐字）

**关联**：这跟**实验07 的 `tool-logger`** 几乎一样——监听 `tools/result`（Cordis 事件）观察工具调用。

### `emitter.ts`（派发 Cordis 事件）

```ts
import type { Context } from '@deepseek-ai/cordis'

declare module '@deepseek-ai/cordis' {
  interface Events {
    'demo/ready': (payload: { id: string }) => void
  }
}

export const name = 'event-emitter'

export function apply(ctx: Context) {
  console.log('[emitter] 派发 Cordis 事件 demo/ready')
  ctx.emit('demo/ready', { id: 'worker-1' })
}
```

### `listener.ts`（监听 Cordis 事件 + 会话事件）

```ts
import type { Context } from '@deepseek-ai/cordis'
import type {} from './emitter.ts'

export const name = 'event-listener'

export function apply(ctx: Context) {
  // ① 监听自定义 Cordis 事件
  ctx.on('demo/ready', ({ id }) => {
    console.log(`[listener] 收到 Cordis 事件 demo/ready：${id} is ready`)
  })

  // ② 监听会话事件（turn/*、step/*、tool/call 等「不是」Cordis 事件）
  ctx.on('session/event', (session: unknown, event: { type?: string }) => {
    console.log(`[listener] 收到会话事件 session/event，type = ${event?.type}`)
  })
}
```

### ✅ 实测输出（① Cordis 事件，2026-09-16）

```
[emitter] 派发 Cordis 事件 demo/ready
[listener] 收到 Cordis 事件 demo/ready：worker-1 is ready
```

> **出处**：本人实测（2026-09-16，`dsh 0.1.5-rc.1`）

**证实**：`namespace/action` 命名（`demo/ready`）+ `interface Events` 声明合并 + `ctx.emit`/`ctx.on` 全链路通。

## 一页纸总结

| 概念 | 一句话 | Go 类比 | 出处 |
|---|---|---|---|
| `ctx.on`/`emit` | 监听 / 广播 | 事件总线 | 官方 events.zh.md |
| emit | 同步广播，忽略返回值 | fire-and-forget | 官方 + 实验04 |
| bail | 短路，首个非空返回胜出 | 中间件短路 | 官方 + 实验04 |
| serial | 顺序 + 等待异步，首个非空终止 | 中间件链 | 官方 + 实验04 |
| waterfall | 流水线，必须调 `next()` | 洋葱中间件 | 官方 + 实验04 |
| `interface Events` | 类型安全的声明合并 | 事件签名表 | 官方 + 实验04 |
| **⭐ Cordis 事件** | 内存事件总线（`tools/result`） | pubsub | 官方 events.zh.md |
| **⭐ 会话事件** | 落盘记录，监听 `session/event`（`tool/result`） | 审计日志/WAL | 官方 events.zh.md |
| 监听器也是 effect | 卸载自动移除 | `defer` | 官方 + 实验04 |

## 踩坑记录

- **⚠️ `tools/result` ≠ `tool/result`**：前者（复数）是 **Cordis 事件**（`ctx.on` 直接用）；后者（单数）是**持久化会话事件类型**——要通过 `session/event` + 判 `event.type` 观察。（出处：官方 events.zh.md）
- **waterfall 忘调 `next()` = 静默短路**：只观察的监听器必须 `return next()`。（出处：官方 events.zh.md + 实验04）
- **官方 events 页只列 4 种模式**：实际 Cordis 有 5 种（含 `parallel`）——完整 API 见 `cordis-api`。（出处：官方 events.zh.md vs 实验04）
