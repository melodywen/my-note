# 02.1 cordis-host-runner——动态插件的运行时与沙箱

> [!info] 版本锚点
> - 源码：`~/ai-work/dsh/deepseek-harness/`（master `0d1f50007f`）；全局包 `dsh 0.1.5-rc.1`
> - 前置：**02 篇（dynamic-cordis）**——本篇是它的**深入子篇**，专讲里面的运行时宿主
> - 写法说明：本系列采用**完整重讲式**；本篇以**读源码 + 讲机制**为主

> [!abstract] 本章是什么 / 该记住什么
> **性质**：**02 篇（dynamic-cordis）的深入子篇**——专讲那个"让动态插件跑起来"的运行时宿主。
> ⚠️ **先澄清一个常见误解**：`cordis-host-runner` **不只是"沙箱"**——它是**运行时宿主**（注册表 + 沙箱 + inspect + 生命周期）。
> **读完该记住 4 点**：
> 1. **它是运行时宿主**，沙箱只是它的一部分（`DynamicCordisRunnerService` 是主类）
> 2. **沙箱机制**：Node 全局 → "陷阱函数" → 引导你用 **Cordis 服务**（`ctx.fs`/`ctx.web`/`ctx.bash`）
> 3. **⭐ 沙箱 ≠ 安全边界**：**防误用、不防恶意**——**视同 bash 权限**
> 4. **版本不可变**：`define` 出的包永不改，改就是**新版本**（`currentPackageId` vs `nextPackageId`）

## 这一篇在讲什么

02 篇你知道了"Agent 能运行时写插件"。**但"插件写出来后，谁让它跑起来？"**——答案就是 **`cordis-host-runner`**。

> **出处**：`cordis-host-runner/README.zh.md`（逐字）——*"让动态包在本进程中可运行：模型用 `cordis_define` 记录的定义留在这里，host 半在 `node:vm` 沙箱中运行…模型也可以在这里检查实时运行时及其定义。"*

**一句话**：**它是"动态插件的宿主进程"**——注册表（存定义）+ 沙箱（`node:vm` 跑代码）+ inspect（查询）。

> **Go 类比**：像**一个能动态加载 `.so` 的宿主程序**——给你个"受限运行时"（沙箱隔离全局），但**加载进来的 `.so` 能干啥，取决于它声明的依赖**。

## 一、它**不只是**沙箱——内部拆解

**⚠️ 常见误解**："`cordis-host-runner` = 沙箱"。**不准确**——它是**运行时宿主**，沙箱是**其中一部分**。

> **出处**：README「设计理念」（逐字）——*"**注册表与沙箱是同一个服务。** `DynamicCordisRunnerService` 拥有定义注册表、vm 沙箱、host 半 fiber 生命周期与 invoke handler 表，因此**一个定义的整个生命周期只有一个 owner**。"*

## 二、⭐ 沙箱机制：Node 全局 → "陷阱" → Cordis 服务

**这是本篇最核心的技术点。**

> **出处**：`sandbox.ts:4-6`（逐字头注释）——*"callable traps over the Node APIs the sandbox deliberately withholds. **Traps steer filesystem, network, process, and timer work to `ctx.fs`, `ctx.web`, `ctx.bash`, and Cordis timers**."*

### 机制：把 Node 全局换成"陷阱函数"

插件代码里如果用 `fs`/`fetch`/`setTimeout`——**不是给你真的 Node API，而是抛"重定向错误"**，告诉你"用 Cordis 服务"：

| 插件想用 | 陷阱 → 引导到 |
|---|---|
| `fs`（文件） | `ctx.fs`（`inject: ['fs']`） |
| `fetch`（网络） | `ctx.web`（`inject: ['web']`） |
| 进程 | `ctx.bash`（`inject: ['bash']`） |
| `setTimeout` 等 | Cordis timers（`ctx.timeout`/`ctx.interval`） |
| `process`（**数据值全局**） | **保持 `undefined`** |

**具体报错**（`sandbox.ts` 里的陷阱文案）：
> *"Node modules are unavailable. Use the cordis services on ctx instead — e.g. inject: `['fs']` for files, `['web']` for HTTP, `['bash']` for processes; query Service.listService with `cordis_inspect_query` first."*

### 🔬 "陷阱函数"的真身（源码 + Go 类比）

"陷阱函数"是**具体的技术手段**——**给你一个"同名、但一调用就报错的替身"**。看源码（`sandbox.ts:96-122`）：

```ts
// ① 定义"哪些 Node API 被禁 + 该引导到哪"
const NODE_API_REDIRECTS = {
  require:      'Node modules are unavailable. Use the cordis services on ctx instead...',
  setTimeout:   TIMER_REDIRECT,
  fetch:        'Network access goes through the cordis web service: declare inject: [\'web\'] and call ctx.web...',
  // ...
}

// ② 为每个禁用的 API 造一个"陷阱函数"
function nodeApiTraps() {
  const traps = {}
  for (const [name, redirect] of Object.entries(NODE_API_REDIRECTS)) {
    traps[name] = () => {                     // ← 陷阱函数本体
      throw new Error(`${name} is not available in the dynamic package sandbox — ${redirect}`)
    }
  }
  return traps                                // { fetch: () => { throw ... }, setTimeout: () => { throw ... } }
}

// ③ 把陷阱塞进 vm 的"全局表"
export function createSandbox(id) {
  const sandbox = {
    ...nodeApiTraps(),          // ← fetch/setTimeout 指向的就是这些"替身"
    console: taggedConsole(id),
    harness: { defineTool, registerTool, ... },
    // ...
  }
  // → 作为 vm 的执行环境
}
```

> **出处**：源码 `sandbox.ts:96-135`

**效果**：插件代码里的 `fetch(...)`——
- **真实期望**：真的发网络请求
- **沙箱实际**：**抛错** `"fetch is not available in the dynamic package sandbox — …use ctx.web…"`

**"陷阱（trap）"的意思**：像**捕兽夹**——你踩上去（调用），它**夹住你**（抛错），**不让你过去**。

> **Go 类比**：像**用 mock 换掉 `os.Getenv`**：
> ```go
> var Getenv = func(k string) string {
>     panic("环境变量不可用，请改用 ConfigService.Get()")   // ← 陷阱：一调就 panic
> }
> ```
> **没拦住"读环境变量"这件事**——**把它换成了一个"调用就报警"的替身**。

**目的**：**逼插件走"可观测、可回收"的 Cordis 服务**（`ctx.web`/`ctx.fs`），而不是偷偷用 Node 全局。

### 两个细节

1. **只 trap "函数值"的全局**
   > **出处**：`sandbox.ts:91-92`（逐字）——*"Only function-valued globals are trapped; a data-valued global such as `process` stays `undefined`."*
   ——`process` 是数据值（不是函数）→ **直接 undefined**（连陷阱都不给）。

2. **`ctx` 也被"façade 化"**：沙箱里的 `ctx` **不含框架内部机制**（只暴露 `get`/`on`/`provide`/`effect` 等）。

> **Go 类比**：像**给你一个"受限的 `os` 包"**——`os.Open` 调不了，会让你**改走依赖注入的接口**（`ctx.fs`）。**逼你走"可观测、可回收"的正路。**

## 三、⭐ 最重要认知：沙箱 **≠** 安全边界

> **出处**：README「信任立场」（逐字）——*"沙箱隔离全局变量，**但不是安全边界**：Node 全局变量不存在，或重定向到 Cordis 服务…host 半收到的是不含框架内部机制的 façade，但**它声明的服务仍会触达存活运行时**。对待动态包要像对待 **bash 访问**一样。"*

### 翻译成人话

| 沙箱**做了** | 沙箱**没做** |
|---|---|
| **防"误用"**：插件作者想读文件 → `fs` 被 trap → 引导用 `ctx.fs`（可观测、可回收） | **防"恶意"**：插件声明 `inject: ['bash']` → **就能 `ctx.bash` 执行命令**（**触达真运行时**） |

**所以**：**加载这个插件 = 给了它 bash 权限**。

### 为什么这样设计

> **出处**：`sandbox.ts:6`——*"keeps **cooperative** packages inspectable and disposable"*

**为"协作式"插件服务**（可检查、可回收），**不是"防御式"**。**它假设插件作者是"合作的"**——所以：

> **⚠️ 别把它当安全沙箱**。要跑**不可信的**动态插件？**这是"给 shell 权限"级别的操作**。

> **Go 类比**：像**给同事 root 但打了日志**——不是"挡住他",是"**让他好排查、能回收**"。**信任是前提。**

### ⚠️ "有意攻破"——**完全可以，官方明说**

**关键认知**：沙箱**只防"无意旁路"，不防"有意攻破"**。**如果你（插件）就是有心要绕过它——能绕过去。**

> **出处**：Agent Note `2026-07-08-self-referential-cordis-toolset`（逐字，`@.agents/notes/...`）——*"临时插件可以调用 `ctx.shell` 以**宿主执行器的权限运行命令**，也能**访问真实的文件系统和网络服务**。它运行在共享 DSH 运行时中，**可能影响同一进程的其他会话**。"*

**"有意攻破"的两条具体路径**：

| 路径 | 怎么破 | 依据 |
|---|---|---|
| **① 声明 `ctx.shell`/`ctx.bash`** | 插件 `inject: ['bash']` → `ctx.bash` **以宿主权限执行命令** | Agent Note `:17` |
| **② 直连真实 `ctx.fs`/`ctx.web`** | 通过它们**访问真实文件系统 / 网络** | Agent Note `:17` |
| **③ 底层 `node:vm` 本身不是安全机制** | Node 官方**明说 `vm` 不是安全边界**——存在逃逸手法 | Node 官方文档 |

**官方对"为什么不加固"的解释**（很重要）：

> **出处**：Agent Note `:80`（逐字）——*"陷阱和门面收窄的是挂载代码所见的 *API*——将其引导至 cordis 服务…目的是**正确性和封堵未受保护的上下文逃逸**，**但门面暴露的能力（`ctx.shell`、`ctx.fs`、`ctx.web`）触及真实运行时，因此它不是安全边界**。**真正的安全边界（独立进程、权限提示）超出…范围，且会与其核心目的——将活跃运行时交给模型——相冲突**。"*

**翻译**：**做真安全边界（独立进程、权限提示）会"杀死这个功能的目的"**——这个功能**本来就是要"把活跃运行时交给模型"**。**所以它选择"信任"而非"隔离"。**

> **一句话**：**"有心攻破，就能攻破"**——**沙箱不是"锁",是"路标"**（引导你走正路，不拦你走偏路）。

> **⚠️ 实用结论**：**动态插件 = 你主动交给模型的"shell 权限"**——**只在"你信任模型 + 是你自己开发"的场景用**（开发工具，非产品默认）。

## 四、一次 run 的流程

> **出处**：README「一次 run 的流程」（要点）

```
define  → 校验元数据 + 语法预检（【不执行】）+ 铸插件/包 ID + 登记到会话
run     → 解析目标：
          ・纯 host 包      → 沙箱求值 + 立即提交
          ・带浏览器半的包  → 建审批请求 + emit cordis/request-run + 【挂起】
stop    → 回退下发（handler disposer + fiber dispose + 广播），【定义保留】
```

**"版本不可变"**（设计理念）：
> *"版本是不可变的包。插件持有 `define` 之后永不变化的包；`currentPackageId` 与 `nextPackageId` 指向运行中与目标版本，`mode: "run"` 与 `"update"` 编码目标是否等于当前版本。"*

**四条转发事件**（client 安全，经 `dsh-api-remotes` 白名单）：
`cordis/request-run`、`cordis/request-run-resolved`、`cordis/dynamic-package`、`cordis/dynamic-retract`。

## 五、已知限制（README 明列）

> **出处**：README「已知限制与延期工作」（逐字要点）

| 限制 | 说明 |
|---|---|
| **run 成功 ≠ UI 渲染成功** | 只要作答页面装了浏览器半，`run` 就返回；React 随后才渲染，抛异常的组件**不在 run 回执里**（靠 steering + `inspect_self` 浮现） |
| **带浏览器半的包无页面时挂起** | headless / ACP 会挂到轮次取消；**纯 host 包不受影响** |
| **挂起的 run 请求没有超时** | 一直等人——**无人值守用不了带浏览器半的包** |
| **`vmTimeoutMs` 只管同步求值** | **async 的 host 半函数体逃出上限**（与协作式信任立场一致） |
| **陈旧成功的拒绝让请求继续挂** | 页面点名的 revision 被越过时结论被拒（`accepted: false`），请求保持可作答 |

> **一条给我们的实用结论**：**要自动化用，别用"带浏览器半的包"**——会挂起等页面。

## 踩坑预防

- **⚠️ `cordis-host-runner` ≠ 沙箱**：它是运行时宿主，沙箱只是内部一部分。（出处：README「设计理念」）
- **⚠️ 沙箱不是安全边界**：能触达 live 运行时（声明 `bash` 就能执行命令）——**按 bash 权限对待**。（出处：README「信任立场」）
- **⚠️ `vmTimeoutMs` 逃得掉**：async host 半函数体不受该上限约束。（出处：README「已知限制」）
- **⚠️ 带浏览器半的包会挂起**：无页面连接时挂到轮次取消——**自动化别用**。（出处：README「已知限制」）
