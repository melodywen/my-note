# 04.2 agent preset 的文件结构——preset.yml 与 agent.cordis.yml

> [!info] 版本锚点
> - 源码：`~/ai-work/dsh/deepseek-harness/`（master `0d1f50007f`）；全局包 `dsh 0.1.5-rc.1`
> - 前置：**04.1 篇（agent preset 与系统提示词）**、**03 篇（patch 概念）**
> - 写法说明：本系列采用**完整重讲式**；以**读源码 + 讲机制**为主

> [!abstract] 本章是什么 / 该记住什么
> **回答的问题**："一个 preset 由哪些文件组成？`preset.yml` 干嘛的、有哪些参数？"
> **读完该记住 4 点**：
> 1. **一个 preset = 一个目录**，含 **2 个文件**：`agent.cordis.yml`（**必需**，能力）+ `preset.yml`（**可选**，展示）
> 2. **目录名 = preset id**（不能在这俩文件里写 id）
> 3. **`preset.yml` 只有 3 个参数**：`name` / `description` / `order`
> 4. **`agent.cordis.yml` 就是"patch 列表"**（和 bundle 的 `cordis.patch.yml` 同一种格式——回扣 03 篇）

## 这一篇在讲什么

04.1 讲了"**你的 prompt 怎么进系统提示词**"（`persona` 机制）。这一篇讲**更基础的一层**：**一个 preset 目录里到底有哪些文件、每个文件干嘛**。

> **出处**：`packages/preset/agent-presets/src/discovery.ts:2`（逐字）——*"**A preset is a directory holding `COMPOSITION_FILE`, optionally beside a `METADATA_FILE` carrying its display text; the directory name is the preset id.**"*

**一句话**：**一个目录 + 2 个文件 = 一个 preset。**

```
presets/my-agent/               ← 目录名 = preset id
├── agent.cordis.yml            ← 必需：能力（persona + 工具 + 行为）
└── preset.yml                  ← 可选：展示（名字/描述/排序）
```

---

## 一、`agent.cordis.yml`——**必需**，管"能力"

**它是"让一个目录成为 preset"的文件**：

> **出处**：`discovery.ts:37`（逐字）
```ts
export const COMPOSITION_FILE = 'agent.cordis.yml'
```

### ⭐ 它就是个 **patch 列表**（回扣 03 篇）

> **出处**：`discovery.ts:197-219`（逐字）——*"Parsed with the loader's own YAML dialect (`entryListSchema`, the one carrying `!!js`)…"*

**即**：**`agent.cordis.yml` 和 bundle 的 `cordis.patch.yml` 用的是同一套格式**（`entryListSchema`）——**一个"顶层 YAML 列表"**（`- id: xxx` 那些）。

**看真实的 `minimal/agent.cordis.yml`**：
```yaml
- id: persona                              # ← 一个个"插件行"
  name: '@deepseek-ai/dsh-persona'
  config:
    prefix: You are a helpful software engineer assistant.
    complete: true
    includeRuntimeContext: false

- id: persistent-shell
  name: cordis:group
  ...
```

**所以**：**`agent.cordis.yml` = "这个 agent 装哪些插件"的 patch 列表**——
- **`persona` 行** → **人设（prompt）**（04.1 篇）
- **工具行** → agent 能用哪些工具
- **其他行** → 门控行为

> **回扣 03 篇**：**它和 `cordis.patch.yml` 是"同一种东西"**（patch 列表）——只是**用途不同**（一个配 agent，一个配整棵树）。

## 二、`preset.yml`——**可选**，管"展示"

**它是"给选择器（picker）看的展示信息"**：

> **出处**：`metadata.ts:25`（逐字）
```ts
export const METADATA_FILE = 'preset.yml'
```

### 为什么单独一个文件？（设计原因）

> **出处**：`metadata.ts` 头注释（逐字）——*"它住在自己的文件里，因为**组合（composition）是一个顶层插件行列表——YAML 无法在上面带兄弟键**……把元信息分开，也让组合保持"名副其实"：一个 Loader 拥有的 Cordis 文件。"*

**翻译**：
- **`agent.cordis.yml` 是"一个顶层列表"**（`- id: xxx`）——**没地方塞"名字/描述"**（YAML 顶层列表不能带兄弟键）
- 所以 **`preset.yml` 单独放**

### 它的 **3 个参数**（全部）

> **出处**：`metadata.ts:23-34`（`PresetMetadata`，逐字）

| 参数 | 类型 | 必填 | 含义 | 默认 |
|---|---|---|---|---|
| **`name`** | string | ❌ | **显示名**（人类看的名字） | **回退到 preset id（=目录名）** |
| **`description`** | string | ❌ | **一句话说明**（干啥的） | 无 |
| **`order`** | number | ❌ | **排序位置**（**越小越靠前**） | 没声明 → **排在"声明了的"之后**，再按 id |

**逐参数细说**：

- **`name`**：*"Human-facing name; **falls back to the preset id when absent**."* —— **不写就用目录名**
- **`description`**：*"One sentence on what this preset is for."* —— 选择器里的副标题
- **`order`**：*"**lower comes first**. A preset that declares none **sorts after every preset that does**, then by id."* —— **越小越靠前；不写排最后**

**真实例子**（内置 4 个）：
> **出处**：`presets/*/preset.yml`
```yaml
# standard
name: 标准模式
description: 功能完整的编码 Agent，支持文件编辑、Shell…
order: 1
# ptc: order 2 / minimal: order 3 / cordis: order 4
```

### 🖼️ 这三个参数在 UI 里长啥样（直观理解）

**假设你写**：
```yaml
name: 代码审查助手
description: 专注代码审查的 agent
order: 10
```

**UI 的 preset 选择器大概长这样**：

```
标准模式          功能完整的编码 Agent…       ← order 1（内置）
PTC 模式          功能完整的编码 Agent，但…    ← order 2
极简模式          仅提供持久 shell…           ← order 3
创造模式          用于创建自定义 Agent…       ← order 4
────────────────────────────────────────
代码审查助手       专注代码审查的 agent         ← order 10（你的）
↑ name           ↑ description
```

| 参数 | 管什么 | UI 效果 |
|---|---|---|
| **`name`** | 显示名 | 那行**大字** |
| **`description`** | 说明 | 那行**小字/副标题** |
| **`order`** | 排序 | **列表里的位置**（`10 > 4` → 排内置后面） |

**关键**：**这 3 个都是"给人看的"**——**和 agent 的实际能力（prompt、工具）无关**（那些在 `agent.cordis.yml`）。

> **一句话**：**`preset.yml` 的 3 个参数 = "这个 preset 在选择器里长啥样"**（名字好看、说明清楚、排得合适）。

### ⚠️ 3 个**不能写**的（安全）

> **出处**：`metadata.ts` 头注释（逐字）——*"The file carries **display text ONLY**. `id` is the directory name and `trust` comes from the root a preset was discovered under, so **neither is writable here** — otherwise a locally authored preset could claim to be a shipped one."*

| 不能写 | 为什么 |
|---|---|
| **`id`** | 就是**目录名** |
| **`trust`** | 来自**"发现根"**（内置 vs 用户）——**不许自声明**（防本地 preset 冒充内置） |

（`order`/`name`/`description` 之外——**别的字段写了会被忽略**，因为 schema 只认这 3 个。）

### ⚠️ 一个特性：**它坏了也不影响运行**

> **出处**：`metadata.ts` 头注释（逐字）——*"**Every read failure degrades to no metadata. A preset whose display text is missing, malformed, or unreadable still mounts**：presentation is not a capability, and a broken name must never become an agent that cannot start."*

**翻译**：**`preset.yml` 完全没有也能跑**（选择器显示目录名）；**坏了/读不了也不影响**（"展示不是能力"）。

## 三、两个文件的**分工**（一句话）

| 文件 | 管什么 | 必需？ | 类比（回扣 03 篇） |
|---|---|---|---|
| **`agent.cordis.yml`** | **能力**（persona + 工具 + 行为） | ✅ | 像 `cordis.patch.yml`（patch 列表） |
| **`preset.yml`** | **展示**（name/description/order） | ❌ | 像 UI 的"标签" |

**核心**：**`preset.yml` 纯展示，不参与"agent 能力"**——**能力全在 `agent.cordis.yml`**。

## 四、放哪 + 怎么被发现

### ⭐ 主推：放**你自己的工程**（配 `roots`）

**preset 不必放 `~/.dsh`**——**可以跟你工程走**（版本控制、团队共享）。做法：**配 `agent-presets` 的 `roots` 指到你工程目录**。

> **出处**：`agent-presets/src/index.ts:181-185`（逐字）——发现根 = **`[shipped] + config.roots + [user]`**——**`config.roots` 是"你指定的任意路径"**。

**① 在工程里建 preset**：
```
dsh-learn/example/deepwater/presets/demo-agent/
├── preset.yml
└── agent.cordis.yml
```

**② 写个 patch 配 `roots`**：
```yaml
# example/deepwater/presets/agent-presets.patch.yml
- id: agent-presets
  config:
    default: standard
    roots:
      - path: '/Users/melodycchen/ai-work/dsh/dsh-learn/example/deepwater/presets'
        trust: 'user'
```

**③ 启动时叠这个 patch**：
```sh
dsh web --patch <codebuddy> --patch example/deepwater/presets/agent-presets.patch.yml
```

**✅ 实测**（本人）：调 `discoverPresets` 发现工程内的 `demo-agent` 被成功读出：
```json
{ "id": "demo-agent", "trust": "user", "name": "演示助手", "description": "放在工程里的自定义 preset", "order": 10 }
```

> **出处**：本人实测（2026-09-16）——工程内 preset + `roots` 配置 → 成功发现

### 三类发现根（按顺序）

> **出处**：`agent-presets/src/index.ts:181-185`（逐字）
```ts
resolvedRoots = [
  ...includeShippedRoot ? [{ path: SHIPPED_PRESET_ROOT, trust: 'system' }] : [],  // ① 内置
  ...config.roots,                                                                  // ② ⭐ 你配的（含你的工程）
  ...includeUserRoot ? [{ path: dshHomePath(USER_PRESET_DIR), trust: 'user' }] : [], // ③ ~/.dsh/.agent-presets
]
```

| 根 | 位置 | 怎么来 |
|---|---|---|
| ① **内置**（shipped） | 包内 `presets/` | 默认开（`includeShippedRoot`） |
| ② ⭐ **你配的**（`config.roots`） | **任意路径（你的工程！）** | **你写 `roots: [{path, trust}]`** |
| ③ **用户默认**（user） | `~/.dsh/.agent-presets/` | 默认开（`includeUserRoot`） |

> **出处**：`discovery.ts:51`（`USER_PRESET_DIR`）、`:60`（`SHIPPED_PRESET_ROOT`）；`PresetRoot = { path, trust }`（`preset.ts:44`）

**⚠️ 关键**：**preset 放哪都行**——**`agent.cordis.yml` 里的包名（`@deepseek-ai/dsh-xxx`）由 harness 解析**（不是 preset 目录）：

> **出处**：`agent-presets/src/index.ts:136-140`（逐字）——*"a preset's own directory is the wrong base for a package name… **Node's upward `node_modules` walk never reaches the harness's dependencies**"*

**所以**：**放工程里，不用在工程里装那些 dsh 包**。

### 发现机制（3 个特点）

> **出处**：`discovery.ts` 头注释（逐字）

| 特点 | 说明 |
|---|---|
| **目录名 = id** | *"the directory name is the preset id"* |
| **每次调用重读** | *"Discovery re-reads the roots on every call **so a preset authored while the process is running is visible without a restart**"* |
| **优先级** | *"an earlier root wins a duplicate id"*（同名时前面的赢——**shipped 最前，所以内置的同名会赢**） |

### ⚠️ 独有的"健康检查"（health）

> **出处**：`discovery.ts` 头注释（逐字）——*"a directory whose composition is **missing or unloadable is reported as a broken roster row rather than skipped**."*

**翻译**：
- **`agent.cordis.yml` 缺失或坏 → 标为"损坏行"**（**不静默跳过**）
- **选择器会"丢掉损坏行"**（而不是等会话启动才失败）
- 检查是**浅层 shape check**（不 import 任何东西，**不跑一行插件代码**）

> **为什么**：*"a skipped directory would still occupy its id on disk"*——**跳过了还会占着 id**，不如**明确报"坏了"**。

> **规则（AGENTS.md）**：动手环节"你动手"。**"放工程 + 配 roots"已实测**（`discoverPresets` 成功发现）；**完整启动未逐条实跑**。

## 一页纸总结

| 概念 | 一句话 | 出处 |
|---|---|---|
| **preset = 目录** | 目录名 = preset id | `discovery:2` |
| **`agent.cordis.yml`** | 必需；**能力**（就是个 patch 列表） | `discovery:37` |
| **`preset.yml`** | 可选；**展示**（name/description/order） | `metadata:25` |
| **`name`** | 显示名；缺省用目录名 | `metadata:30` |
| **`description`** | 一句话说明 | `metadata:32` |
| **`order`** | 越小越靠前；缺省排最后 | `metadata:38` |
| **不能写 `id`/`trust`** | id=目录名；trust=发现根 | `metadata` 头注 |
| **坏了也能跑** | 展示不是能力 | `metadata` 头注 |
| **放哪** | ⭐ **可放工程**（配 `roots`）；或 `~/.dsh/.agent-presets/`；内置 `presets/` | `agent-presets:181` |
| **健康检查** | 坏 composition 标"损坏行"，不静默跳 | `discovery` 头注 |

## 踩坑预防

- **⚠️ `agent.cordis.yml` 是"顶层列表"**：不能在里面写 name/description（YAML 顶层列表没法带兄弟键）——**那归 `preset.yml`**。（出处：`metadata` 头注）
- **⚠️ `preset.yml` 只能有 3 个字段**：`name`/`description`/`order`；写别的被忽略。（出处：`PresetMetadata`）
- **⚠️ 别想写 `id`/`trust`**：防冒充。（出处：`metadata` 头注）
- **⚠️ `preset.yml` 是可选**：没有它 preset 照样跑（显示目录名）。（出处：`metadata` 头注）
