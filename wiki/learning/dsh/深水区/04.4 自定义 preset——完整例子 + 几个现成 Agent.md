# 04.4 自定义 preset——完整例子 + 几个现成 Agent

> [!info] 版本锚点

> [!abstract] 本章是什么 / 该记住什么
> **回答的问题**："自定义 preset **完整**怎么写？给我几个能抄的例子。"
> **读完该记住 3 点**：
> 1. **一个 preset = 2 文件**（`preset.yml` + `agent.cordis.yml`）
> 2. **最稳的创作法**：**复制一个内置 preset → 改**（官方 `cordis` preset 明文推荐）
> 3. **给 6 个现成例子**：审查 / 极简 / 翻译 / 贴吧客服 / 只在后台跑 / 带工具的完整版

## 这一篇在讲什么

前面讲清了机制（提示词/文件/complete）。**这一篇给"可直接抄的完整例子"**——你选一个改改就能用。

> **官方创作法**（逐字，`cordis` preset 的 persona）——*"要改内置 preset 的行为，**把它的 composition 复制到一个新的 preset 目录，改副本**。"*

## 一、完整结构（照这个建）

**⭐ 放在你的工程里**（已验证可行）：

```
your-project/presets/<你的id>/          ← 工程内的 presets 目录
├── preset.yml            ← 展示（name/description/order）
└── agent.cordis.yml      ← 能力（persona + 工具）
```

**再配一个 patch，把发现根指过来**（`presets/agent-presets.patch.yml`）：
```yaml
- id: agent-presets
  config:
    default: standard
    roots:
      - path: '/绝对路径/your-project/presets'
        trust: 'user'
```

### 🚀 怎么跑（6 个例子共用）

**本文 6 个例子都已在工程里建好**（`example/deepwater/presets/`），**一键启动**：

```sh
cd ~/ai-work/dsh/dsh-learn/example/deepwater/presets
./start.sh
```

**然后**：浏览器打开它打印的 URL → **preset 选择器里选对应名字** → **发一句话，观察行为**。

> **`./start.sh` 干跑已验证**（列出 6 个 preset + 拼好命令）；**6 个 preset 被 `discoverPresets` 发现已验证**。
> **每个例子的"看什么"**见下方各节。

> **出处**：`agent-presets/src/index.ts:181-185`（`roots = [shipped] + config.roots + [user]`）
> **（也可放 `~/.dsh/.agent-presets/<id>/`——默认 user 根，自动发现）**

**⚠️ 规矩**：
- **目录名 = preset id**（用小写英文 + `-`）
- **别改内置的**（`cordis` preset persona 逐字警告：*"NEVER edit or delete the shipped preset install… an upgrade overwrites it"*）
- **包名由 harness 解析**（`@deepseek-ai/dsh-xxx`）——**工程里不用装这些包**

**效果**：人设="严谨审查"，**工具/能力照旧**（能读文件、跑命令）。

## 四、⭐ 例子 3：极简模式（`complete: true`，只有自己的 prompt）

> **照官方 `minimal` preset 抄**（它就是这个用法）。

**`example/deepwater/presets/myminimal/agent.cordis.yml`**：
```yaml
- id: persona
  name: '@deepseek-ai/dsh-persona'
  config:
    prefix: You are a helpful software engineer assistant.
    complete: true                 # 只有这一句，官方全抑制
    includeRuntimeContext: false
```

**效果**：系统提示词**只有一句**（回扣 04.3——**代价：砍掉工具用法说明**）。

**▶ 怎么跑 + 看什么**：
```sh
cd ~/ai-work/dsh/dsh-learn/example/deepwater/presets
./start.sh
```
→ UI 选「**极简模式**」→ 发"读取 xxx 文件" → **看它是否"不太会用 read 工具"**（因工具用法说明被砍——这正是 `complete: true` 的代价）。

## 六、⭐ 例子 5：带工具选择的 Agent（加/删能力）

**`agent.cordis.yml` 是 patch 列表**（回扣 03 篇）——**你能控制"这个 agent 有哪些工具"**：

> **出处**：`cordis` preset 挂了 `tool-bash` / `tool-fs` / `tool-jobs` / `tool-goal` 等（真实内容）

**例**：一个"**只读**"agent（禁掉写工具）——**从 `standard` 复制，删/禁掉写工具**：
```yaml
- id: persona
  name: '@deepseek-ai/dsh-persona'
  config:
    prefix: 你是一个只读助手，绝不能修改文件。

# 显式"禁用"写工具（disabled: true）
- id: tool-write
  disabled: true
- id: tool-edit
  disabled: true
```

> **出处**：patch 语法（09 篇）——`- id: xxx  disabled: true` 禁用某行

**效果**：agent **只能读、不能写**。

**▶ 怎么跑 + 看什么**：
```sh
cd ~/ai-work/dsh/dsh-learn/example/deepwater/presets
./start.sh
```
→ UI 选「**只读助手**」→ 发"把 a.txt 改成 b.txt" → **看它是否拒绝写、只给建议**（写工具被 `disabled`）。

## 七、⭐ 例子 6：给"子 agent"换人设（用 `tool-subagent` 的 persona）

> **⚠️ 一个易错点（实测澄清）**：**子 agent 默认继承父 agent 的 preset**——**不是"你指定子 agent 用某个 preset"**。
> **出处**：`subagent/src/child-agent.ts:145`（逐字）——`const agentPreset = parent.ctx.get('agentPresets')?.composedPreset(parent.ctx)`
> **想给子 agent 不同人设** → **用 `tool-subagent` 的 `persona` config**（"Per-child persona"）。

**在 preset 里，给委派工具配一个不同的人设**：

**`agent.cordis.yml`**：
```yaml
# 主 agent 人设
- id: persona
  name: '@deepseek-ai/dsh-persona'
  config:
    prefix: 你是总协调者。收到任务后，用 subagent 委派出去，再汇总。

# 委派工具：给子 agent 换人设（子 agent 变成"审查员"）
- id: subagent-reviewer
  name: '@deepseek-ai/dsh-tool-subagent'
  config:
    provider: spawn
    toolName: subagent_review        # 模型看到的工具名
    persona: |-
      你是代码审查子 agent。收到代码后，只输出 JSON：
      {"issues": [{"file": "...", "line": 0, "severity": "high|mid|low", "suggestion": "..."}]}
```

> **出处**：`tool-subagent/src/index.ts:48-110`（`Config`）——`persona`：*"Per-child persona that shadows `deployment:persona-prefix`. Requires the provider's `persona` capability."*

**效果**：主 agent 调 `subagent_review` → **起一个"审查员人设"的子 agent**（不是继承主 agent 的人设）。

**▶ 怎么跑 + 看什么**：
```sh
cd ~/ai-work/dsh/dsh-learn/example/deepwater/presets
./start.sh
```
→ UI 选「**带子代理的协调者**」→ 发"审查下 `function f(){}` 这段代码" → **看它是否调 `subagent_review`、且子 agent 按 JSON 输出**。

> **⚠️ 注意**：`persona` **需要 provider 支持 `persona` capability**（`spawn` 是否支持待验证）；不支持会**明确报错**（不静默忽略）。

### 相关的配置（`tool-subagent` 的 `Config`）

| 字段 | 作用 |
|---|---|
| `provider` | 用哪个提供方（`spawn`/`fork`/…） |
| `toolName` | **模型看到的工具名**（如 `subagent` / `subagent_fork`） |
| **`persona`** | **给子 agent 换人设** |
| `toolFilter` | 给子 agent 限工具（`allow`/`deny`） |
| `maxDepth` | 委派深度（默认 3；**`0` 禁止委派**） |

> **出处**：`tool-subagent/src/index.ts:48-110`

> **💡 回扣 04 篇**：`standard` preset 就是**挂多个 `tool-subagent` 实例**（`subagent` + `subagent_fork`），不同 `provider`/`toolName`。

## 八、怎么创建？两种方式

### 方式 A：手动建文件（照上面抄）

```sh
mkdir -p example/deepwater/presets/<id>
# 写 preset.yml + agent.cordis.yml
```

### 方式 B：⭐ 让官方 `cordis` preset 帮你（推荐）

**`cordis` preset = "创造模式"**——**专门用来创建 preset**：

> **出处**：`presets/cordis/preset.yml`（逐字）——*"用于创建自定义 Agent preset：具备标准模式的全部能力，并提供运行时检查、插件实验和 preset 创作指导。"*

**用法**：
1. 起 dsh，**选「创造模式」preset**
2. 跟它说："帮我建一个 XX 的 preset"
3. 它**会帮你写**（它有 `editing-cordis-compositions` skill + 创作指导）

> **⚠️ 前提**：`cordis` preset 的 persona 逐字说——*"Load the `editing-cordis-compositions` skill before writing or changing a composition."*

**官方推荐的"复制法"**（逐字）：
> *"To change what a shipped preset does, **copy its composition into a new preset directory and edit the copy**."*

## 一页纸总结

| 概念 | 要点 | 出处 |
|---|---|---|
| **结构** | 2 文件：preset.yml + agent.cordis.yml | `discovery` |
| **位置** | ⭐ **工程内**（配 `roots`）；或 `~/.dsh/.agent-presets/<id>/` | `agent-presets:181` |
| **创作法** | **复制内置 preset → 改副本** | `cordis` persona |
| **`agent.cordis.yml`** | patch 列表（可加/删/禁工具） | 03 篇 |
| **让 AI 帮写** | 用 **`cordis` preset**（创造模式） | `cordis/preset.yml` |
| **别改内置** | 升级会覆盖；改内置=破坏该模式 | `cordis` persona |

## 踩坑预防

- **⚠️ 别直接改内置 preset**：升级会覆盖；`cordis` preset persona 逐字警告。（出处：`cordis` persona）
- **⚠️ 复制后记得改 `preset.yml` 的 name**：否则显示"复制来的名字"。（出处：`metadata`）
- **⚠️ `complete: true` 慎用**：砍工具用法说明（04.3）。（出处：04.3）
- **⚠️ 未实测**：本篇例子**基于源码机制**，**未逐个实跑**——建议从"例子 1"开始验证。（出处：诚实标注）
