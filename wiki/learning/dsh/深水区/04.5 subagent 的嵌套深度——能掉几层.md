# 04.5 subagent 的嵌套深度——能掉几层

> [!info] 版本锚点
> - 源码：`~/ai-work/dsh/deepseek-harness/`（master `0d1f50007f`）
> - 前置：**04 篇（subagent）**、**04.1~04.4（agent preset）**
> - 写法说明：本系列采用**完整重讲式**；**嵌套已实测**

> [!abstract] 本章是什么 / 该记住什么
> **问题**：**subagent 能不能"继续调 subagent"？能掉几层？能不能改？**
> **读完该记住 3 点**：
> 1. **能嵌套**（递归委派）——**默认 `maxDepth = 3`**（= root + 3 代后代）
> 2. **可改**——`maxDepth` 是**任意非负安全整数**（0 ~ 2^53-1）；`0`=禁止委派
> 3. **超限报错**：`subagent depth N exceeds maxDepth 3`

## 这一篇在讲什么

04 篇你知道 subagent 能"委派"。**但委派出去的子 agent，能不能再委派？**——**能**（递归），**但有层数上限**。

> **一句话**：**subagent 能嵌套，默认 3 层，可改。**

---

## 一、能嵌套吗？——**能**（递归委派）

**子 agent 的工具集里【有】subagent 工具**——**它能再起 subagent**。

**实测验证**（本人，`maxDepth=5`）：
```
我（第 0 层）
 └─ 子 agent（第 1 层）        ← 我用 subagent 创建
     └─ 孙 agent（第 2 层）    ← 子 agent 用 subagent 创建
跨层的 subagent 工具可用，链条没断，无报错。
```

> **出处**：本人实测（2026-09-16）

## 二、⭐ 能掉几层？——**默认 3**

### 深度定义

> **出处**：Agent Note `2026-07-12-subagent-persona-tool-filter-and-depth.zh.md:54`（逐字）——*"顶层 agent 深度为零；**进程内子 agent 的深度为其父级已验证深度加一**。`maxDepth` 是一个绝对的非负安全整数，当推导出的子 agent 深度**大于上限时，启动在子 agent 所有权开始之前即被拒绝**。"*

**即**：`depth(子) = depth(父) + 1`。

### `maxDepth` 默认 `3`

> **出处**：`tool-subagent/src/index.ts:129`（逐字）——`maxDepth: ...default(3)`
> **出处**：Agent Note `:58`（逐字）——*"经 loader 解析的 `dsh-tool-subagent` 配置则**默认值为 `3`**…**三是一个较小的有限默认值，仍允许 root 加三代后代**，base profile 采用这项通用策略。"*

**所以默认能掉 3 层**：
```
depth 0：顶层 agent（root）
  └─ depth 1：子 agent       ✅
      └─ depth 2：孙 agent    ✅
          └─ depth 3：曾孙    ✅
              └─ depth 4：❌ 【超过 maxDepth=3 → 拒绝】
```

> **超限报错**（逐字）：`subagent depth ${attemptedDepth} exceeds maxDepth ${maxDepth}`（`depth.ts`）

## 三、⭐ 能改吗？——**能（嵌套更多层）**

### `maxDepth` 的合法值

> **出处**：`tool-subagent/src/index.ts:129`（逐字）——`z.union([z.natural().max(Number.MAX_SAFE_INTEGER), z.const('provider-managed')])`

| 值 | 含义 |
|---|---|
| **非负安全整数**（`0` ~ `2^53-1`） | **自定义上限** |
| **`0`** | **禁止委派**（`0` forbids delegation entirely） |
| **`'provider-managed'`** | 交给**进程外提供方**管（`:102`） |
| **不写** | **默认 `3`** |

**校验规则**（`assertSubagentMaxDepth`，`depth.ts:42`）：必须是"非负安全整数"——**负值/小数/负零/非有限/非安全整数都拒绝**。

### 怎么改（patch 示例）

```yaml
# example/deepwater/subagent-depth-demo/depth-5.patch.yml
- id: tool-subagent
  config:
    provider: spawn
    toolName: subagent
    backgroundMode: continuable
    maxDepth: 5          # ← 改成 5（嵌套到第 5 层）
```

**实测**：改成 `5` 后，**嵌套 2 层跑通**（本人）。

## 四、深度是"绝对树上限"（几个要点）

> **出处**：Agent Note `:52/56/60`（逐字）

| 点 | 说明 |
|---|---|
| **独立于工具可见性** | *"深度限制**独立于工具可见性**来约束递归委派"* |
| **持久化** | *"进程内子 agent 把推导出的深度记录在会话 header 中，**恢复时会重新载入**，因此**重启无法降低递归计数**"* |
| **有效深度 = max(header, runtime)** | `delegationDepthOf = Math.max(header.delegationDepth, options.subagentDepth)`（`depth.ts:35`） |
| **⚠️ 工具仍可见** | *"委派工具在上限处**仍然可见**…**每次尝试启动都会检查**调用方深度，被拒绝的启动返回错误工具结果"*——**超层的 subagent 还能看到 subagent 工具，但一起就报错** |
| **数值上限不合成过滤器** | *"数值上限**不会合成过滤器**"*——想"固定不委派"，要**另外 deny 委派工具** |

## 五、对比 Claude Code

| | **dsh subagent** | **CC subagent** |
|---|---|---|
| **嵌套** | ✅ 能（默认 3 层） | ✅ 能（**最多 5 层**） |
| **可配** | ✅ `maxDepth` | ✅（CC 有嵌套层数上限） |

**⚠️ 注意区分**：**CC 的 agent-team 里 teammate 不能嵌套**（"No nested teams"）；但 **CC 的 subagent 能嵌套（最多 5 层）**。**dsh 的 subagent 也是"能嵌套、有上限"。**

## 一页纸总结

| 概念 | 一句话 | 出处 |
|---|---|---|
| **能嵌套** | subagent 能再调 subagent | 实测 |
| **深度定义** | `depth(子) = depth(父) + 1`；顶层 = 0 | Agent Note `:54` |
| **默认 maxDepth** | **`3`**（root + 3 代） | `tool-subagent:129` |
| **可改** | 非负安全整数（0~2^53-1）/ `'provider-managed'` | `tool-subagent:129` |
| **`0`** | 禁止委派 | Agent Note |
| **超限报错** | `subagent depth N exceeds maxDepth` | `depth.ts` |
| **持久化** | 深度记在 session header，重启不降 | Agent Note `:56` |
| **有效深度** | `max(header.delegationDepth, runtime.subagentDepth)` | `depth.ts:35` |

## 踩坑预防

- **⚠️ 默认只能 3 层**——要更深，**配 `maxDepth`**。（出处：`tool-subagent:129`）
- **⚠️ 深度"重启不降"**——写了 header，重启后仍算数。（出处：Agent Note `:56`）
- **⚠️ 超层的 subagent 仍看到 subagent 工具**——但一起就报错（不是"工具消失"）。（出处：Agent Note `:60`）
- **⚠️ 想"固定不委派"，要 `maxDepth:0` + 另外 deny 工具**——数值上限不自动合成过滤。（出处：Agent Note `:60`）
- **⚠️ 可配，但别乱调大**——嵌套多了，**token 成本指数增长**（每个子 agent 独立 context）。
