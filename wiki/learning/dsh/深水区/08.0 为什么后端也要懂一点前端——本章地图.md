# 08.0 为什么后端也要懂一点前端——本章地图

> [!info] 版本锚点
> - 源码：`~/ai-work/dsh/deepseek-harness/`（master `0d1f50007f`）；全局包 `dsh 0.1.5-rc.1`
> - 前置：无（这是"Web UI"整块的**起点**）
> - **本篇的对象**：**没写过前端的后端工程师**。全程用 Go 类比。

> [!abstract] 这一章是给谁写的 / 为什么这么排
> **你**：资深 Go 后端，TS 零基础，前端的印象大概是"一堆 div"。
> **问题**：dsh 是个"什么都能插件化"的框架——**它的界面本身也是插件拼出来的**。你如果不懂"界面是什么、插件怎么往界面上加东西"，那 dsh 最核心的一块你就永远是黑盒。
> **但**：你**不需要成为前端**。你只需要**看懂 + 会改** dsh 的 UI。
> **所以本章的排法是**：**先补最小前端地基（08.1~08.3），再进 dsh（08.4~08.6）**。**顺序不能反**——不知道 React 是什么，直接看 dsh 的 slot 系统，只会一头雾水（这是我第一版写砸的教训）。

## 老实话：我第一版写砸了

我第一版本章一上来就是"dsh 前端三层架构 / slot 四份额 / uSES 桥 / NoInfer 类型裁定"——**那是"给已经懂前端的人做架构 review"，不是"教后端学前端"**。

**错在哪**：
- **起点错了**：拿"dsh 内部实现"当第一节，等于让一个没学过微积分的人直接看偏微分方程。
- **假设错了**：默认你懂"组件 / props / 渲染 / hooks"——**这些全是前端行话**，你当然不懂。
- **顺序反了**：违反 `AGENTS.md` 铁律"**先理论后实践、由浅入深**"。

**重写后**：把"dsh 内部机制"**挪到本章最后**（08.6 进阶），前面全是**补地基**。

## 一个"后端视角"的类比总纲（先立个锚）

**整个前端世界，你可以先这样粗暴地映射到后端概念**（后面几节会逐个展开、纠正）：

| 前端概念 | 后端类比（先这么记，后面纠偏） | 8.x 哪节细讲 |
| --- | --- | --- |
| 浏览器 | 一个**长期运行的客户端进程**（像你的 CLI 工具，但带图形界面） | 08.1 |
| HTML | 进程里**对象的序列化结构**（树） | 08.1 |
| CSS | 给这棵树**上样式**的规则表（像模板/主题） | 08.1 |
| JavaScript | 客户端进程里跑的**脚本语言** | 08.2 |
| TypeScript | JS + **编译期类型**（≈ Go 的类型） | 08.2 |
| React 组件 | 一个**纯函数**：输入 props，输出界面描述 | 08.3 |
| 渲染 | 把"界面描述"**应用到屏幕**（≈ 把 struct 序列化出去） | 08.3 |
| dsh slot | 界面上的**扩展点 / 插件挂载位**（≈ 你熟悉的 hook 点） | 08.4 |
| dsh client 插件 | 一个**在浏览器里跑的插件**（≈ 你写的后端插件，只是跑在浏览器） | 08.4 |

> **⚠️ 别较真**：这张表是**脚手架**，不是定义。后面每一节都会**纠正**其中的不准确处。它的用处是：让你**读第一节时不至于完全悬空**。
