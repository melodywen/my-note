# 08.2 JS / TS 速成（Go 视角）——只讲读 dsh 必须懂的那部分

> [!info] 版本锚点
> - 源码：`~/ai-work/dsh/deepseek-harness/`（master `0d1f50007f`）；全局包 `dsh 0.1.5-rc.1`
> - 前置：**08.1（前端是什么）**
> - 本篇对象：**TS 零基础的后端**——**不教完整 TS**，只教"读 dsh 前端代码够用"的最小集

> [!abstract] 读完该记住 6 点
> 1. **JS 是弱类型脚本语言**；**TS = JS + 编译期类型**（≈ Go 的类型，但**只在编译期存在**）
> 2. **模块**：`import` / `export`——≈ Go 的 `import` + 大写导出
> 3. **类型**：`type` / `interface`——≈ Go 的 `type` / `struct` 定义
> 4. **异步**：`async` / `await` / `Promise`——≈ Go 的 goroutine + channel 的**简化版**
> 5. **`?.` 和 `??`**——空值处理，Go 里你得写一堆 `if x != nil`
> 6. **JSX**（`.tsx` 里的 `<div>`）——**不是 HTML，是"生成界面对象的语法糖"**

## 这一篇在讲什么

08.1 你知道了"前端是跑在浏览器里的程序"。**那这个程序用什么语言写？** —— **JavaScript（JS）**，实际工程里写 **TypeScript（TS）**。

**你不需要学会写 TS**。你只需要**看懂 dsh 的前端代码**。所以本篇**只挑"读 dsh 必须懂"的语法**，每条都配 dsh 真实代码 + Go 类比。

---

## 一、TS vs JS：一句话说清

|         | JavaScript (JS)    | TypeScript (TS)    |
| ------- | ------------------ | ------------------ |
| 类型      | **弱类型**（变量可以随便换类型） | **有类型**，但**只在编译期** |
| 运行      | 浏览器直接跑             | **先编译成 JS** 再跑     |
| 后缀      | `.js`              | `.ts`、`.tsx`       |
| dsh 用哪个 | 编译产物               | **源码都是 TS** ✅      |

> **Go 类比**：
> - **JS ≈ 没有类型检查的 Go**（想象所有变量都是 `interface{}`）
> - **TS ≈ 有类型检查的 Go**——但你得记住**一条关键差异**：

> [!warning] 最重要的差异：TS 的类型"编译完就没了"
> **Go**：类型信息**编译进二进制**，运行时还在（反射能用）。
> **TS**：类型**编译时检查完就擦除**，运行时**一点类型都不剩**——最终跑的就是纯 JS。
>
> **后果**：TS 的类型是**给开发者看的护栏**，**不是运行时保障**。所以 dsh 代码里**大量类型检查是"编译期"的**（还记得 08.0 提到的"编译期收口"吗）。**运行时校验必须另外写**。

## 二、模块：`import` / `export`

先看 **dsh 真实代码**（`packages/client/ui-sidebar/src/client/index.ts` 头部，逐字）：

```ts
import type { Context as ClientContext } from '@deepseek-ai/cordis'
import { createSnapshotStore } from '@deepseek-ai/dsh-client-store'
import { resolveSlotLabel } from '@deepseek-ai/dsh-client-ui-slots'
import type { SidebarPanelMetadata, SidebarRootInjected } from './contract/slots.ts'
import { SidebarRoot } from './SidebarRoot.tsx'
import { en, zh, type SidebarKey } from './locales.ts'
```

**逐条读**：

| TS 写法 | 含义 | Go 类比 |
| --- | --- | --- |
| `import { X } from 'pkg'` | 从 pkg **导入具名** `X` | `import "pkg"` 后用 `pkg.X` |
| `import { X as Y }` | 导入并**改名** | `import y "pkg"`（重命名包） |
| `import type { X } from 'pkg'` | **只导入类型**（编译后消失） | 无直接对应；相当于"只为编译期" |
| `from './contract/slots.ts'` | 从**相对路径**导入（`./` 是当前目录） | 本地包 / 相对 import |
| `from '@deepseek-ai/cordis'` | 从**依赖包**导入 | 第三方 module |

**导出**（同一文件）：

```ts
export function apply(ctx: ClientContext): void { ... }   // 导出函数
export const inject = ['slots']                            // 导出常量
export type { SidebarKey } from './locales.ts'            // 转导出类型
```

> **Go 类比**：
> - `export` ≈ **Go 的大写导出**（`Apply` 是大写 = 公开；`apply` 小写 = 私有）
> - **JS 没有"大写=公开"的约定**，靠 `export` 关键字显式导出
> - `export type { ... }` ≈ 只是"把类型再暴露出去"，理解成 re-export 即可

> **⚠️ 你会看到的怪东西**：dsh 里有一批**只有类型、没有值**的 import，像这样：
> ```ts
> import type {} from '@deepseek-ai/dsh-client-ui-renderer/client'
> ```
> **导入了一个空对象 `{}`？** —— 这是"**只为触发类型合并**"（让 `ctx.slots` 这个类型在编译期存在）。**运行时什么都没导入**。你在 dsh 前端代码里会反复看到这个模式，**知道它"是给编译器看的、不产生运行时代码"即可**。

## 三、类型：`type` 和 `interface`

**dsh 真实代码**（`packages/client/ui-sidebar/src/client/contract/slots.ts` 逐字）：

```ts
export interface SidebarBrandMarkOwnerProps {
  size: number          // 请求的方形边长（像素）
}
```

**读法**：定义了一个"结构"——**有个 `size` 字段，是数字**。

**类型别名**（`type`）：

```ts
type MainPanelId = 'chat' | 'trajectory' | 'settings'
```

**读法**：`MainPanelId` 只能是这三个字符串之一（**联合类型**）。

> **Go 类比**：

| TS | Go |
| --- | --- |
| `interface Foo { size: number }` | `type Foo struct { Size int }` |
| `type Id = 'a' \| 'b'` | `type Id string` + 常量约束（Go 没有原生联合类型，得自己校验） |
| `string` / `number` / `boolean` | `string` / `int` / `bool` |
| `X \| null` | `*X`（可能为 nil） |

**dsh 里最常见的类型用法**——**在对象字面量上标注类型**（就是那个 "slot 声明"）：

```ts
'sidebar.brand.mark': { kind: 'single'; scope: 'root'; owner: SidebarBrandMarkOwnerProps }
```

**读法**：键 `'sidebar.brand.mark'` 对应的值，是个对象，有三个字段：`kind='single'`、`scope='root'`、`owner=某个类型`。

> **Go 类比**：像**一个 map 的声明**：
> ```go
> map[string]SlotSpec{
>     "sidebar.brand.mark": {Kind: "single", Scope: "root"},
> }
> ```

> **⚠️ 注意 `;` 和 `,`**：TS 对象里字段用 **`;` 或 `,`** 都行（这里用了 `;`）。**你读代码时别被这个迷惑**。

## 四、函数与箭头函数

**dsh 真实代码**（`ui-brand-official/src/client/index.ts` 逐字）：

```ts
export function apply(ctx: ClientContext): void {
  ctx.slots.inject('sidebar.brand.mark', () =>
    ctx.slots.inject('sidebar.brand.name', function* () {
      yield ctx.slots.register({ name: 'sidebar.brand.mark' }, OfficialBrandMark)
    }))
}
```

**三种函数写法**：

| 写法 | 例子 | Go 类比 |
| --- | --- | --- |
| 普通函数 | `function apply(ctx) {...}` | `func Apply(ctx ...) {...}` |
| **箭头函数** | `(x) => x + 1` | **匿名函数** `func(x int) int { return x+1 }` |
| **生成器** `function*` | `function* () { yield ... }` | **`yield return` 的协程**（Go 没有，≈ channel 的产者模式） |

**逐条读上面那段**：

- `apply(ctx: ClientContext): void` → 一个函数，收 `ctx`，**返回 `void`（无返回值）** ← Go 里没有返回值就省略，TS 要显式写 `: void`
- `() => ...` → **箭头函数**，**空参数**，返回箭头后面的东西
- `function* () { yield ... }` → **生成器**——**调用一次产出一个值**（这里每次产出一个注册动作）

> **Go 类比**：
> - 箭头函数 `(x) => expr` ≈ `func(x T) T { return expr }`（**但 JS 里函数是"一等公民"，可以随便传来传去**——Go 也可以，但 JS 更普遍）
> - 生成器 `function*` ≈ **Go 的 `chan` 产者**：
>   ```go
>   func gen() <-chan Reg {
>       ch := make(chan Reg)
>       go func() { defer close(ch); ch <- regA; ch <- regB }()
>       return ch
>   }
>   ```
>   JS 的 `yield` 就像"往 channel 里塞一个值"。**dsh 用生成器来"注册一组东西"**。

## 五、异步：`async` / `await` / `Promise`

这是**后端最需要理解、也最容易懵**的部分。

**dsh 真实代码**（随便找一处异步调用）：

```ts
const session = ctx.sessions.binding(sessionId)?.session
if (session === undefined) {
  throw new Error(`ui-trajectory: session "${sessionId}" is unavailable`)
}
await session.loadOlder()
```

**核心概念**：

| 概念 | 是什么 | Go 类比 |
| --- | --- | --- |
| `Promise<T>` | 一个"**将来会有结果**"的对象 | 有点像 `future` / 带结果的 channel |
| `async` 函数 | 标记这个函数**里面会有异步等待** | 有点像标了"会阻塞"的函数 |
| `await x` | **等** `x` 完成，拿到结果 | `<-ch`（从 channel 取结果，**会阻塞**） |

**逐条读**：

```ts
await session.loadOlder()
```
→ **等** `loadOlder()` 这个异步操作**做完**，再往下走。

> **Go 类比**：
> ```go
> // TS:  await doSomething()
> // Go:  result := <-doSomething()   // 等 channel 出结果
> ```
> **关键差异**：
> - Go 里"**异步**"靠 **goroutine + channel**（你要显式 `go` 开协程）。
> - JS 里"**单线程 + 事件循环**"：`async/await` 让你**像写同步代码一样写异步**，**不需要手动开 goroutine**。
> - JS **只有一个线程**（跑用户代码的那个），**别指望 `await` 能并行跑 CPU 活**——它只是"等 I/O 时不卡住界面"。

> **⚠️ 一个反直觉点**：JS 里调用一个 `async` 函数，**它立刻返回一个 Promise，不等你**。要拿结果必须 `await`（或用 `.then(...)`）。这跟 Go 里"调函数会立刻跑起来"**不一样**。第一次看 dsh 代码时，注意**哪里 `await` 了、哪里漏了**。

## 六、两个"空值处理"神器：`?.` 和 `??`

**dsh 代码里到处都是**（逐字）：

```ts
const session = ctx.sessions.binding(sessionId)?.session
if (session === undefined) { throw ... }
```

```ts
// 另一处
source = { getSnapshot: () => target.getSnapshot() ?? EMPTY_TRAJECTORY_SNAPSHOT }
```

| 写法 | 含义 | Go 里你得写 |
| --- | --- | --- |
| `a?.b`（可选链） | `a` 是 null/undefined 就**停，返回 undefined**，不报错 | `if a == nil { return nil }; return a.B` |
| `a ?? b`（空值合并） | `a` 是 null/undefined 就用 `b` | `if a == nil { a = b }` |

> **Go 类比**：**这就是 Go 里让你写吐的 nil 检查**——JS 用两个符号省掉了：
> ```go
> // Go：三层 nil 检查
> if a != nil { if a.B != nil { use(a.B.C) } }
> // TS：一行
> use(a?.B?.C)
> ```

> **⚠️ 别搞混三个东西**：
> - `??`（空值合并）——**null/undefined** 才触发
> - `||`（逻辑或）——**任何"假值"**（`0`、`''`、`false`、null）都触发 ← **容易踩坑**
> - `? :`（三元）——不是这个，是"条件表达式"

## 七、JSX：`.tsx` 里的 `<div>` 到底是什么

**这是前端最"劝退"的东西**——`.tsx` 里居然能写 HTML：

```tsx
export function HelloButton({ wide }: { wide: boolean }) {
  return (
    <button title="Hello" style={{ color: 'var(--dsw-alias-brand-primary)' }}>
      <span aria-hidden="true">👋</span>
      {wide ? <span>Hello</span> : null}
    </button>
  )
}
```

**它看起来像 HTML，但【不是】HTML**——它是 **JSX**：**一种"生成界面对象"的语法糖**。上面这段**编译后**大概是：

```js
// 概念示意——JSX 编译后变成"函数调用"
react.createElement('button', { title: 'Hello' }, 
  react.createElement('span', {...}, '👋'),
  wide ? react.createElement('span', null, 'Hello') : null
)
```

**所以 JSX 的两条铁律**：

1. **`{}` 里是 JS 表达式**——所以能写 `{wide ? <span>Hello</span> : null}`（三元 + 嵌套 JSX）。
2. **它最终就是一个"描述界面的对象"**——**不是字符串、不是 DOM**。

> **Go 类比**：JSX 像**一个返回"结构体树"的语法糖**：
> ```go
> // 你所熟悉的
> Button{Title: "Hello", Children: []Node{
>     Span{Text: "👋"},
>     If(wide, Span{Text: "Hello"}),
> }}
> ```
> **JSX 就是把上面这个"造对象树"的过程，写成了看起来像 HTML 的形式**。

**几个你会看到的 JSX 细节**：

| 写法 | 含义 |
| --- | --- |
| `<div className="x">` | 注意是 **`className`** 不是 `class`（因为 `class` 是 JS 保留字） |
| `<Comp />` | **大写开头** = 用你定义的组件（不是 HTML 标签） |
| `<div />` | **小写开头** = 原生 HTML 标签 |
| `{/* 注释 */}` | JSX 里的注释 |

> **⚠️ 大小写是关键规则**：`<div>`（小写）是浏览器原生标签；`<HelloButton>`（大写）是**你自己的组件**。**dsh 代码里所有 `<XxxYyy>` 都是组件**。

## 八、自测：你能读懂这段 dsh 代码了吗

```ts
// 出处：简化自 ui-trajectory/src/client/index.ts
export function apply(ctx: Context): void {
  ctx.slots.inject('conversation.view', () => ctx.slots.register({
    name: 'conversation.view',
    id: 'trajectory',
    order: 10,
    children: { 'conversation.trajectory.images': { kind: 'single', scope: 'session' } },
    inject: (sessionId: SessionId): TrajectoryViewInjected => {
      const session = ctx.sessions.binding(sessionId)?.session
      if (session === undefined) throw new Error(`session "${sessionId}" is unavailable`)
      return { /* ... */ }
    },
  }, TrajectoryView))
}
```

**你应该能读出的**（对照本篇）：

1. `export function apply(ctx: Context): void` → 导出一个函数，收 `ctx`，无返回
2. `ctx.slots.inject('...', () => ...)` → 调用 `inject`，**第二个参数是个箭头函数**
3. `ctx.slots.register({...}, TrajectoryView)` → 调用 `register`，传了**一个配置对象**和**一个组件**
4. `sessionId: SessionId` → 参数 `sessionId`，类型 `SessionId`
5. `ctx.sessions.binding(sessionId)?.session` → **可选链**：binding 结果可能为空
6. `if (session === undefined) throw ...` → **手动空值检查**（TS 类型擦除后，运行时得自己查）
7. `(sessionId) => (...)` → 箭头函数，返回一个对象
