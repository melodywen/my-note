# 08.3 React 是什么——够用就好的 30 分钟

> [!info] 版本锚点
> - 源码：`~/ai-work/dsh/deepseek-harness/`（master `0d1f50007f`）；全局包 `dsh 0.1.5-rc.1`
> - 前置：**08.1（前端是什么）** + **08.2（JS/TS 速成）**
> - 本篇对象：**没写过 React 的后端**——只讲到"能读懂 dsh 的组件"为止，**不深入原理**

> [!abstract] 读完该记住 6 点
> 1. **组件 = 一个函数**：输入 `props`，输出"界面描述"（JSX）
> 2. **`props` 是只读输入**——≈ 函数参数
> 3. **`state` 是组件自己的可变数据**——变了会**自动重新渲染**
> 4. **`useState` / `useEffect` / `useStore` 都是"钩子"（hook）**——`use` 开头的特殊函数
> 5. **渲染 = "根据 props + state，重新算出界面"**——React 负责把差异应用到屏幕
> 6. **dsh 的组件收到的是"组合好的 props"**（四份额）——组件**不用自己接线订阅**

## 这一篇在讲什么

08.1 说"页面是 HTML 结构"，08.2 说"用 TS 写、能写 JSX"。**但 JSX 不会自己动**——你点个按钮，界面怎么变？

**React 就是管这个的**：它让你把界面拆成**一个个组件（函数）**，数据一变，**自动重新渲染**。

**你只学 30 分钟的量**：读懂 dsh 的组件、会改。**不学**它的内部原理（那是前端的事）。

---

## 一、组件 = 一个函数

先看 **dsh 最简单的真实组件**（`ui-brand-official/src/client/Brand.tsx` 逐字）：

```tsx
export function OfficialBrandMark({ size }: SidebarBrandMarkOwnerProps) {
  return <FishLogo size={size} />
}
```

**就三件事**：

1. **名字大写**（`OfficialBrandMark`）—— React 组件的约定
2. **收 props**（`{ size }`）—— 从参数里**解构**出 `size`
3. **返回 JSX**（`<FishLogo size={size} />`）—— 输出"界面"

> **Go 类比**：
> ```go
> // React 组件 ≈ 一个"返回界面结构的函数"
> func OfficialBrandMark(p SidebarBrandMarkOwnerProps) Node {
>     return FishLogo{Size: p.Size}
> }
> ```
> **本质就是纯函数**：同样输入 → 同样输出。**没有副作用，不碰外部状态**（这是 React 的核心纪律）。

### 解构语法（你会反复看到）

```tsx
function Foo({ size }: Props) { ... }
```

`{ size }` 是**从对象里"拆"出字段**——等于：

```ts
function Foo(props: Props) {
  const size = props.size   // 等价写法
}
```

> **Go 类比**：Go 没有解构，你得 `p := props; size := p.Size`。JS 的 `{ size }` 就是**简写**。

## 二、props：只读的"输入参数"

```tsx
<FishLogo size={24} />
```

**读法**：渲染 `<FishLogo>` 这个组件，传进去 **`size = 24`**。

**props 的两条铁律**：

1. **只读**——组件**不能改自己的 props**（像函数不能改传入参数）
2. **从父传子**——**数据从上往下流**（父组件给子组件喂数据）

> **Go 类比**：props ≈ **函数参数**（传值）。**单向**：父 → 子，跟函数调用一模一样。

> **⚠️ 你在 dsh 里会看到 `PropsRuntime` / `PropsStore` / `PropsLocale` 这些类型**——它们是"**不同来源的 props**"（08.6 细讲）。**现在你只要知道"它们都是 props"就够**。

## 三、state：组件自己会变的数据（关键）

props 是"外面给的、不能改"。**那组件自己想记点东西怎么办？** —— 用 **`state`**。

看 **dsh 真实组件**（`ui-theme/src/client/AppearanceRow.tsx` 精简）：

```tsx
export function AppearanceRow({ t, setTheme, useStore }: AppearanceRowComponentProps) {
  const preference = useStore(s => s.preference)      // ← 读状态
  return (
    <div>
      {CUBES.map(({ id, labelKey, Icon }) => (
        <button
          key={id}
          onClick={() => { setTheme(id) }}             // ← 点击改状态
        >
          <Icon />
          {t(labelKey)}
        </button>
      ))}
    </div>
  )
}
```

**这个组件的逻辑**：读当前主题偏好 `preference` → 渲染三个按钮 → 点哪个就 `setTheme(id)` → **状态一变，组件自动重新渲染**。

> **Go 类比**：state ≈ 一个**有观察者的字段**。你一改它，**React 自动重新跑这个组件函数**，算出新界面。
> ```go
> // 概念上像：
> type AppearanceRow struct {
>     preference ThemePreference  // "state"
> }
> // 改了 preference → React 自动重新渲染（Go 里你得手动通知）
> ```

**"改了状态 → 自动重渲染" = React 的核心魔法**。你记住这一条，就理解了 React 的 80%。

## 四、钩子（hook）：`use` 开头的特殊函数

你在 dsh 代码里会看到一堆 `use` 开头的函数：

| 钩子 | 干什么 | 你在 dsh 哪见 |
| --- | --- | --- |
| `useState(...)` | 声明一个**本地状态** | 通用 React |
| `useEffect(...)` | **副作用**（组件挂载/卸载时干点事） | 通用 React |
| `useStore(s => ...)` | **从 store 读状态**（dsh 封装） | AppearanceRow |
| `useSession(...)` | 读会话数据（dsh 提供） | 对话相关组件 |

**钩子的两条铁律**（前端面试必考，你只要记住规则）：

1. **只能在组件函数顶层调用**——不能塞进 `if` / 循环里
2. **只能组件里用**——不能普通函数里用

> **Go 类比**：钩子 ≈ **一个"受框架管理的上下文"**——你**声明你要什么**（"我要读 store 的这个字段"），**框架负责把数据接好**。有点像**依赖注入**：你不自己 new，**声明依赖，容器给你**。

> **⚠️ dsh 的特殊之处**：dsh **不让业务代码自己写订阅逻辑**（什么 `subscribe`/`addEventListener`）。**它把数据先绑好，以"钩子"形式喂给组件**。所以 dsh 组件里看到 `useStore(...)`、`useSession(...)`——**这些是框架给的，组件只管用**。（原理在 08.6。）

## 五、渲染：从"数据"到"屏幕"

```
① 你改了 state
       ↓
② React 重新调用组件函数（拿到新的 JSX）
       ↓
③ React 对比"新界面"和"旧界面"的差异
       ↓
④ 只把差异应用到真实屏幕（高效）
```

**关键认知**：

- **组件函数会被反复调用**——每次数据变，就重新跑。（所以组件**必须是纯函数**，不能有副作用。）
- **JSX 不是 DOM**——它是"**描述**"，React 负责把描述**变成真正的页面**。
- **第 ③ 步"对比差异"由 React 自己做**——**你不用手动操作 DOM**（这是 React 相对"手写 JS 操作 DOM"的最大价值）。

> **Go 类比**：
> - 你写后端"**声明期望状态**"（比如 k8s 的 `replicas: 3`），**控制器**负责把现实变成期望。
> - **React 就是"界面的控制器"**：你声明"界面应该长这样"，**它负责把屏幕调成那样**。

## 六、`map`：把数组渲染成一堆元素

你会反复看到 `.map(...)`：

```tsx
{CUBES.map(({ id, labelKey, Icon }) => (
  <button key={id} onClick={() => setTheme(id)}>
    <Icon />{t(labelKey)}
  </button>
))}
```

**读法**：把数组 `CUBES` 里每一项，**变一个 `<button>`**，组成一串按钮。

> **Go 类比**：
> ```go
> // 概念上像
> for _, c := range CUBES {
>     buttons = append(buttons, Button{ID: c.ID})
> }
> ```
> JS 的 `.map` ≈ **Go 的 `for` 循环 + append**（把每个元素映射成新元素）。

> **⚠️ `key={id}` 是什么**：给每个元素一个**稳定身份**，React 靠它**高效地增删改**（不然会认错元素）。**规则**：列表里每个元素都要 `key`，且**用稳定唯一值**（别用数组下标）。

## 七、条件渲染：`&&` 和三元

```tsx
{wide ? <span>Hello</span> : null}     // 三元：wide 为真显示，否则不显示
{isLoading && <Spinner />}             // &&：isLoading 为真才显示
```

> **Go 类比**：
> ```go
> // 三元 ≈
> if wide { return Span{Text:"Hello"} } ; return nil
> // && ≈
> if isLoading { return Spinner{} }
> ```

## 八、把一篇 dsh 组件彻底读懂（综合演练）

回到 `AppearanceRow`（逐行）：

```tsx
export function AppearanceRow({ t, setTheme, useStore }: AppearanceRowComponentProps) {
  const preference = useStore(s => s.preference)
  return (
    <div className={css.group}>
      <div className={css.title}>{t('appearance.title')}</div>
      <div className={css.cubeRow}>
        {CUBES.map(({ id, labelKey, Icon }) => (
          <button
            key={id}
            type="button"
            className={clsx(css.themeCube, preference === id && css.selected)}
            aria-pressed={preference === id}
            onClick={() => { setTheme(id) }}
          >
            <Icon />
            {t(labelKey)}
          </button>
        ))}
      </div>
    </div>
  )
}
```

**逐行翻译**：

| 行 | 读法 | 你已学的 |
| --- | --- | --- |
| `({ t, setTheme, useStore })` | 从 props 解构出三个东西 | props + 解构 |
| `useStore(s => s.preference)` | 读 store 里的 `preference` | 钩子 + state |
| `<div className={css.group}>` | 一个盒子，样式来自 CSS 模块 | CSS（08.1） |
| `{t('appearance.title')}` | 调 `t` 翻译，`{}` 里是表达式 | JSX `{}` |
| `CUBES.map(...)` | 数组 → 按钮列表 | map |
| `key={id}` | 列表身份 | key |
| `clsx(a, cond && b)` | 拼类名（条件加 `selected`） | 条件渲染 |
| `preference === id && css.selected` | 选中就加样式类 | `&&` |
| `onClick={() => setTheme(id)}` | 点击回调 | 事件 + 箭头函数 |
| `<Icon />` | 渲染图标组件 | 组件（大写） |

**读懂了这一整段 → 你就能读懂 dsh 的绝大多数组件了。**

## 九、自测

1. React 组件是什么？（→ 一个收 props、返回 JSX 的函数）
2. props 和 state 的区别？（→ props 外面给的、只读；state 自己管的、可变，变了会自动重渲染）
3. 为什么列表元素要 `key`？（→ 给 React 稳定身份，高效增删改）
4. `<div>` 和 `<Div>` 有什么区别？（→ 小写原生标签；大写自定义组件）
