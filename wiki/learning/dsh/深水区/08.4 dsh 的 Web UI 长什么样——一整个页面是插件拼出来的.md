# 08.4 dsh 的 Web UI 长什么样——一整个页面是"插件拼"出来的

> [!info] 版本锚点
> - 源码：`~/ai-work/dsh/deepseek-harness/`（master `0d1f50007f`）；全局包 `dsh 0.1.5-rc.1`
> - 前置：**08.1~08.3**（前端是什么 / TS / React）。**到这里你已经有地基了。**
> - 本篇对象：**刚补完前端基础的后端**——"现在来看 dsh 的界面到底怎么回事"

> [!abstract] 读完该记住 6 点
> 1. **dsh 的网页 = 一堆插件"拼"出来的**——不是一个大 React 应用写死的
> 2. **页面骨架只有一个根**：`root` 槽；谁渲染它，谁就掌握整个布局
> 3. **一个 UI 插件 = 一个 npm 包**（在 `packages/client/ui-*`）——**≈ 你写的一个后端插件**
> 4. **拼装靠"扩展点"（slot）**：每个插件声明"我要占哪个槽 / 我能往外露哪些槽"
> 5. **主界面是三栏**：`sidebar | center | rightbar`（`ui-layout` 定义）
> 6. **dsh 自带约 39 个 client-ui 插件**——它们负责你能看到的每一块界面

## 这一篇在讲什么

前三节讲的是**通用前端**。**这一节开始，专门看 dsh**。

**核心问题**：dsh 那个网页，是谁做出来的？

**答案**：**没有"一个前端大项目"**。dsh 的网页是**几十个小插件，各自往"扩展点"上挂东西，最后拼出来**。

> **Go 类比**：这跟 **dsh 后端"一切皆插件"是同一个哲学**——**界面也是**。
> - 后端：`ctx.tools.register(...)` 挂一个工具
> - 前端：`ctx.slots.register(...)` **挂一块界面**
> **同一个 `register` 思路**，只是注册的对象从"工具"变成了"界面组件"。

---

## 一、先破除误解：不是"一个大 React 应用"

**传统前端项目**长这样：

```
一个大项目
└── src/
    ├── App.tsx          ← 顶层组件，写死所有布局
    ├── Header.tsx
    ├── Sidebar.tsx      ← 都是这一个项目里的文件
    └── Chat.tsx
```

**dsh 不是这样**。dsh 是：

```
一个"外壳"（shell）+ 几十个独立插件
├── ui-layout       插件  → 定义三栏骨架
├── ui-sidebar      插件  → 左侧栏
├── ui-chat         插件  → 对话区
├── ui-settings     插件  → 设置页
├── ui-tool         插件  → 工具调用卡片
├── ui-trajectory   插件  → 轨迹视图
└── ...（共约 39 个）
```

**每个都是独立的包**，可以**各自装载/卸载**。

> **出处**：`packages/client/web/README.zh.md` 相关段落 + `dsh-web-app` 的 `cordis.patch.yml`（`dsh-client-ui` 行数 `grep` 实测 = **39**）

> **Go 类比**：**更像你做后端微服务的方式**——不是一个巨型单体，而是**一堆小服务，各自注册到总线上**。

---

## 二、拼装的核心：一个根 + 一堆扩展点

**dsh 的界面拼装，只有一条主线**：

```
① 页面启动
      ↓
② 渲染器渲染唯一的根槽：renderSlot('root')
      ↓
③ 某个插件（ui-layout）占了 root，摆出三栏骨架
      ↓
④ ui-layout 的三栏里，又声明了子槽：sidebar / main / rightbar
      ↓
⑤ 别的插件分别往这些子槽里挂自己的界面
      ↓
⑥ 递归下去…… 最终拼成整个页面
```

**关键概念——"槽（slot）"**：**就是界面上的一个"洞"**，等插件来填。

> **Go 类比**：**slot ≈ 一个注册点 / hook 点**。像你后端里：
> ```go
> // 你熟悉的"注册点"
> ctx.OnToolCall.Register(handler)
>
> // dsh 前端的"注册点"
> ctx.slots.register({ name: 'sidebar.footer.action' }, MyButton)
> ```
> 想法一模一样：**"我在这里留个挂钩，谁感兴趣谁挂上来"**。

> **⚠️ 别急着深究 slot 细节**：**slot 的完整机制（四种类型、优先级、props 四份额）放在 08.6**。这一节你只要建立**"界面 = 根 + 槽 + 插件填充"**这个直觉。

---

## 三、页面骨架：三栏

dsh 的主界面是**三栏**，由 **`ui-layout` 插件**定义：

```
┌─────────────┬─────────────────────────┬──────────────┐
│   sidebar   │         center          │   rightbar   │
│   左侧栏     │         中间主区          │    右侧栏     │
│             │                         │              │
│ 工作区/会话   │   对话 / 各种主面板        │  详情/预览    │
└─────────────┴─────────────────────────┴──────────────┘
```

**dsh 真实代码**（`packages/client/ui-layout/src/client/AppFrame.tsx` 逐字注释）：

> *"Three-column shell frame, registered into the built-in `'root'` slot (the web shell renders only `'root'`). Owns the grid tracks (**sidebar | center | rightbar**), the drag handles …… and the child-slot render decisions"*

**读法**：

- `ui-layout` **占了 `root` 槽** → 它掌握整个布局
- 它**声明了三个子槽**：`sidebar` / `main` / `rightbar`
- 它负责**画三栏的格子 + 拖拽把手**
- **每一栏里装什么，它不管**——留给别的插件

```tsx
// 出处：AppFrame.tsx:30（它声明自己能渲染这些子槽）
& PropsRenderSlots<'sidebar' | 'main' | 'rightbar' | 'shell.overlay'>
```

**翻译**：这个组件**有权力往 sidebar / main / rightbar / overlay 这四个槽里渲染**。

> **Go 类比**：像**一个框架的"路由骨架"**——框架定好"有哪几个位置（slot）"，**具体每个位置放什么，由业务插件决定**。

## 四、"一个 UI 插件"是什么样

看**最典型的一个**——`ui-sidebar`（左侧栏插件）：

```
packages/client/ui-sidebar/
├── package.json          ← 声明：这是个 client 插件（dsh.client 字段）
├── src/
│   ├── index.ts          ← node 半边（占位）
│   └── client/
│       ├── index.ts              ← 浏览器半边入口（apply 函数）
│       ├── SidebarRoot.tsx       ← 左栏的界面（React 组件）
│       ├── SidebarRoot.module.css← 左栏的样式
│       └── contract/slots.ts     ← 声明"左栏里有哪些子槽"
```

**跟你写后端插件对比**：

| | 后端插件（你熟） | dsh UI 插件 |
| --- | --- | --- |
| 包 | 一个 npm 包 | 一个 npm 包 ✅ |
| 入口 | `apply(ctx)` | `apply(ctx)` ✅ |
| 注册 | `ctx.tools.register(...)` | `ctx.slots.register(...)` |
| "干活的东西" | 一个工具函数 | **一个 React 组件** |
| 跑在哪 | 服务器 | **浏览器** ← 唯一区别 |

**看到没**：**结构几乎一样**。你会写后端插件，**就会写 UI 插件的骨架**——只差"组件怎么写"（08.3 学过了）。

## 五、`contract/slots.ts`：插件的"扩展点说明书"

每个 UI 插件会**声明自己提供哪些槽**。看 `ui-sidebar` 的（逐字）：

```ts
// 出处：packages/client/ui-sidebar/src/client/contract/slots.ts:22-50
'sidebar.brand.mark':   { kind: 'single'; scope: 'root'; owner: SidebarBrandMarkOwnerProps }
'sidebar.brand.name':   { kind: 'single'; scope: 'root'; owner: SidebarBrandNameOwnerProps }
'sidebar.panellist':    { kind: 'list';   scope: 'root'; owner: SidebarPanelIconOwnerProps }
'sidebar.workspaces':   { kind: 'single'; scope: 'root'; owner: SidebarSectionOwnerProps }
'sidebar.footer.action':{ kind: 'list';   scope: 'root'; owner: SidebarFooterActionOwnerProps }
```

**读法**（对照 08.2 的 TS + 08.3 的组件）：

- **`'sidebar.brand.mark'`** → 槽的名字（点分命名，像命名空间）
- **`kind: 'single'`** → 这槽**只能有一个**占位者
- **`kind: 'list'`** → 这槽**可以有多个**（按序排列）
- **`owner: ...OwnerProps`** → **占这个槽的组件，会收到什么样的 props**

> **Go 类比**：像**接口定义**——"我这儿有个位置，规矩是这样的，谁想填就按这规矩来"。

**记住两种 kind 就够了**：

| kind | 含义 | 类比 |
| --- | --- | --- |
| `single` | 独占（一个位置一个） | **单例注册** |
| `list` | 可多个（有序） | **中间件链 / 事件监听器列表** |

> **⚠️ 这个细节 08.6 会展开**（还有 `keyed` / `chain` 两种）。**这里先建立"槽有类型"的概念。**

## 六、动手前先"看图"：你眼里的 dsh 界面 → 拆成插件

下次打开 dsh Web UI，你可以**这样拆解**：

```
┌───────────────────────────────────────────────────────┐
│ [顶部] 品牌名 / 新建会话     ← ui-sidebar (brand 槽)     │
├─────────────┬─────────────────────────┬───────────────┤
│ 工作区列表   │   对话内容（消息流）      │   详情面板     │
│ 会话列表     │   ← ui-chat              │   ← rightbar   │
│ ← ui-sidebar │                         │                │
│             │   工具调用卡片 ← ui-tool   │               │
│             │   输入框 ← ui-conversation │               │
│ 底部设置/动作 │                         │                │
│ ← ui-sidebar │   主面板切换 ← ui-plan 等 │               │
└─────────────┴─────────────────────────┴───────────────┘
```

**每一个你能看到的区块，背后都是某个插件**。**你想加东西 → 找到对应的槽 → 注册一个组件**。

## 七、那"我想加个按钮"到底怎么加（预告 08.5 / 08.6）

**三步**（08.6 会完整做一遍）：

```
① 写一个 React 组件（08.3 学的那种）
       ↓
② 找到合适的槽（比如 sidebar.footer.action——一个 list 槽）
       ↓
③ 在 apply 里注册：
   ctx.slots.register({ name: 'sidebar.footer.action', id: 'my-btn' }, MyButton)
```

**就这么简单**。（我实测做过一次——真在左栏底部加出了一个按钮。见 08.6。）

> **⚠️ 一个真实的坑（我踩过）**：
> - 如果你往一个**已被占用的 `single` 槽**里注册，会**装载报错**（"already has a registration"）。
> - 若往 `list` 槽注册，**必须给 `id`**（否则报 "requires options.id"）。
> **这些坑 08.6 会讲清**——现在你只要知道"**加东西要挑对槽**"。
