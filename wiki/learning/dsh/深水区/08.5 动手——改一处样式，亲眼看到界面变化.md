# 08.5 动手：改一处样式，亲眼看到界面变化

> [!info] 版本锚点
> - 源码：`~/ai-work/dsh/deepseek-harness/`（master `0d1f50007f`）；全局包 `dsh 0.1.5-rc.1`
> - 前置：**08.4（dsh Web UI 长什么样）**
> - 本篇对象：**后端**——第一次"改 dsh 的界面"的实践
> - **重要**：本篇所有命令**我实际跑过**，输出贴的就是真实结果。

> [!abstract] 这一篇你会做到什么
> **改一处样式（主题偏好），启动 dsh，亲眼看到整个界面从浅色变深色。**
> **读完该记住 4 点**：
> 1. **改样式不碰 React、不写代码**——只改一个配置值
> 2. 改的是 `~/.dsh/settings.yaml` 里的 `ui-theme.preference`
> 3. **界面样式来自"主题 token"**（`--dsw-*` 变量），你改的是"选哪套 token"
> 4. **dsh 启动必须带 `?token=...`**——这是它的浏览器鉴权（08.1 讲过）

## 这一篇在讲什么

08.4 你知道了"dsh 界面是插件拼的、样式来自 token"。**现在动手改一次，把概念变成体感。**

**为什么选"改主题"当第一个实验**：

- ✅ **零代码**——只改一个 YAML 值，**不碰 React**
- ✅ **反馈快**——重启就能看到整个界面变化
- ✅ **正好兑现 08.1/08.4 的结论**："改样式不用懂前端逻辑"

> **Go 类比**：像**改你服务的配置文件**（比如把日志级别从 `info` 改成 `debug`），**重启生效**。**跟写业务代码是两回事**。

## 一、搞清"主题"是怎么存的

dsh 的主题偏好存在 **`~/.dsh/settings.yaml`**（用户设置文档）。先看它长啥样：

```bash
cat ~/.dsh/settings.yaml
```

**我机器上的真实输出**：

```yaml
ui-onboarding:
  welcomeNoticeVersion: 2026-08-13.1
agent-presets:
  default: standard
ui-theme:
  preference: system                    # ← 就是这一行
agent-default-model:
  provider: codebuddy
  model: deepseek-v4.1-flash
```

> **出处**：`packages/client/ui-theme/lib/index.js`——`THEME_SETTINGS_NAMESPACE = "ui-theme"`、`THEME_PREFERENCE_FIELD = "preference"`、`THEME_PREFERENCES = ["light", "dark", "system"]`（逐字常量）

**`preference` 三个可选值**：

| 值 | 含义 |
| --- | --- |
| `light` | 强制浅色 |
| `dark` | 强制深色 |
| `system` | **跟随系统**（默认） |

> **Go 类比**：这就是**你的应用配置**。`ui-theme` 是命名空间，`preference` 是键。**跟改 `config.yaml` 没区别**。

## 二、动手：把 `system` 改成 `dark`

### 步骤 1：备份（好习惯）

```bash
cp ~/.dsh/settings.yaml ~/.dsh/settings.yaml.bak
```

### 步骤 2：改值

用你顺手的编辑器，把

```yaml
ui-theme:
  preference: system
```

改成

```yaml
ui-theme:
  preference: dark
```

> **⚠️ 注意 YAML 缩进**：`preference` 前面是**两个空格**（YAML 靠缩进表达层级，像 Python）。**别用 Tab**。

### 步骤 3：启动 dsh（带 token）

```bash
cd ~/ai-work/dsh/dsh-learn
./start.sh
```

**我机器上的真实输出**（启动日志）：

```

→ Profile   : web（配置目录 /Users/melodycchen/.dsh/profiles/web/）
→ 插件层    : /Users/melodycchen/ai-work/dsh/dsh-learn/plugins/codebuddy-llm-v2/cordis.patch.yml
→ Web UI    : http://127.0.0.1:3080（start.sh --port <n> 可换端口）
dsh web: http://127.0.0.1:3080/?token=URVS1Xk7SSldZqTtFr-s-sBRFOlDBHxD6ncVf3vqjZo
dsh web: opening the default browser; pass --no-open to disable
```

**复制那个带 `?token=...` 的 URL** 到浏览器打开。

> **⚠️ 一定要带 `?token=...`**：不带会得到 **`dsh web authentication required`**（我实测过）。原因见 08.1——这是 dsh 的浏览器鉴权。

### 步骤 4：看效果

**整个界面变成深色了。** 我截图对比：

- 改之前（`system`，在浅色系统上）→ **浅色界面**
- 改之后（`dark`）→ **深色界面**（左栏、对话区、输入框全变深）

> **实测证据**：改完后我抓了首页 HTML，boot script 里变成：
> ```js
> const preference = "dark"
> const dark = preference === 'dark' || systemDark
> document.body.toggleAttribute('data-ds-dark-theme', dark)
> ```
> （来源：`packages/client/ui-theme/lib/index.js` 的 `bootThemeScript()` 生成）
> 也就是：**`preference` 值 → boot 脚本解析 → 给 `<body>` 打上 `data-ds-dark-theme` 属性 → CSS 里所有 `body[data-ds-dark-theme]` 的规则生效**。

### 步骤 5：还原

```bash
cp ~/.dsh/settings.yaml.bak ~/.dsh/settings.yaml
```

（或手动改回 `system`。）

## 三、这一切背后的机制（看懂这几行就够）

**为什么改一个 YAML 值，整个界面就变深了？** —— 三样东西串起来：

### ① 主题 token：`--dsw-*` 变量

dsh 的 CSS 里**不写死颜色**，而是用**变量**：

```css
/* 出处：ui-theme/src/styles/design-platform.css（逐字） */
--dsw-alias-bg-base: var(--dsw-static-neutral-bluish-00);   /* 浅色：近白 */
```

### ② 深色模式 = 换一组同名变量

```css
/* 出处：design-platform.css:251 起（逐字） */
body[data-ds-dark-theme] {
  --dsw-alias-bg-base: var(--dsw-static-neutral-bluish-950);  /* 深色：近黑 */
}
```

**同一套变量名（`--dsw-alias-bg-base`），深色模式下换成不同的值。** CSS 层叠自动生效——**所有用到这个变量的地方一起变**。

> **Go 类比**：像**一份接口，两套实现**——业务代码调 `GetBgBase()`，**底层是浅色实现还是深色实现，你不用改调用方**。

### ③ `preference` → `data-ds-dark-theme` 属性

```
settings.yaml 的 preference
      ↓（启动时读取）
boot script 生成
      ↓
body[data-ds-dark-theme] 被设上
      ↓
所有 --dsw-* 深色覆盖生效
      ↓
整个界面变深
```

**所以"改主题"= 改"触发哪套 CSS 变量"**——**完全不碰 React 组件**。

> **出处**：`ui-theme/src/styles/design-platform.css`（两处 `body[data-ds-dark-theme]`）+ `ui-theme/lib/index.js` 的 `bootThemeScript()`

## 四、你学到的"后端可迁移技能"

这个实验**表面上很小**（改了个主题），但它验证了**三件对后端重要的事**：

| 结论 | 对应前文 |
| --- | --- |
| **配置驱动**：改行为不一定要改代码 | 08.1（配置 vs 逻辑） |
| **样式与逻辑分离**：改样式不碰组件逻辑 | 08.4（token 体系） |
| **鉴权意识**：访问要带 token | 08.1（浏览器鉴权） |

> **Go 类比总纲**：你改 Go 服务的**配置**，不需要重编译；同理，**改 dsh 的样式，不需要会 React**。
