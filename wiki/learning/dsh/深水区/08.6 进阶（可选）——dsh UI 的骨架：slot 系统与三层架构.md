## 这一节的组织

08.6 是**四篇子文章**，按"从全局到局部"排列：

```
08.6.1  三层架构模型        ← 全局：dsh 前端为什么"不依赖 React"、哪层干嘛
   ↓
08.6.2  Slot 系统深入       ← 核心：一个 register API 撑起整棵 UI 树
   ↓
08.6.3  React 绑定机制      ← 局部：裸数据源 → React 钩子（27 行）
   ↓
08.6.4  样式体系深入        ← 局部：三层 token、CSS Modules、发丝线规矩
```

**每篇的定位**：

| 篇 | 回答什么 | 难度 |
| --- | --- | --- |
| **08.6.1 三层架构模型** | dsh 前端分了哪三层？为什么 React 只是在最上面一层？ | ★★☆ |
| **08.6.2 Slot 系统深入** | `register` 怎么拼出整棵树？四种 kind？props 四份额？ | ★★★ |
| **08.6.3 React 绑定机制** | "没有 React 的数据"怎么变成"React 能订阅的钩子"？ | ★★★ |
| **08.6.4 样式体系深入** | token 的三层结构？那些"发丝线/投影"的硬规矩是啥？ | ★★☆ |

## 为什么把这四篇放"最后"

**回到 08.0 的教训**：我第一版**把这四篇放在了开头**——结果对一个不懂前端的后端来说，**完全悬空**。

**现在它们放在最后**，因为读到这里：

- 你懂了**前端是什么**（08.1）→ 能看懂"浏览器/服务器三层"
- 你懂了 **TS 语法**（08.2）→ 能看懂类型、模块、异步
- 你懂了 **React**（08.3）→ 能看懂组件、钩子
- 你懂了 **dsh 界面 = 插件拼的**（08.4）→ 有了"槽"的直觉
- 你**动手改过样式**（08.5）→ 有了体感

**这时候再看"slot 系统的四种 kind、props 四份额、uSES 绑定"——才接得住。**

## 一条"进阶路线"建议

如果你是**后端、想写 dsh UI 插件**，建议这个顺序：

```
① 读 08.6.1（三层架构）—— 建立全局观
       ↓
② 读 08.6.2（slot 系统）—— 核心机制，重点
       ↓
③ 跳过 08.6.3 / 08.6.4（先不深究绑定/样式细节）
       ↓
④ 回去实践：照 08.6.2 写一个最小的 UI 插件（注册一个按钮）
       ↓
⑤ 卡住了再回来查 08.6.3 / 08.6.4
```

> **我实测做过 ④**：在 `~/ai-work/dsh/dsh-learn/example/deepwater/plugins/ui-hello/` 里写了一个最小 client 插件，往左侧栏底部加了个按钮，**真的跑起来了**（该目录带 `README.md`，含构建/运行步骤）。过程中踩了两个真实的坑——**这俩坑正是 08.6.2 讲的规则的现实版**：
> 1. 往**已被占用的 `single` 槽**注册 → 装载报错 `already has a registration at priority 0`
> 2. 往 **`list` 槽**注册但**没给 `id`** → 报 `list slot "..." requires options.id`
