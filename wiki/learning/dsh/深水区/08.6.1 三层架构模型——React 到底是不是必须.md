# 08.6.1 前端架构三层模型——React 到底是不是"必须"

> [!info] 版本锚点
> - 源码：`~/ai-work/dsh/deepseek-harness/`（master `0d1f50007f`）；全局包 `dsh 0.1.5-rc.1`
> - 前置：**08.0~08.5**（地基 + dsh 界面直觉）+ **03 篇（插件·package·bundle·patch·profile）**
> - **定位**：**08.6 进阶的第一篇**——可选，卡住了再回来查
> - 写法说明：本篇以**读源码 + 讲机制**为主，每个结论都带可复现的 grep 断言

> [!abstract] 本章是什么 / 该记住什么
> **回答的问题**："**dsh 写前端，必须用 React 吗？**"
> **答案**：**分层看**——**状态层和组合层根本没有 React；只有"渲染层"用 React**。
> **读完该记住 5 点**：
> 1. **dsh 前端是"三层"**：`store`（无 React 状态）+ `ui-slots`（框架无关组合）+ `ui-renderer`（**唯一** React 集成点）
> 2. **45 个 `ui-*` 包，React 一律在 `devDependencies`**，**没有任何包**把它放进 `dependencies`/`peerDependencies`
> 3. **数据对象层（`session-controller/src/client`）是 React-free 的**——架构文档明说"grep 可断言"，本篇实测 = **0 处**
> 4. **`ctx↔React` 集成只发生在一个文件/一个包**（`ui-renderer`）；业务组件"**永远不需要自行接线订阅**"
> 5. **结论**：想写"非 UI 的客户端逻辑"（状态/通信/RPC）→ **可以完全不碰 React**；想写"浏览器里看得见的东西" → **走 slot 系统，组件是普通 React 组件**

## 这一篇在讲什么

**你（Go 后端）问了个好问题**："dsh 写前端必须用 React 吗？"

我当时先跑了 `grep -rl '"react"' packages/client/*/package.json | wc -l` → **45**（45 个 `ui-*` 包都提到 react）。**但这个数字会骗人**——它没区分 react 是"依赖"还是"开发依赖"。本篇就是**把这件事查到底**，顺便给你一张**前端架构全景图**。

**一句话**：**dsh 前端 = "框架无关的内核" + "一个可替换的 React 渲染器"**。React 是**被选中的渲染实现**，不是**架构的地基**。

> **Go 类比**：就像 **`http.Handler` 接口 vs `net/http` 的默认实现**——**接口（slot 系统）是地基，`net/http`（React）只是当前接上去的那套实现**。而 store/对象层相当于"**不依赖任何 Web 框架的领域模型**"，跟 `encoding/json` 一样，谁都能用、谁都不绑。

## 一、先破一个直觉：45 个包 ≠ 45 处 React 依赖

### 直觉的坑

```bash
# 这是我最开始跑的，看起来很吓人
grep -rl '"react"' packages/client/*/package.json | wc -l
# → 45
```

**但 `'"react"'` 匹配不到"在哪一类依赖里"**。换一个查法：

```bash
cat packages/client/ui-chat/package.json | python3 -c "
import json,sys
d=json.load(sys.stdin)
for k in ['dependencies','peerDependencies','devDependencies']:
    v=list(d.get(k,{}).keys())
    print(f'{k}:', [x for x in v if 'react' in x.lower()] or '（无react）')
"
# → dependencies: （无react）
# → peerDependencies: （无react）
# → devDependencies: ['@types/react', '@types/react-dom', 'react', 'react-dom']
```

> **出处**：`packages/client/ui-chat/package.json`（`ui-chat` 是主对话视图包）

**结论 1**：**React 是 `devDependencies`**——`dependencies` 和 `peerDependencies` **都没有**。

### 这个"devDependencies"意味着什么（重点）

在 npm 语义里：

| 依赖类别 | 含义 | 打不打进产物 |
| --- | --- | --- |
| `dependencies` | 运行**必须**带上 | ✅ 会 |
| `peerDependencies` | "由宿主提供，我不带" | ❌ 不会 |
| `devDependencies` | 只**开发/构建**时用 | ❌ 不会 |

**React 在 `devDependencies`** → **`ui-*` 插件编译出的 `lib/client.js` 里不会打包 React**。React **由 Web 外壳在运行时统一提供**。

> **出处**：`packages/client/README.zh.md:37` 说 `ui-renderer` "将 slot 数据绑定到 React"；`2026-07-23-client-plugin-loading-model.zh.md:31`（逐字）：*"**React、Cordis 与静态 UI 库的身份由外壳 seed 提供**。"*

**为什么这么设计？** —— 假设每个插件都自带一份 React：

```
插件A 带 React@18.2  ┐
插件B 带 React@18.2  ├─► 浏览器里 3 份 React → 3 套 hooks 状态 → 💥
插件C 带 React@18.2  ┘
```

**共享运行时**（单一版本的 React + 单一 Cordis 实例）是**插件化 GUI 的硬前提**。所以 React 必须被"**外壳播种**"，插件只写组件、不带运行时。

## 二、三层模型：一张图看懂

架构文档的原话是"**React-free 对象层**" + "**React 面**"两段式的。我把它整理成**三层**（更好记，且每层都有 grep 断言）：

```
┌─────────────────────────────────────────────────────────────┐
│  ③ 渲染层    ui-renderer        ← 唯一碰 React 的地方         │
│              ─────────────                                  │
│              · createSlotRenderer() / SessionProvider / uSES │
│              · mount(container) 挂载 React 根                │
│              · ctx.slots.install(...) 安装渲染器             │
└───────────────────────────▲─────────────────────────────────┘
                            │  "裸 observable source"
                            │  （getSnapshot / subscribe，
                            │   README 原文：绝不携带 React 钩子）
┌───────────────────────────┴─────────────────────────────────┐
│  ② 组合层    ui-slots          ← 框架无关（依赖里没有 react）  │
│              ─────────────                                  │
│              · 单一 register API                             │
│              · SlotMap 声明合并（编译期类型权威）             │
│              · 四种 kind：single / list / keyed / chain       │
└───────────────────────────▲─────────────────────────────────┘
                            │  声明 store 席位 / renderSlot
┌───────────────────────────┴─────────────────────────────────┐
│  ① 状态层    store             ← 明确"不依赖 React"           │
│              ─────────────                                  │
│              · zustand vanilla + immer + 可选 localStorage    │
│              · 产出"裸的可观察源"                             │
│              · 以及 api/session-controller/src/client（对象层）│
└─────────────────────────────────────────────────────────────┘
```

### 每层的一句话证据

**① 状态层**（`store` 包）：

> **出处**：`packages/client/store/README.zh.md:11`（逐字）——*"供 Client 控制器与 renderer 适配器共用的**不依赖 React** 的 observable 和快照存储基础原语。……**React 钩子的构造仍属于** `@deepseek-ai/dsh-client-ui-renderer`。"*

**② 组合层**（`ui-slots` 包）：

> **出处**：`packages/client/ui-slots/package.json` —— `dependencies: []`（空！）、`peerDependencies: ['@deepseek-ai/cordis']`、`devDependencies: ['@types/react']`（只有类型）。
> **出处**：`packages/client/ui-slots/README.zh.md:12`（逐字）——*"**需要与框架无关的 slot 组合时选择本包**；客户端需要 React 渲染时与 `ui-renderer` 配合使用。"*
> **出处**：同文件 `:58` —— *"引擎产物与渲染器宿主约定携带裸快照 source（`getSnapshot`/`subscribe`），**绝不携带 React 钩子**——钩子绑定属于渲染机制。"*

**③ 渲染层**（`ui-renderer` 包）：

> **出处**：`packages/client/ui-renderer/README.zh.md:46`（逐字，最强的一句）——*"本包实现一条边界：**对象层（运行时，无 React）拥有业务状态**；**这里是 ctx 到 React 集成唯一发生的位置**——slot 渲染器、`SessionProvider` 与 `useSyncExternalStore` 适配器。"*

> **Go 类比**：这三层就是**"领域模型 / 装配接口 / 具体框架适配器"**的正统分层。第 ③ 层相当于 `database/sql` 的 driver——**换个 driver（比如将来换 Preact/Solid），上面两层不动**。

## 三、四条可复现的 grep 断言（把结论钉死）

架构文档自称"对象层 React-free（**零 React import，grep 可断言**）"。我**逐条实测**，四条全过：

### 断言 ① 对象层真的 React-free

```bash
cd ~/ai-work/dsh/deepseek-harness
grep -rcE "from ['\"]react" packages/api/session-controller/src/client/ | grep -v ":0" | wc -l
```
**实测 → `0`** ✅

> **出处**：`2026-07-19-gui-web-client-architecture.zh.md:51`（逐字）——*"帧从这里进、快照从这里出、Conversation assembler 坐在中间——**React-free（零 React import，grep 可断言）**"*

**这层就是**：帧进 → 快照出 → `ConversationNodeAssembler` 在中间。它**只做数据**，一行 React 都没有。

### 断言 ② `store` 包 React-free

```bash
grep -rcE "from ['\"]react" packages/client/store/src/ | grep -v ":0" | wc -l
```
**实测 → `0`** ✅

### 断言 ③ 全仓只有一处挂载 React 根

```bash
grep -rlE "react-dom/client|createRoot" packages/client/*/src | sed 's|packages/client/||;s|/src.*||' | sort -u
```
**实测 → `ui-renderer`、`web`** ✅（`web` 是外壳，`ui-renderer` 是渲染器——正是文档说的"Web 外壳与启动内核是它仅有的直接消费方"）

> **出处**：`packages/client/ui-renderer/README.zh.md:12` —— *"Web 外壳与启动内核是它仅有的直接消费方"*；`gui-web-client-architecture.zh.md:78` 段落标题即"**React 面（`packages/client/ui-renderer`）**"。

### 断言 ④ 没有任何包把 react 放进"真依赖"

```bash
cd ~/ai-work/dsh/deepseek-harness
for f in packages/client/*/package.json; do
  python3 -c "
import json,sys
d=json.load(open('$f'))
deps=set(d.get('dependencies',{}))|set(d.get('peerDependencies',{}))
print('YES' if any(x in ('react','react-dom') for x in deps) else 'NO')
" | grep -q YES && echo "⚠️ $f 违规"
done
```
**实测 → 无输出**（即**零违规**）✅

## 四、所以：到底"必须"吗？——分场景回答

把三层模型翻译成**你可以直接用的判断**：

| 你想做的事                   | 要不要碰 React | 走哪层    | 关键 API                                              |
| ----------------------- | ---------- | ------ | --------------------------------------------------- |
| 管理客户端状态（选中项、草稿、面板宽）     | ❌ **不用**   | ① 状态层  | `defineStore({ init, actions })`                    |
| 处理浏览器↔宿主通信（RPC、事件流）     | ❌ **不用**   | ① 状态层  | `ctx.connection` / `ctx.remote`                     |
| 写业务逻辑、数据组装、投影           | ❌ **不用**   | ① 状态层  | `session-controller`（React-free）                    |
| 在页面上**加一块 UI**（按钮/面板/行） | ✅ 要        | ② + ③  | `ctx.slots.register({ name, children }, Component)` |
| 覆盖/扩展已有 UI 区域           | ✅ 要        | ② + ③  | `ctx.slots.inject(key, () => register(...))`        |
| 改主题色 / 排版 / 阴影          | ❌ **不用**   | ③ 的样式层 | `--dsw-alias-*` token（见 08.4）                       |

**两条硬结论**：

1. **"必须用 React"成立的条件**：你要**往浏览器里放一个看得见的组件**。因为 `ui-renderer` 渲染的就是 React 组件——**这一层目前只有 React 实现**。
2. **"可以完全不用 React"也成立**：**纯逻辑/状态/通信/主题**的客户端插件，**一行 React 都不用写**——`store`（0 处）、`connection`（0 处）、对象层（0 处）都是活证据。

> **⚠️ 别忘了架构的"逃生舱"设计**：`ui-slots` 是**框架无关**的（`dependencies: []`）。这意味着**渲染器是可以换的**——React 只是当下的选择，"框架无关的组合核心"才是架构想保住的东西。这一点在 `ui-slots/README.zh.md:12` 有明确措辞（"需要与框架无关的 slot 组合时选择本包"）。

## 五、10 个"零 React import"的客户端包（真实清单）

我把 `packages/client/*/src` 里**不 import react** 的包全列出来——**这就是"不用 React 也能写客户端插件"的实证**：

```bash
cd ~/ai-work/dsh/deepseek-harness
for d in packages/client/*/; do
  if [ -d "$d/src" ] && ! grep -rqE "from ['\"]react" "$d/src" 2>/dev/null; then
    echo "  $(basename $d)"
  fi
done
```

**实测输出**（10 个）：

| 包 | 职责（出处：`packages/client/README.zh.md` 包表） |
| --- | --- |
| `connection` | 浏览器↔宿主 RPC 通信与事件投递（`ctx.connection`） |
| `file-upload` | 在页面线程之外发送原始 Blob/字节流 |
| `hmr` | 开发期刷新客户端插件 |
| `modules` | 加载浏览器侧客户端模块（`ctx.clientModules`/`ctx.modules`） |
| `resources` | 客户端资源模型（见 `2026-09-05-client-resource-model.zh.md`） |
| `store` | 不依赖 React 的 observable 与快照存储原语 |
| `ui-brand-official` | 品牌标识（纯静态资源/变量） |
| `ui-reference` | 引用相关（视图注册，不含 React import 路径） |
| `ui-settings` | 设置（`2026-09-07-prebuilt-system-primitives.zh.md` 相关） |
| `ui-theme` | 应用颜色主题（**token 定义，不是组件**） |

> **注意**：这里的判断标准是"`src` 里有没有 `from 'react'`"。像 `ui-theme`/`ui-settings` **有自己的 React 组件子树**（`src/client/*.tsx`），但它们**核心的 token/设置逻辑**不与 React 耦合——`ui-theme` 的核心是 `styles/*.css`，属**样式层**，见 08.4。

## 六、本篇小结

- **dsh 前端不是"React 应用"**，而是"**框架无关的 slot 组合核心 + 一个 React 渲染器**"。
- **React 在所有 `ui-*` 包里都是 `devDependencies`**——运行时不打包，由外壳统一播种（**共享运行时**是插件化 GUI 的前提）。
- **数据对象层（`session-controller/src/client`）是 React-free 的**，`store` 也是——**grep 断言四条全过**。
- **"必须 React"只在"要渲染可见组件"时成立**；纯逻辑/状态/通信/主题/样式**零 React**。
- **下一节**（08.2）深入 **slot 系统**——`register` 这**唯一一个** API 怎么撑起整棵 UI 树。
