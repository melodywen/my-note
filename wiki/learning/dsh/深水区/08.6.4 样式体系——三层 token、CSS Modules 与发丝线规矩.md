# 08.6.4 样式体系——三层 token、CSS Modules 与那一套"发丝线"规矩

> [!info] 版本锚点
> - 源码：`~/ai-work/dsh/deepseek-harness/`（master `0d1f50007f`）；全局包 `dsh 0.1.5-rc.1`
> - 前置：**08.6.1（三层模型）**——样式属③渲染层的"旁支"（`ui-theme` 是 token 定义，不是组件）
> - 权威文档：`docs/web-styling.zh.md`（**全文仅 30 行**，却是核心规范）
> - token 真值目录：`packages/client/ui-theme/src/styles/`
> - 写法说明：以**读源码 + 讲机制**为主；引号内为文档**逐字**

> [!abstract] 本章是什么 / 该记住什么
> **回答的问题**："**dsh 的 UI 样式怎么组织？我怎么改主题、写自己的组件样式？**"
> **答案**：**三层 token**（static 色板 → alias 语义 → elevation 投影）+ **CSS Modules** + **一套"发丝线/投影"硬规矩**。
> **读完该记住 7 点**：
> 1. **三层 token**：`--dsw-static-*`（73 个真色值）→ `--dsw-alias-*`（85 个语义别名）→ `--dsw-elevation-*`（5 个投影）
> 2. **功能包只用 `--dsw-alias-*`**——**禁止**写死色值/复制静态色板（文档逐字）
> 3. **CSS Modules + `clsx`**；**不得**加组件库或 Tailwind
> 4. **主题切换是 `body[data-ds-dark-theme]`**——暗色覆盖**归主题所有方**，功能组件**不得含主题选择器**
> 5. **发丝线规矩**：中性边框/分割线一律 **`0.5px`**（Chromium 画成 1 设备像素）
> 6. **高层级表面用 `box-shadow: var(--dsw-elevation-*)` + `border: 0`**——**不得**把 `--dsw-alias-border-*` 和 elevation 投影配对（spec 会拒）
> 7. **改样式前先复用 `ui-primitives`**——它是**唯一跨功能包通道**；有意的视觉差异应做成那里的一个 prop

## 这一篇在讲什么

08.1 说"改主题色/排版/阴影**不用碰 React**"——本篇就来兑现这句话。**样式是独立于组件逻辑的一层**：`ui-theme` **只定义 token**，组件**只消费语义别名**。

**一句话**：**dsh 的样式 = "三层 token 体系" + "一系列被 spec 强制执行的硬规矩"**。

> **Go 类比**：三层 token 就像**常量 → 领域名 → 组合**：`--dsw-static-neutral-100` 是**常量**（`245,245,245`），`--dsw-alias-bg-layer-2` 是**领域名**（"第二层背景"），`--dsw-elevation-panel` 是**组合**（描边+两层阴影）。**业务代码只引用领域名**——跟"不 magic number、用具名常量"同一条纪律。

## 一、三层 token：从"真色值"到"语义"到"投影"

token 真值全在 `packages/client/ui-theme/src/styles/design-platform.css`（主体）+ `gradient-shadow-text.css`（投影）。共三类：

| 层 | 前缀 | 数量 | 例子（真值） |
| --- | --- | --- | --- |
| **静态色板** | `--dsw-static-*` | **73** | `--dsw-static-neutral-100: rgb(245, 245, 245);` |
| **语义别名** | `--dsw-alias-*` | **85** | `--dsw-alias-bg-layer-2: var(--dsw-static-neutral-bluish-00);` |
| **投影** | `--dsw-elevation-*` | **5** | `--dsw-elevation-panel: ...;` |

> **出处**：`design-platform.css:5` 起定义 `--dsw-static-*`；`:157` 起定义 `--dsw-alias-*`；`gradient-shadow-text.css:28-34` 定义 `--dsw-elevation-*`（数量为 `grep -oE` 实测）

### 第一层：静态色板（真色值）

```css
/* 出处：design-platform.css 逐字 */
--dsw-static-neutral-100: rgb(245, 245, 245);
--dsw-static-blue-500: rgb(59, 130, 246);
--dsw-static-deepseek-500: rgb(65, 118, 230);
```

**命名规律**：`色名-步进`（`00` 最亮 → `1000` 最暗）。**业务代码不该直接用这一层**——它是"调色板"。

### 第二层：语义别名（业务代码该用的层）

```css
/* 出处：design-platform.css:157 起，逐字 */
--dsw-alias-bg-base:     var(--dsw-static-neutral-bluish-00);
--dsw-alias-bg-layer-1:  var(--dsw-static-neutral-bluish-00);
--dsw-alias-bg-layer-2:  var(--dsw-static-neutral-bluish-00);
--dsw-alias-bg-layer-3:  var(--dsw-static-neutral-bluish-00);
--dsw-alias-border-l1:   rgba(0, 0, 0, 0.04);
--dsw-alias-border-l2:   rgba(0, 0, 0, 0.1);
--dsw-alias-brand-primary: var(--dsw-static-neutral-bluish-1000);
```

**读法**：`bg-layer-N` = "第 N 层背景"；`border-lN` = "第 N 级边框"；`brand-primary` = 品牌主色。**这些名字描述"用途"，不描述"颜色"**——所以暗色主题能**换掉背后的真值**而业务代码不动。

> **⚠️ 硬规矩（文档逐字）**：
> > **出处**：`docs/web-styling.zh.md` 组件规则第 3 条——*"功能组件使用 `--dsw-alias-*` 语义 token。**不得复制静态色板值或在其中写入颜色字面量**。"*

### 第三层：投影（elevation）

```css
/* 出处：gradient-shadow-text.css:28-34，逐字 */
--dsw-elevation-stroke:    0 0 0 0.5px var(--dsw-elevation-stroke-color);
--dsw-elevation-panel:
  var(--dsw-elevation-stroke), 0 3px 8px 0 rgba(0, 0, 0, 0.03), 0 0 16px 0 rgba(0, 0, 0, 0.02);
--dsw-elevation-prominent:
  var(--dsw-elevation-stroke), 0 3px 8px 0 rgba(0, 0, 0, 0.04), 0 0 20px 0 rgba(0, 0, 0, 0.05);
--dsw-elevation-soft:
  var(--dsw-elevation-stroke), 0 4px 16px 0 rgba(0, 0, 0, 0.03), 0 0 24px 0 rgba(0, 0, 0, 0.03);
```

**三个投影，每个都是"描边 + 两层柔光"**：

```
--dsw-elevation-panel     →  面板（0 3px 8px + 0 0 16px）
--dsw-elevation-prominent →  强调浮层（0 3px 8px + 0 0 20px，更深）
--dsw-elevation-soft      →  输入框（0 4px 16px + 0 0 24px，更大模糊、更低透明度）
```

> **设计要点（文档逐字）**：第一层是 `0 0 0 0.5px` 的**"发丝描边"**——*"0.5px 发丝描边是**第一层投影**"*（`docs/web-styling.zh.md` 组件规则）。**它把"描边"统一进了阴影**，所以高层级表面 `border: 0`。

## 二、主题切换：`body[data-ds-dark-theme]`

**机制很简单**：`:root` 定义亮色 token，`body[data-ds-dark-theme]` **重定义同名 token** → CSS 层叠自动生效。

```css
/* 亮色（:root，出处：design-platform.css:157 起） */
--dsw-alias-bg-base: var(--dsw-static-neutral-bluish-00);   /* 白 */

/* 暗色（出处：design-platform.css:251 起，逐字） */
body[data-ds-dark-theme] {
  --dsw-alias-bg-base: var(--dsw-static-neutral-bluish-950);  /* 近黑 */
  --dsw-alias-bg-layer-1: var(--dsw-static-neutral-bluish-875);
  /* ... */
}
```

> **出处**：`design-platform.css:80` 和 `:251` 两处 `body[data-ds-dark-theme]` 块（前者重定义 static，后者重定义 alias）

> **⚠️ 硬规矩（文档逐字）**：
> > **出处**：`docs/web-styling.zh.md` 职责归属——*"`ui-theme` 负责 `--dsw-*` 静态色阶、语义别名、排版、动效、渐变、阴影、滚动条样式以及**明暗主题偏好**。`ui-layout` 将**解析后的主题快照应用到文档**。"*
> > 组件规则第 4 条——*"功能组件 CSS **不得包含主题选择器**。**明暗主题覆盖属于主题所有方**。"*

**两条职责是分开的**：

```
ui-theme  →  定义 token（静态值 + 明暗覆盖）
ui-layout →  应用主题（把"解析后的快照"写到文档上）
功能包    →  只用 --dsw-alias-*，不写主题选择器
```

> **Go 类比**：`ui-theme` 像**"配置的定义"**（schema + 默认值），`ui-layout` 像**"配置的加载与应用"**。**业务代码只读配置，不改配置**。

## 三、组件样式：CSS Modules + clsx（没有 Tailwind）

> **出处**：`docs/web-styling.zh.md` 组件规则第 2 条（逐字）——*"使用 **CSS Modules 和 `clsx`**；**不得添加组件库或 Tailwind**。"*

**为什么禁 Tailwind / 组件库？** —— 见下一节（08.1 讲过"共享运行时"）：插件样式**内联在各自 bundle 里**，用 CSS Modules 能保证**类名哈希化 + 归属隔离**：

> **出处**：`2026-07-19-gui-web-client-architecture.zh.md:31`（逐字）——*"全局样式与 CSS Modules 都**内联在其持有插件的 bundle 中**，物化时注入为 `<style data-plugin="<id>">`（**CSS Modules 还会取得哈希类名**；**归属标签使重载时移除成为可能**）"*

**示例（组件旁放 `.module.css`）**：

```css
/* MyPanel.module.css */
.panel {
  border: 0;                              /* 高层级表面：border 归零 */
  box-shadow: var(--dsw-elevation-panel); /* 用投影 */
  background: var(--dsw-alias-bg-layer-1);/* 语义别名 */
  color: var(--dsw-alias-text-primary);
}
```

```tsx
import clsx from 'clsx'
import styles from './MyPanel.module.css'
// <div className={clsx(styles.panel, isActive && styles.active)} />
```

### 局部自定义属性：允许的"逃生舱"

> **出处**：`docs/web-styling.zh.md` 职责归属（逐字）——*"组件样式以 **CSS Modules 格式放在组件旁**。当某个值属于该组件的**布局或呈现约定**时，组件**可以定义局部自定义属性**；**共享颜色、排版、层级和动效属于主题包**。"*

**判断标准**：

```
这个值是我这个组件的"局部约定"（如某面板宽度的变量）  →  组件可定义局部自定义属性
这个值是"共享的颜色/排版/层级/动效"                  →  必须用主题 token
```

> **出处**：组件规则第 8 条（逐字）——*"呈现规则**写在 CSS 中**。React 内联样式**可以传递组件局部自定义属性值**，但**不得编码主题分支**。"*

## 四、那套"发丝线 + 投影"的硬规矩（dsh 样式最独特的部分）

这是 `docs/web-styling.zh.md` 花最多笔墨的地方，也是 dsh UI "看起来干净"的秘诀。**逐条列出**：

### 规矩 1：发丝线 = `0.5px`

> **出处**：组件规则第 7 条（逐字）——*"使用中性 `--dsw-alias-border-*` token 的**平面边框与分割线一律 `0.5px`**——按钮、输入框、卡片、行分割线，以及以填充盒绘制的分隔线（菜单分隔、对话标题栏接缝、markdown `hr`、竖向轨道线）**共用发丝线粗细**，**Chromium 将其绘制为一个设备像素**。**dashed 记号与状态色 border 保持 1px**；spinner 圆环经 spec 的显式豁免保留原宽度。**更宽的中性 solid border 会被 ui-theme elevation spec 拒绝**。"*

**翻译**：

```
中性 border（--dsw-alias-border-*）  →  0.5px（Chromium 画成 1 设备像素）
dashed 记号 / 状态色 border        →  1px（例外）
spinner 圆环                       →  豁免
更宽的中性 solid border            →  ❌ spec 拒绝
```

### 规矩 2：高层级表面 = `border: 0` + `box-shadow`

> **出处**：组件规则第 6 条（逐字）——*"高层级表面（菜单、浮层、对话框、面板、悬浮按钮、输入框）**设 `border: 0`** 并使用 `box-shadow: var(--dsw-elevation-panel)`、`var(--dsw-elevation-prominent)` 或输入框专用的 `var(--dsw-elevation-soft)`……**不得将 `--dsw-alias-border-*` border 与 lv/elevation 投影配对**——ui-theme 的 elevation spec 会拒绝；**状态色 border（warn 面板）保持真 border**。"*

```
高层级表面（菜单/浮层/对话框/面板/悬浮按钮/输入框）
  →  border: 0
  →  box-shadow: var(--dsw-elevation-panel | -prominent | -soft)

⚠️ 禁止：border: 1px solid var(--dsw-alias-border-*) + box-shadow: var(--dsw-elevation-*)
         （会"双重描边"——elevation 第一层已是描边）
```

### 规矩 3：字体大小必须配行高

> **出处**：组件规则第 5 条（逐字）——*"字体大小**必须与行高配对**；已有角色匹配时使用**主题排版变量**。"*

### 规矩 4：圆角与 `corner-shape`

> **出处**：组件规则第 10 条（逐字）——*"支持的引擎上，**圆角继承 ui-theme `corner-shape.css` 的全局超级椭圆平滑**。每个**正圆 `border-radius`（`50%`、`100%` 或胶囊半径）必须配对 `corner-shape: round`**，使圆形与胶囊保持圆弧；ui-theme 的 corner-shape spec 强制这一配对。"*

### 规矩 5：不换行 + 无障碍

> **出处**：组件规则第 9 条（逐字）——*"当组件约定要求**保留列结构**时，源码文本、终端输出和 diff 行**不得换行**；使用**共享滚动条样式**，不得定义组件专用滚动条选择器。"*
> 第 9 条下一条（逐字）——*"添加过渡动画或仅悬停可见的控件时，**保留清晰可见的键盘焦点和减少动态效果行为**。"*

### 规矩 6：可点击链接的统一外观

> **出处**：组件规则第 12 条（逐字）——*"可点击产物链接（Markdown 锚点、正文文件引用、网页来源与抓取链接、产物 chips、workflow 成员链接）经 `--dsw-alias-link` 着色、`font-weight: 500`，**默认无下划线，hover/focus 时为 3px offset 的点状下划线**。"*

### 这些规矩"谁在管"？—— **spec**

文档多次提到"**ui-theme 的 elevation spec 会拒绝**""**corner-shape spec 强制**"。说明有一层**自动检查**：

> **出处**：`docs/web-styling.zh.md` 变更系统（逐字）——*"在所属 `ui-theme` 样式表中**添加或修改共享 token**，然后在功能包中使用其**语义别名**。公共样式约定发生变化时，更新所属包的参考文档。视觉行为遵循[测试策略](testing.zh.md)；[样式系统 Agent Note](../.agents/notes/implemented/process/2026-07-19-web-styling-system.zh.md) 记录框架依据。"*

## 五、改样式的正确姿势（工作流）

> **出处**：`docs/web-styling.zh.md` 变更系统（逐字，上述引文）

```
① 要在 ui-theme 样式表里加/改【共享 token】
       ↓
② 在功能包里改用它的【语义别名】（--dsw-alias-*）
       ↓
③ 公共约定变了 → 更新所属包的参考文档
```

### 但第一原则是"**先复用，别重造**"

> **出处**：组件规则第 1 条（逐字）——*"**重新设计控件样式之前先复用控件**：**ui-primitives 组件目录是唯一跨功能包的通道**，有意的视觉差异应作为**那里的一个 prop**，而不是另起一份拷贝"*

**翻译**：想要个按钮？**先看 `ui-primitives` 有没有**。想让它"轻微不同"？**去 `ui-primitives` 加个 prop**——**不要**自己拷一份改。

> **Go 类比**：这就是**"先看标准库，别自己造轮子"**。`ui-primitives` 就是 dsh UI 的"标准库"——**唯一被允许跨功能包共享的控件层**。

## 六、本篇小结

- **三层 token**：`--dsw-static-*`（73，真色值）→ `--dsw-alias-*`（85，语义）→ `--dsw-elevation-*`（5，投影）。**业务只用后者**。
- **禁色值字面量**、**禁复制静态色板**、**禁 Tailwind/组件库**；**CSS Modules + clsx**。
- **主题切换是 `body[data-ds-dark-theme]`**；**暗色覆盖归主题所有方**，功能组件**禁主题选择器**。
- **发丝线规矩**：中性 border `0.5px`；**高层级表面 `border: 0` + `box-shadow: var(--dsw-elevation-*)`**；**禁** alias-border 与 elevation 配对。
- **先复用 `ui-primitives`**——**唯一跨功能包通道**，视觉差异做成 prop 而非拷贝。
- **改样式工作流**：改 ui-theme token → 功能包用别名 → 更新文档。
- 这些规矩由 **ui-theme 的 spec** 强制执行（elevation spec / corner-shape spec）。

- **下一节**（08.5）开始**动手**——写一个最小的 `ui-*` 插件，把前三节串起来。
