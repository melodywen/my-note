# 09.0 mini-dsh——从零理解一个 Agent Harness

> [!info] 版本锚点
> - 源码：`~/ai-work/dsh/deepseek-harness/`（master `0d1f50007f`）；全局包 `dsh 0.1.5-rc.1`
> - 前置：**01 内核机制（agent-loop）** + **03 插件·package·bundle·patch·profile** + **08 章（如果涉及 Web）**
> - 本篇对象：**想真正搞懂"harness 内核"的后端**——不是学 API，是学**机制**

> [!abstract] 这一章讲什么 / 为什么值得做
> **一句话**：**亲手搭一个"能跑的最小 harness"**——能对话、能调工具、能循环。
> **为什么**：前面章节你都是"**读** dsh 的代码"。这一章是**第一次让你"自己造一个"**——只有造过，才真正知道 dsh 里那些代码**为什么要那么写**。
> **读完该记住 3 点**：
> 1. **harness 的内核只有四块**：agent-loop（循环）+ tools（工具）+ llm（模型）+ session（会话）
> 2. **官方自己就是这么界定的**：`sdk-minimal` profile = 32 个插件（对比完整版 87 个）
> 3. **"最小"不是我们拍脑袋**——是**照着官方最小形态反推**出来的

## 二、先破题：什么是"harness 的最小内核"

**问题**：dsh 那么大（几十个包），**哪个才是"不可再删"的内核**？

**答案不该我拍脑袋**——**去看官方自己的"最小"是什么**。

### 关键证据：官方有个 `sdk-minimal`

> **出处**：`packages/bundle/sdk-minimal/README.zh.md`（逐字）——*"当 SDK 客户端需要**小型、显式的 coding agent 运行时**时，请使用 `dsh --profile sdk-minimal`。该 profile 默认**只公布按平台选择的持久 shell**，把会话持久化为未压缩 JSONL……它提供完整 Cordis 配置树，并**刻意排除** `dsh-base`、Web、settings、托管凭据、遥测、压缩（compaction）、文件系统工具、workspace 指令、skill（技能）、jobs 与 subagent。"*

**量化对比**（`grep` 实测）：

| Profile | 插件数 | 说明 |
| --- | --- | --- |
| **`sdk-minimal`** | **32** | 官方"最小" |
| **`base`**（完整产品基础） | **87** | 完整版 |

**sdk-minimal 的插件树清单**（出处：`packages/bundle/sdk-minimal/cordis.patch.yml`，逐字摘）：

```
启动/协议   sdk-app-startup, sdk-jsonrpc-server
模型        llm, llm-deepseek, llm-retry
会话        session, session-title, session-persistence-jsonl
提示词      system-prompt
工具        tools, persistent-bash（唯一工具）
Agent       agent, agent-loop        ← 核心循环
脚手架      scope, timer, subprocess, pty, sandbox, jobs, mcp-resources
不变式      invariants + 各包 /invariant
```

> **注意最后一行**：`invariants` 是 dsh 的"运行时断言"（"模型可见即已记录"那套）。**连最小 profile 都带着它**——说明**不变式是 harness 内核的一部分，不是可选装饰**。

### 从 32 个插件里，提取"不可再删"的四块

把 sdk-minimal 的 32 个插件按职责归并，**内核只有四块**：

```
① agent-loop  循环    —— 心脏：发消息 → 模型 → 工具 → 循环
② tools       工具    —— 手：注册 + 执行
③ llm         模型    —— 嘴：把请求发给模型、收回复
④ session     会话    —— 记忆：把消息记下来（可重建上下文）
```

其余 28 个（sandbox / pty / jobs / mcp / jsonrpc / 各种 invariant / 平台 shell）**都是"增强"或"部署形态"**——删掉它们，**harness 依然能"对话 + 调工具"**。

> **出处**：`docs/architecture.zh.md`「核心包」表——列出 `core/session`、`core/tools`、`core/agent`、`core/agent-loop`、`llm/llm`，正是这四块。（`core/system-prompt` 也列了，但它属于 ④ 的"组装"面，mini-dsh 里并入循环。）

> **Go 类比**：就像**一个最小的 Web 框架**——内核是 **路由循环（agent-loop）+ handler（tools）+ 数据源（llm）+ 日志（session）**。中间件、监控、限流都是外围。**mini-dsh = "能跑的最小 agent 框架"**。
