# 09.1 harness 内核的四块——每块职责、接口、dsh 多大、mini 怎么简化

> [!info] 版本锚点
> - 源码：`~/ai-work/dsh/deepseek-harness/`（master `0d1f50007f`）；全局包 `dsh 0.1.5-rc.1`
> - 前置：**09.0（本章地图）**
> - 本篇对象：**想搞懂 harness 内核的后端**

> [!abstract] 读完该记住
> harness 的内核 = **四块服务**：`session`（会话）+ `tools`（工具）+ `llm`（模型）+ `agent-loop`（循环）。
> **每块在 dsh 里都是一个 cordis 服务**，都很大（几千行）；**mini-dsh 把每块砍成主干**。

## 先看一张"规模对照表"（先把"大"建立起来）

> **出处**：以下行数为 `find packages/<p>/src -name '*.ts' | xargs wc -l` **实测**（deepseek-harness master `0d1f50007f`）

| 块 | dsh 真实包 | 源码行数 | mini-dsh 目标 |
| --- | --- | --- | --- |
| ④ 会话 | `packages/core/session` | **3144** | ~40 行 |
| ② 工具 | `packages/core/tools` | **5746** | ~60 行 |
| ③ 模型 | `packages/llm/llm` | **3862** | ~40 行 |
| ① 循环 | `packages/core/agent-loop` | **2470** | ~80 行 |
| （Agent 抽象） | `packages/core/agent` | **1630** | 并入循环 |

**合计 dsh 侧 ≈ 1.7 万行，mini-dsh 目标 ≈ 250 行**（约 **1/68**）。

> **Go 类比**：这不是"mini-dsh 是 dsh 的替代品"——而是像**你写一个 200 行的玩具 HTTP 服务器**去对照 `net/http` 的 3 万行。**造玩具，是为了看懂真家伙在补什么。**

## ① agent-loop：心脏

### 职责

**把"发消息 → 模型回 → 有工具就执行 → 再发 → …… → 结束"这个循环跑起来。**

> **出处**：`packages/core/agent-loop/README.zh.md:73`「一个步骤做什么」（逐字）——*"每个步骤都会发送会话的派生历史……及其可见工具 schema；**模型的工具调用经过受守卫的工具流水线**，每个被接纳的事实都会在**下一步据此派生之前追加到会话日志**。"*

### 一个"步骤"和"轮次"的定义

> **出处**：`docs/architecture.zh.md`「轮次流程」（逐字）——*"一个**步骤**是一次模型请求加上它调用的工具。一个**轮次**包含零个或多个步骤：它在领取首条输入之前打开，并在不再欠下任何工作时关闭。"*

```
turn（轮次）= 用户发一句话 → 到"再也没有工具要调了"
  ├── step 1：请求模型 → 模型说"调 echo" → 执行 echo
  ├── step 2：带上 echo 结果再请求 → 模型说"我答完了"
  └──（没有工具要调了）→ turn 结束
```

### 真实的核心接口

> **出处**：`packages/core/agent-loop/src/index.ts:358`（逐字）——`export class AgentLoop extends Service implements AgentFactory`
> **出处**：同文件 `:702`——`async create(id: SessionId, options: AgentOptions = {}, meta: ...): Promise<Agent>`

**注意**：`AgentLoop` **本身就是一个 cordis Service**（`extends Service`），在 `ctx.agents` 上注册为 `AgentFactory`。

### mini-dsh 怎么简化

砍掉：取消（abort）、重试、并行工具、waterfall 事件、持久化集成、`prepareCall` 能力协商、请求序列管理……
**只留主干**：

```
loop(history):
  while true:
    decision = llm.decide(history)
    if decision 是"调工具":
       result = tools.execute(...)
       history.append(tool 结果)
    else:                        # 最终答复
       history.append(assistant 答复)
       break
```

## ② tools：手

### 职责

**一个"工具的注册表 + 执行器"。** 插件把工具注册进来，循环按名字执行。

> **出处**：`docs/architecture.zh.md`「核心包」（逐字）——*"`core/tools` | 作用域化的工具注册表和**带把关的执行流水线** | `ctx.tools`"*

### 真实的工具定义形状

> **出处**：`packages/core/tools/src/index.ts:216`（逐字）：

```ts
export interface ToolDefinition extends ToolSchema {
  readonly output: ToolOutputDefinition
  execute(args: unknown, exec: ToolRunContext): Promise<unknown>
  // ...还有 render 等
}
```

**核心四样**：`name`（名字）、`description`（给模型看的说明）、`parameters`（参数 schema）、`execute`（干活的函数）。

### 真实的核心接口

> **出处**：`packages/core/tools/src/index.ts:1043`——`register(definition: ToolDefinition): () => void`
> **出处**：同文件 `:1210`——`get(name: string, scope?: ScopeKey): ToolDefinition | undefined`
> **出处**：同文件 `:1348`——`async execute(exec: ToolExecutionInput): Promise<ToolExecutionResult>`

### mini-dsh 怎么简化

砍掉：`output`/`render` 规范化、作用域（`scope`）、JSON Schema 转换、守卫流水线（pre/post-execute 事件）、超时/取消。
**只留**：`name / description / parameters / execute` + `register` / `names` / `execute`。

> **⚠️ 一个真实的坑（我造 mini-dsh 时踩到）**：
> **提供服务的插件，不能在自己的 `apply` 里直接读该服务**——会报 `cannot get property "tools" without inject`。
> **所以工具必须由"独立的工具插件"（声明 `inject: ['tools']`）注册**。
> **这也正是 dsh 的惯例**：工具由独立的工具插件注册（如 `dsh-tool-bash-persistent`，出处：`sdk-minimal/cordis.patch.yml`）。

## ③ llm：嘴

### 职责

**把"消息历史"发给模型，收回复（可能带工具调用）。**

> **出处**：`docs/architecture.zh.md`「核心包」（逐字）——*"`llm/llm` | 消息与流式词汇表，以及**适配器 seam** | `ctx.llm`"*

### 真实的适配器契约

> **出处**：`packages/llm/llm/src/index.ts:203`（逐字）——`export abstract class LlmAdapter`
> **出处**：同文件 `:284`——`abstract stream(options: GenerateOptions): AsyncIterable<StreamChunk>`
> **出处**：同文件 `:390`——`registerAdapter(providers: string[], adapter: LlmAdapter): AdapterRegistrationHandle`

**关键概念**：**适配器（adapter）= 一个"把统一请求翻译成某个厂商 API 格式"的插件**。DeepSeek、CodeBuddy……各是一个 adapter。

> **出处**：`packages/llm/llm/README.zh.md` 相关段落 + `sdk-minimal/cordis.patch.yml` 里 `llm-deepseek` 那一行——**模型也是一个插件**。

### mini-dsh 怎么简化

**假模型**：不接真实 API，写死一个"决策函数"——看历史里有没有工具结果，没有就调工具，有了就给最终答复。

```
decide(history):
  if 历史里没有 tool 结果: return { kind: 'tool_call', name: 'echo', args: {...} }
  else:                    return { kind: 'final', text: '...' }
```

**好处**：**不烧 token、离线可跑、聚焦"循环"本身**。等循环跑通了，再把假模型换成真 adapter。

> **Go 类比**：假模型 = **你在写 HTTP 客户端时先 mock 掉 `http.Client`**——先把业务逻辑（循环）跑通，再换真实现。

## ④ session：记忆

### 职责

**把对话消息按顺序记下来**；**模型看到的上下文 = 从日志投影出来的**。

> **出处**：`docs/architecture.zh.md`「会话日志」（逐字）——*"**会话日志是模型所见上下文的来源**。`deriveMessages()` 从中投影出模型历史。"*

**这是 harness 最反直觉、也最重要的设计**：**不是"内存里存个消息数组"，而是"append-only 日志 + 从中投影"**。

> **出处**：同段（逐字）——*"**模型可见即已记录。** 抵达模型请求的一切都必须能从日志重建，并由一项**运行时不变量**断言这一点。"*

**为什么这么设计**：因为要支持 **fork（分叉）、resume（恢复）、回放、迁移**——**只要日志在，一切可重建**。

### mini-dsh 怎么简化

**内存里一个消息数组 + 一个 `deriveMessages()`**。
**保留概念（"日志是上下文来源"），砍掉持久化/迁移/版本**。

> **⚠️ 但要点出**：mini-dsh **丢掉了"append-only + 可重建"这条铁律**——所以它**不能 fork/resume**。这正是 09.5 要讲的"mini 缺了什么"。

## 四块之间的关系（一张图）

```
                  ┌─────────────────────┐
                  │   ① agent-loop       │  ← 心脏，驱动一切
                  │   （自己写，~80 行）  │
                  └──────┬──────────────┘
            读历史 ↕      │      调模型 ↕       执行工具 ↕
      ┌──────────────┐   │   ┌──────────────┐  ┌──────────────┐
      │ ④ session    │◄──┼──►│ ③ llm        │  │ ② tools      │
      │ （日志/历史） │   │   │ （模型/适配器）│  │ （注册/执行） │
      └──────────────┘   │   └──────────────┘  └──────────────┘
                         │
              循环每一轮：session.deriveMessages()
                         → llm.decide()
                         → tools.execute()
                         → session.append()
                         → 直到没有工具调用
```

> **Go 类比**：这就是**一个"事件循环 + 四个依赖"**——循环是主体，四块是它依赖的四个接口。**四块都可以替换**（换个 llm 就是换个模型，换个 session 就是换个存储）——**这正是"一切皆插件"的意义**。
