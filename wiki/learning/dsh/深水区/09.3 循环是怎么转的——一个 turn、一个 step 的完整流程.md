# 09.3 循环是怎么转的——一个 turn、一个 step 的完整流程

> [!info] 版本锚点
> - 源码：`~/ai-work/dsh/deepseek-harness/`（master `0d1f50007f`）；全局包 `dsh 0.1.5-rc.1`
> - 前置：**09.1（四块内核）**
> - 本篇对象：**想真正看懂 agent-loop 转法的后端**

> [!abstract] 读完该记住 5 点
> 1. **step（步骤）= 一次模型请求 + 它调用的工具**；**turn（轮次）= 零或多个 step**
> 2. **循环的本质**：派生历史 → 发模型 → 有工具就执行 → **把事实追加进日志** → 下一步
> 3. **"追加日志"是核心**——每一步的事实都进日志，**下一步从日志重新派生**
> 4. **循环什么时候停**：模型不再产生工具调用（"不再欠下任何工作"）
> 5. **mini-dsh 的循环就是把这条主干用 ~80 行写出来**

## 一、先把两个词钉死：step 和 turn

> **出处**：`docs/architecture.zh.md`「轮次流程」（逐字）——*"一个**步骤**是一次模型请求加上它调用的工具。一个**轮次**包含零个或多个步骤：它在**领取首条输入之前打开**，并在**不再欠下任何工作时关闭**。"*

```
turn（轮次）开始
  │   （打开时机：领取到首条用户输入）
  ├── step 1
  │     请求模型 → 模型说"调用 echo(text=Cordis)"
  │     执行 echo → 得到 "echo: Cordis"
  │     把 echo 结果追加进日志
  ├── step 2
  │     请求模型（这次历史里有 echo 结果了）→ 模型说"我答完了：..."
  │     把 assistant 答复追加进日志
  └── 模型没再要工具 → "不再欠下工作" → turn 结束
```

> **Go 类比**：**turn = 一次 HTTP 请求的完整处理**；**step = 处理过程中的一次数据库往返**。一个请求可能查 0 次或多次数据库。

---

## 二、一个 step 里，究竟发生了什么（官方原文）

> **出处**：`packages/core/agent-loop/README.zh.md:73`（逐字）——*"每个步骤都会**发送会话的派生历史**……及其**可见工具 schema**；模型的工具调用经过**受守卫的工具流水线**，每个被接纳的事实在**下一步据此派生之前追加到会话日志**。"*

把它拆成朴素的语言：

```
一个 step：
  ① 从 session 里【派生】出当前消息历史（deriveMessages）
  ② 把历史 + 可用工具清单，发给 llm
  ③ llm 回一个决策：
       - 要么"调用工具 X"
       - 要么"这是最终答复"
  ④ 如果是工具调用：
       执行工具 → 得到一个结果
       把【工具调用 + 结果】追加进 session 日志
       （然后进入下一个 step）
     如果是最终答复：
       把 assistant 答复追加进日志
       （循环结束）
```

**注意第 ① 步"派生"**——**不是"手里攒着一个消息数组传下去"，而是"每步都从日志重新算一遍"**。

> **出处**：`docs/architecture.zh.md`「会话日志」（逐字）——*"`deriveMessages()` 从中投影出模型历史。"*
> **出处**：`packages/core/agent-loop/README.zh.md:148`（逐字）——*"每个步骤中，循环会发送**会话的派生消息**与可见工具 schema。"*

## 三、为什么是"日志 + 派生"，而不是"内存数组"

这是 harness 最值得理解的设计决定。**三个理由**：

### 理由 1：模型可见 = 已记录（可重建）

> **出处**：`docs/architecture.zh.md`「会话日志」（逐字）——*"**模型可见即已记录。** 抵达模型请求的一切都必须能从日志重建，并由一项**运行时不变量**断言这一点。"*

**含义**：**任何送到模型眼前的东西，都必须先落到日志里**——这样**一切都能重放**。

### 理由 2：支持 fork（分叉）

**分叉 = 从某个历史点，开一条新的对话线。** 如果历史是"内存数组"，**你没法复制某个时刻的状态**；如果历史是"append-only 日志"，**截断到某个位置就是一条新线**。

> **出处**：`docs/architecture.zh.md`（逐字）——*"**fork、恢复、transcript（文本记录）、遥测与持久化都从这些持久 settlement 派生**"*

### 理由 3：压缩（compaction）是"遮蔽旧节点"

**上下文太长要压缩**——dsh 的做法是**在日志里"遮蔽"旧节点**，而不是"把数组删一半"。

> **出处**：`packages/core/agent-loop/README.zh.md:162`（逐字）——*"输入会随每条表层消息增长，**直到压缩替换遮蔽较旧节点**"*

> **Go 类比**：这就像**事件溯源（Event Sourcing）**——**不存"当前状态"，存"事件序列"，需要时回放**。好处完全一致：**可审计、可重放、可分叉、可迁移**。你是后端，这套你应该不陌生。

## 四、循环什么时候停

> **出处**：`docs/architecture.zh.md`（逐字）——*"它在领取首条输入之前打开，并**在不再欠下任何工作时关闭**。"*

**"不再欠下工作" = 模型这次没有产生工具调用**（也就是它给了最终答复）。

```
step N：模型回"最终答复"，没有工具调用
   → 循环判断："没有工具要调了，也没有新输入"
   → turn 结束
```

> **⚠️ 如果模型一直产生工具调用**（比如陷进循环）：dsh 有 `maxParallelToolCalls`、超时、取消等机制兜底（这些 mini-dsh **先不做**）——见 09.5。

## 五、官方完整流程图（原样引用）

> **出处**：`docs/architecture.zh.md`「轮次流程」（逐字，节选主干）：

```text
turn/start
  claim next-step input plus one queued message
  assemble prompt sections + tool schemas; project runtime context
  -> agent/pre-step                   reject | enter(messages, startsRequestSeries?)
     step/start
     agent/request -> prepareCall
     reconcile system/message ...
     derive and freeze model history from the log        ← 派生历史
     stream the bound prepared call -> llm/stream        ← 请求模型
       assistant/message | assistant/attempt
     tool/call* -> tools/pre-execute -> tools/execute -> tools/post-execute -> tool/result*   ← 工具流水线
     step/end
     tools owe another request, or next-step input arrived -> claim -> next step
  -> agent/turn-stopping
turn/end
```

**别被这一堆事件吓到**——**主干就是**：

```
派生历史 → 请求模型 → （有工具）执行工具 → 追加日志 → 回到"派生历史"
```

**其余都是"钩子"**（`agent/pre-step`、`tools/pre-execute`、`llm/stream` 等瀑布式事件）——**留给插件插入自定义逻辑**。mini-dsh **先不实现这些钩子**。

> **Go 类比**：主干是**业务逻辑**；那些 `*/pre-*`、`*/post-*` 事件是**中间件切面**。**先写业务，再加中间件。**

## 六、mini-dsh 的循环（把主干写出来）

**目标**：用 ~80 行，把上面"主干"写出来。

```
async function runTurn(userInput):
  session.append({ role: 'user', text: userInput })
  while true:
    history = session.deriveMessages()        # ① 派生历史
    decision = llm.decide(history)            # ② 请求模型
    if decision.kind === 'tool_call':         # ③ 有工具调用
       session.append({ role: 'assistant', toolCall: decision })
       result = await tools.execute(decision.name, decision.args)
       session.append({ role: 'tool', text: result })
       continue                               # → 回到 ① 派生新历史
    else:                                     # ④ 最终答复
       session.append({ role: 'assistant', text: decision.text })
       break                                  # turn 结束
```

**对照真实 dsh（对照点）**：

| mini-dsh 那行 | 真实 dsh 对应 |
| --- | --- |
| `session.deriveMessages()` | `deriveMessages()`（从日志投影） |
| `llm.decide(history)` | `llm.stream(options)`（流式，还带 waterfall） |
| `tools.execute(...)` | `tools.execute()`（带守卫流水线、pre/post 事件） |
| `continue` | "tools owe another request → claim → next step" |
| `break` | `agent/turn-stopping` → `turn/end` |

**你会发现：主干一模一样，dsh 只是把每一行都"加固"了。**
