# 09.4 动手：从零搭一个能跑的 mini-dsh

> [!info] 版本锚点
> - 源码：`~/ai-work/dsh/deepseek-harness/`（master `0d1f50007f`）；全局包 `dsh 0.1.5-rc.1`
> - 前置：**09.1~09.3**（四块内核 / Cordis 骨架 / 循环流程）
> - 代码位置：`~/ai-work/dsh/dsh-learn/example/mini-dsh/`
> - **重要**：本篇所有命令与输出**我实际跑过**；`~/ai-work/dsh/dsh-learn/example/mini-dsh/` 里有可运行的参考实现

> [!abstract] 这一篇你会做到什么
> **从零搭一个能跑的 mini-dsh**：它**真的会转循环**——你发一句话，它会"调模型 → 调工具 → 再调模型 → 给答复"。
> **读完该记住 4 点**：
> 1. **搭建顺序**：session → tools → echo → mock-llm → loop（**照依赖顺序**）
> 2. **每一步都先跑通再往下**（别一次写完再调试）
> 3. **测试驱动**：每写一个服务，先写个探针插件验证它
> 4. **踩坑是重点**——我踩的三个坑（服务不能自读、name 不支持 #、vendor 未编译）都标了

## 一、搭建顺序（照依赖来）

```
① session.ts     会话服务（别人都依赖它）→ 先搭
② tools.ts       工具服务
③ echo.ts        echo 工具（消费 tools）
④ mock-llm.ts    假模型
⑤ loop.ts        循环（消费 session/tools/mock-llm）
⑥ cordis.yml     拼装
⑦ boot.mjs       启动器
```

**每搭一块，先写个"探针插件"验证它**——这是后端调试的老习惯（写完一个 handler 先 curl 一下）。

> **Go 类比**：像你**逐个写微服务**——先起 DB，再起 Service，最后起 Gateway。**每起一个先测通**，别全部起完再排查。

**问题**：官方启动器 import 的是 `vendor/cordis`，但**`vendor/cordis/lib/` 没有编译好的 JS**（只有 `types/`）。直接跑会报：

**解法**：用**全局 dsh 安装里已编译的 Cordis**（在 `~/.nvm/.../dsh/node_modules/@deepseek-ai/`），软链到 mini-dsh 的 `node_modules`：

```bash

mkdir -p node_modules/@deepseek-ai
for p in cordis cordis-plugin-loader cordis-plugin-include cordis-plugin-timer; do
  ln -sfn "$G/$p" "node_modules/@deepseek-ai/$p"
done
```

**验证**：从 mini-dsh 能解析到 cordis 即可。

## 三、第 ① 块：session（会话服务）

**职责回顾**（09.1 ④）：记消息 + `deriveMessages()`。

> **关键 API**（出处：`docs/cordis-tutorial/03-services.zh.md`）：服务 = `class extends Service` + `super(ctx, '名字')`。

```ts
// src/session.ts（要点）
import { Service, type Context } from '@deepseek-ai/cordis'

export interface MiniMessage {
  role: 'system' | 'user' | 'assistant' | 'tool'
  text?: string
  toolCall?: { name: string; args: Record<string, unknown> }
}

declare module '@deepseek-ai/cordis' {
  interface Context { session: SessionService }   // ← 编译期：把服务加进 ctx 类型
}

export class SessionService extends Service {
  private readonly messages: MiniMessage[] = []
  constructor(ctx: Context) { super(ctx, 'session') }
  append(m: MiniMessage): void { this.messages.push(m); console.log(`  [session] + ${m.role}`) }
  deriveMessages(): readonly MiniMessage[] { return this.messages }
}

export const name = 'mini-session'
export function apply(ctx: Context): void { ctx.plugin(SessionService) }
```

**探针验证**（另起一个插件注入 `session`，追加两条、打印长度）：

**我实测的输出**：

```
  [session] + system: mini-dsh online
  [session] + user: hi
  [probe] deriveMessages 长度 = 2
```

## 四、第 ② 块：tools（工具服务）+ echo 工具（**第二个坑**）

### 4.1 服务：`src/tools.ts`

```ts
export class ToolsServiceImpl extends Service {
  private readonly registry = new Map<string, MiniTool>()
  constructor(ctx: Context) { super(ctx, 'tools') }
  register(tool: MiniTool): void { this.registry.set(tool.name, tool) }
  names(): string[] { return [...this.registry.keys()] }
  async execute(name, args): Promise<string> { /* 查表 + 调 execute */ }
}
export function apply(ctx: Context): void { ctx.plugin(ToolsServiceImpl) }
```

### 4.2 echo 工具：`src/echo.ts`（**必须独立成文件**）

**⚠️ 第二个坑**：我一开始把"注册工具"写在 `tools.ts` 的 `apply` 里，报：

```
cannot get property "tools" without inject
```

**原因**（Cordis 规则）：**提供服务的插件，不能在自己的 `apply` 里直接读该服务**。

**所以**：工具必须由**独立的插件**注册，并**声明 `inject: ['tools']`**：

```ts
// src/echo.ts
import type { Context } from '@deepseek-ai/cordis'
import type {} from './tools.ts'

export const name = 'mini-tool-echo'
export const inject = ['tools']            // ← 声明依赖，等 tools 就绪

export function apply(ctx: Context): void {
  ctx.tools.register({
    name: 'echo',
    description: 'Echo back the given text.',
    parameters: { text: 'string' },
    execute(args) { return `echo: ${String(args.text ?? '')}` },
  })
}
```

> **这也正是 dsh 的惯例**：工具由独立的工具插件注册（如 `dsh-tool-bash-persistent`，出处：`sdk-minimal/cordis.patch.yml`）。

**探针验证**：

**我实测的输出**：

```
  [tools] registered: echo
  [probe] 可用工具: [ 'echo' ]
  [tools] execute echo({"text":"Cordis"})
  [tools] echo → "echo: Cordis"
```

### ⚠️ 顺带第三个坑：`name` 不支持 `#具名导出`

我试过 `cordis.yml` 里写 `name: './src/tools.ts#echoPlugin'`——**不生效**（工具列表为空）。

**原因**：`cordis-plugin-loader` 的 `import(name)` 把 `name` 当**模块说明符**，**不支持 `#export` 语法**。

**解法**：**拆成独立文件**——这就是为什么 `echo.ts` 要单独一个文件。

## 五、第 ③ 块：mock-llm（假模型）

```ts
// src/mock-llm.ts（要点）
export type Decision =
  | { kind: 'tool_call'; name: string; args: Record<string, unknown> }
  | { kind: 'final'; text: string }

export class MockLlmService extends Service {
  constructor(ctx: Context) { super(ctx, 'mockLlm') }
  decide(history: readonly MiniMessage[]): Decision {
    const hasToolResult = history.some(m => m.role === 'tool')
    if (!hasToolResult) return { kind: 'tool_call', name: 'echo', args: { text: 'Cordis' } }
    const last = [...history].reverse().find(m => m.role === 'tool')
    return { kind: 'final', text: `我调用了 echo，它返回：${last?.text ?? ''}` }
  }
}
```

**"智能"逻辑**：看历史里有没有 tool 结果——**没有就调 echo，有了就给最终答复**。这就能驱动循环转两圈，且不烧 token。

## 六、第 ④ 块：loop（循环，消费前面三块）

```ts
// src/loop.ts（要点）
import type { Context } from '@deepseek-ai/cordis'

export const name = 'mini-loop'
export const inject = ['session', 'tools', 'mockLlm']   // ← 依赖三块

export function apply(ctx: Context): void {
  async function runTurn(userInput: string): Promise<void> {
    ctx.session.append({ role: 'user', text: userInput })
    while (true) {
      const history = ctx.session.deriveMessages()      // ① 派生历史
      const decision = ctx.mockLlm.decide(history)       // ② 请求模型
      if (decision.kind === 'tool_call') {               // ③ 有工具调用
        ctx.session.append({ role: 'assistant', toolCall: decision })
        const result = await ctx.tools.execute(decision.name, decision.args)
        ctx.session.append({ role: 'tool', text: result })
        continue
      }
      ctx.session.append({ role: 'assistant', text: decision.text })  // ④ 最终答复
      break
    }
  }
  void runTurn('你好，试试调个工具')
}
```

**对照 09.3 的流程图**：这 15 行就是那条主干的完整实现。
