# 09.5 回头看 dsh——mini-dsh 缺了什么，那些代码在补什么

> [!info] 版本锚点
> - 源码：`~/ai-work/dsh/deepseek-harness/`（master `0d1f50007f`）；全局包 `dsh 0.1.5-rc.1`
> - 前置：**09.4（动手搭 mini-dsh）**
> - 本篇对象：**搭完 mini-dsh，回来重新审视 dsh 的后端**

> [!abstract] 为什么要写这一篇
> 搭完 mini-dsh，你可能会想："dsh 的 agent-loop 有 2470 行，我才 80 行，**那 2390 行在干嘛？**"
> **这一篇就是回答这个问题的。** 读完你会明白：**那些代码不是"复杂"，是"把一个玩具变成生产级"**。

## 一、总览：mini-dsh 砍掉了什么

**mini-dsh 只保留了主干**，砍掉的东西**分五类**：

| 类别 | mini-dsh | 真实 dsh | 补的是什么 |
| --- | --- | --- | --- |
| **① 生命周期/持久化** | 内存数组 | append-only 日志 + JSONL + 版本迁移 | **重启后还在**、能 fork/resume |
| **② 取消/超时** | 无 | `AbortSignal`、协作式取消、超时 | **能打断**、不卡死 |
| **③ 重试/容错** | 无 | `llm-retry`、`agent/request-error` | **网络抖动能恢复** |
| **④ 并发/排序** | 严格串行 | 并行安全调用 + 独占屏障 | **性能** |
| **⑤ 钩子/扩展** | 无 | `agent/pre-step`、`tools/*` 等 waterfall | **插件能插手** |
| **⑥ 安全/沙箱** | 无 | `sandbox`、`sandbox-policy` | **不能随便删文件** |
| **⑦ 不变式** | 无 | `invariants` + 各包 `/invariant` | **运行时自检** |

---

## 二、逐类拆解（每一类都值得你对照自己写后端的经验）

### ① 持久化：从"内存数组"到"append-only 日志"

**mini-dsh**：`messages: MiniMessage[]`——**进程一退就没了**。

**真实 dsh**：
> **出处**：`sdk-minimal/cordis.patch.yml`——`session-persistence-jsonl`，`config: { root: dshHomePath('sessions'), compression: none }`
> **出处**：`docs/architecture.zh.md`「会话日志」——*"JSONL v0 使用 `session.jsonl[.zstd]`，v1 及后续版本使用 `session.vN.jsonl[.zstd]`……每个相邻迁移包只负责一个 `vN -> vN+1` 步骤"*

**它补的是**：
- **持久化**（重启后会话还在）
- **格式版本 + 迁移**（老会话能升级）
- **可重建**（"模型可见即已记录"的不变式）

> **Go 类比**：就像你**从"内存 map 缓存"升级到"带版本的持久化存储"**——**加了 WAL、加了 schema migration**。

### ② 取消：从"跑到底"到"能打断"

**mini-dsh**：循环**跑到底**，没地方中断。

**真实 dsh**：
> **出处**：`packages/core/agent-loop/README.zh.md:123`「失败与取消」（逐字）——*"取消后未分发的模型工具调用会收到合成的 `tool/call` 加 `ABORTED_BEFORE_DISPATCH` 结果对。"*
> **出处**：同上 `:73`（逐字）——*"取消是**协作式**的：`agent.cancel()` 中止当前活动……被取消的流会**终结已送达用户的文本**。"*

**它补的是**：用户**随时能停**；停止时**已产生的部分结果不丢**。

> **Go 类比**：就像你的 handler 从"不管客户端断没断"升级到**全程传 `ctx.Context()`、检查 `ctx.Err()`**。

### ③ 重试：从"一次就完"到"网络抖动可恢复"

**mini-dsh**：没有重试。

**真实 dsh**：
> **出处**：`packages/core/agent-loop/README.zh.md:123`（逐字）——*"最终适配器选择、分发与迭代失败……**处理该失败的监听器返回 `{ kind: 'retry' }`**……未被处理的失败则是终态。"*
> **出处**：`sdk-minimal/cordis.patch.yml`——`llm-retry` 插件。

**它补的是**：模型 API 抖动时**自动重试**，且**重试不重复预处理**（记忆化的组装结果复用）。

> **Go 类比**：就像你给下游调用加**指数退避重试**——而且**幂等**（不重复扣款）。

### ④ 并发：从"严格串行"到"并行 + 屏障"

**mini-dsh**：一个工具调完再调下一个。

**真实 dsh**：
> **出处**：`packages/core/agent-loop/README.zh.md:73`（逐字）——*"**并行安全调用最多可重叠 `maxParallelToolCalls` 个**；独占调用单独运行并构成**排序屏障**。"*

**它补的是**：多个只读工具**并行跑**（快）；写操作**串行**（安全）。

> **Go 类比**：就像**读用 `errgroup` 并行、写加锁串行**——**同一套并发纪律**。

### ⑤ 钩子：从"写死"到"插件能插手"

**mini-dsh**：循环是写死的，别人插不进去。

**真实 dsh**：
> **出处**：`docs/architecture.zh.md`「轮次流程」——一堆 waterfall 事件：`agent/pre-step`、`agent/request`、`llm/stream`、`tools/pre-execute`/`execute`/`post-execute`。

**它补的是**：**别的插件能在循环的每个环节插入逻辑**（比如：改提示词、拦工具、记日志）。

> **Go 类比**：就像你的 handler 从"一坨代码"重构成**`http.Handler` 链**——每层中间件可插拔。

### ⑥ 沙箱/安全：从"裸跑"到"受控"

**mini-dsh**：没有沙箱概念（也不执行真实命令）。

**真实 dsh**：
> **出处**：`sdk-minimal/cordis.patch.yml`——`sandbox`（`dsh-sandbox-local`）+ `sandbox-policy`（`mode: danger-full-access`）。
> **出处**：`sdk-minimal/README.zh.md`（逐字）——*"其 **danger-full-access 策略允许 shell 修改进程可访问的任何路径**，因此**只能配合隔离 workspace 使用**。"*

**它补的是**：**agent 跑命令的权限控制**——连"最小" profile 都得显式声明策略。

> **Go 类比**：就像你给容器加**能力白名单 / seccomp**——**默认最小权限**。

### ⑦ 不变式：从"靠自觉"到"运行时断言"

**mini-dsh**：没有。

**真实 dsh**：
> **出处**：`sdk-minimal/cordis.patch.yml`——`invariants` + `session-invariant` + `agent-invariant` + `scope-invariant` + `agent-loop-invariant`。

**它补的是**：**运行时自检**——比如"模型看到的一切都可从日志重建"，**一旦违反，大声报错**。

> **Go 类比**：就像你写**运行时断言 / 数据一致性校验**——**宁可在开发期炸，也不要在生产期静默出错**。

## 三、一个"缺什么会怎样"的对照表

| 如果 mini-dsh 缺了… | 会怎样 |
| --- | --- |
| 持久化 | 进程一退，会话全没 |
| 取消 | 用户点了"停止"也没用，得杀进程 |
| 重试 | 模型接口抖一下，整个对话就断了 |
| 并发 | 几个工具只能排队，慢 |
| 钩子 | 想加个"日志/拦截"都得改循环源码 |
| 沙箱 | agent 能删你任何文件 |
| 不变式 | 出了问题你不知道，静默错乱 |

**这张表，就是"toy → 生产"的距离。**

## 四、最重要的收获：你现在能"读懂那 2470 行"了

回到最初的问题：**dsh 的 agent-loop 有 2470 行，mini-dsh 才 80 行——那 2390 行在干嘛？**

**答**：它在**逐条补上面那七类**。而且**每一类的代码，你都能对应到一个"为什么"**：

```
2470 行 = 主干（80 行）
        + 持久化集成（写日志、派生、迁移）
        + 取消（signal 生命周期、竞态处理）
        + 重试（记忆化、序列管理）
        + 并发（并行池 + 屏障）
        + 钩子（waterfall 事件分发）
        + 错误分类与恢复
        + 那一堆 agent/* 事件的发布
```

**你造过 80 行的玩具，再看 2470 行的真家伙——你不再"看不懂"，而是"知道每一块在补什么"。**

> **出处**：`packages/core/agent-loop/README.zh.md` 全文 200+ 行，讲的就是这些补强；`docs/architecture.zh.md`「轮次流程」是它们的权威定义。

> **Go 类比**：这就像**你读过 `net/http` 的 `Server.Serve`**——**看似一堆细节，其实每行都在处理"生产环境的现实"**（超时、连接复用、优雅关闭……）。**造过玩具，你就有了"读生产代码"的眼睛。**

## 五、这一章的收尾

**你学到了**：

1. **harness 内核只有四块**（session / tools / llm / agent-loop）
2. **Cordis 骨架极简**（16 行启动器 + 一份配置）
3. **循环主干清晰**（派生历史 → 模型 → 工具 → 追加 → 循环）
4. **mini-dsh 能跑**（~250 行，你亲手搭过）
5. **toy → 生产差七类补强**（持久化/取消/重试/并发/钩子/沙箱/不变式）

**下一步可以做什么**（可选）：

- 把 mini-dsh 的**假模型换成真 adapter**（接 DeepSeek / CodeBuddy）
- 给 mini-dsh **加一个钩子**（比如循环每步打印日志）——体会"扩展点"
- 给 mini-dsh **加取消**（一个 `AbortSignal`）——体会"生产级补强"
- 然后**回去读 dsh 的 `agent-loop` 源码**——现在你读得懂了
