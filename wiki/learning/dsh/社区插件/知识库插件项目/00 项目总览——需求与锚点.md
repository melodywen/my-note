## 一、这是什么项目

一个 **dsh Web UI 插件**（暂名「知识库 / Knowledge Base」），给 dsh 挂上「多知识库管理」能力：每个知识库绑定一个 Git 仓库 URL + 仓库内子路径，互相物理隔离。

## 二、需求定义（已确认，2026-09-27）

| #   | 需求点      | 内容                                     |
| --- | -------- | -------------------------------------- |
| R1  | **产品形态** | dsh Web UI 插件（client + host 双半侧）       |
| R2  | **入口**   | 工作区左侧侧边栏一个专属卡片，点击进入                    |
| R3  | **主界面**  | 知识库主题列表页，展示所有知识库                       |
| R4  | **物理隔离** | 每个知识库是完全独立的存储区域，互不干扰                   |
| R5  | **手动建库** | 用户手动创建知识库，绑定 Git 仓库 URL；**知识库 ↔ 仓库多对多**：多个知识库可绑同一仓库，一个知识库也可绑 N 个仓库（分布式 polyrepo，2026-09-27 补充） |
| R6  | **路径绑定** | 每个仓库绑定含子路径（同 URL 不同路径 = 不同知识库）；绑定元组 = (URL, subpath, branch, 主域)，登记于 vault 的 `00-总表/仓库登记簿.md` |
| R7  | **多库并存** | 多知识库同时存在、分别管理                          |

## 四、用法分类（2026-09-27 起，学习者逐类口述）

| # | 用法 | 内容 | 文档 |
|---|---|---|---|
| **用法一** | **项目史官**（编年史模式） | 绑定 Git 仓库 → 追史（一篇一事）→ 快照（当前 Master 能力）→ 旁证（需求/方案/纪要，被动存储）→ 审阅归档闭环 | [[02 内容模型——史官、快照、旁证与审阅闭环]]、[[03 运行时机制——skill载体、job执行与Git集成]] |

**知识库形态总览**（R3 主界面列表页最终呈现）：

```text
[项目史官库 A]（绑 N 个 Git 仓库）
[项目史官库 B]（可绑同一仓库的不同路径）
[好代码收藏]
[我的编码习惯]
[API 调用案例]
...（用户自由增删）
```

> 用法二与用法一共享同一套插件基础设施（vault 结构、审阅闭环、术语表、检索），只是**内容 schema 不同**（个人库不绑 Git 仓库、无追史游标）。

## 五、关键辨析（本项目的设计前提）

- **知识库 ≠ 记忆**：知识库 = 人维护的 Obsidian wiki / Git 仓库（参考书），记忆 = agent 自传（会话经历）。本插件做的是**知识库**。
- **源与索引分离**：Git 仓库是源（source of truth），检索结构（BM25/向量/链接图）是可重建的派生索引。本插件的「物理隔离」语义要在这个框架下定义。
