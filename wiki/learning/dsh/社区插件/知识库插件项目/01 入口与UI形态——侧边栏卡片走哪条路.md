## 一、问题：你的需求 vs 官方机制，有一个岔路口

需求 R2 说「工作区左侧侧边栏一个专属卡片，点进去进入主界面」。核实官方源码后，dsh Web UI 的左侧栏有两套「加东西」的机制，**性质完全不同**：

| 路线 | 机制 | 最终效果 | 来源 |
|---|---|---|---|
| **A. 设置卡片**（settings card） | 注册进 `settings.plugin.item` keyed slot，以 namespace 为键 | 卡片出现在**设置弹窗 →「插件配置」标签页**里，是**配置表单**，不是独立页面 | `docs/cookbook/adding-a-settings-card.zh.md:9-79` |
| **B. 全局面板入口**（panel entry） | 侧边栏图标行注册进 `sidebar.panellist` list slot + 主面板注册进 `main` keyed slot | 侧边栏出现一个**图标按钮**，点击后**主区域切换**到你的独立页面 | `packages/client/ui-sidebar/src/client/contract/slots.ts:27-31` + `packages/client/ui-layout/src/client/index.ts:60-67` |

**关键判断**：你的需求（点击卡片 → 进入独立主界面）是 **路线 B**。路线 A 的 settings card 只是设置页里的一个表单卡片，承载不了「独立主题列表页」的形态——它俩很容易被「卡片」这个词混淆。

> **出处**：`sidebar.panellist` 契约注释（`packages/client/ui-sidebar/src/client/contract/slots.ts:25-28`）——*"Global panel icons. Each list id addresses the matching main panel; the sidebar owns the button and resolves its label from list metadata."*（全局面板图标。每个 list id 寻址匹配的主面板；侧边栏拥有按钮，从列表元数据解析 label。）

## 二、路线 B 的完整拼图（三件套）

从源码看，一个「侧边栏入口 + 主面板」插件需要往三个 slot 里注册：

```
sidebar（single, root）── 左栏外壳，被 ui-sidebar 占据
 ├─ sidebar.panellist（list, root）── ① 你的图标行在这注册
 │    └─ 每个 id ↔ main keyed slot 的一个 key
 └─ (workspaces / settings / footer.action 席位)

main（keyed, root）── 主区域，按 entry key 分派
 └─ ② key: 'knowledge-base' → 你的知识库主题列表页
```

1. **① 图标行**：`ctx.slots.register({ name: 'sidebar.panellist', id: 'kb', order: N, label: ... }, IconComp)`
   - `order` 升序排列，同序号保持注册顺序（`lib/types/client/contract/slots.d.ts:97-98`）
   - label 支持字符串或 locale-aware（README.zh.md「全局面板入口」节）
2. **② 主面板**：`ctx.slots.register({ name: 'main', key: 'kb' }, KbPanelComp)`
   - `main` 是 **keyed** slot，按 key 分派（`ui-layout/src/client/index.ts:66`：`'main': { kind: 'keyed'; scope: 'root' }`）
   - 点击图标 = `selectPanel(MainPanelId)`，布局 store 切换 `activePanelId`（`ui-layout/src/client/stores.ts:94`）
   - **保留键 `conversation`** 承载会话主界面，其他 key 无 Session 绑定（`index.ts:63-65` 注释）
3. **③ 卡片内页**：知识库主题列表 → 点进单个知识库 → 文档浏览/检索——这层完全是你自己的组件树（用 ui-primitives 组合，遵守 web-styling 规范）

> **出处**：`ui-sidebar/README.zh.md`「概述」「全局面板入口」两节；`ui-layout/src/client/index.ts:60-67`；slot 纪律（声明感知的 `slots.inject()`）见 `ui-sidebar/README.zh.md`「slot 纪律」节。

## 三、Host 半侧与浏览器半侧的分工

按官方双半侧架构（00 总览锚点表「双半侧打包」），这个插件两个半侧的职责：

| 半侧 | 代码位置 | 职责 |
|---|---|---|
| **Host 半侧**（Node 进程） | `src/` | ① storage domain 定义（知识库条目 CRUD 的落盘）② Git 集成（clone/pull，真正跑 git 命令）③ 向 client 暴露服务（经 remote/Typert 通道） |
| **浏览器半侧** | `src/client/` | ① 注册 `sidebar.panellist` 图标行 ② 注册 `main` key 面板（主题列表页）③ 建库表单（URL/路径绑定）④ 调 Host 服务做 CRUD |
| **dsh.client 声明** | `package.json` | `"dsh": { "client": { "platform": "web", "inject": [...] } }` + `./client` 导出 | 挂载即出现在页面，无需重建 Web 应用（`adding-a-settings-card.zh.md:80-92`） |
