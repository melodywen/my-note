## 一、这是什么

扫描「Git 提交人是**我**」的提交历史，**归纳**出我的编码风格特征——独立知识库。它不是记录单条提交（那是用法一史官的事），是从 N 条提交里**提炼风格**。

**用法场景**：「写新代码时遵循我的习惯」——把习惯清单注入 Agent 上下文（类似 AGENTS.md 的个人版）。

## 二、内容 schema（待议）

一条习惯的字段草案：

```yaml
---
category: 格式风格 | 命名 | 结构 | 错误处理 | ...
habit: 用 tab 缩进，不用空格
confidence: high        # 归纳置信度
evidence:                # 证据（提交列表，可多条）
  - repoA:abc1234
  - repoB:def5678
first_seen: 2024-03
last_seen: 2026-09
---
说明 + 例外情况
```

**关键设计**：习惯是**累积归纳**的（一条 habit 多个 evidence），不是一提交一条。

## 四、采集机制（与追史 job 同构）

```
【主动声明】（2026-09-27 裁定补全：2b 是双通道）
用户显式说「我的习惯是 X」（如「我用 tab」「记一下我用早期返回」）
→ Agent 直接起草稿（判断权在用户）→ 审阅 → 归档

【存量归纳】（显式触发）
面板点「归纳我的习惯」/ 对话指令
→ job 启动（复用 03 的 skill+job 架构）
→ 扫描范围：哪些仓库？（⚠️ 待定：当前工作区？用户指定仓库列表？）
→ 过滤：git log --author=<me>（多个 email 匹配）
→ 归纳：diff 模式 → 风格特征（skill 提示词约束）
→ 草稿：新发现的习惯 / 更新既有习惯的 evidence
→ 人审 → 归档（合并进分类文件）

【增量捕获】（2026-09-27 裁定：被动通道）
会话中发生提交（用户让 Agent 跑 git 命令 / Agent 提交经用户批准）
→ Agent 静默观察该提交的 diff 风格
→ 顺手更新既有习惯的 evidence / 发现新特征则起草稿
→ 仍走审阅闭环（观察自动，判断归人）
```
